## Findings

1. **P1 — whole-document executable accounting is omitted.**
   `web/tests/publication/build.test.ts:22` calls `unmarkedDocumentHazards` without
   the complementary executable occurrence matcher. That helper intentionally
   filters out `script`, `style`, `iframe`, `base`, stylesheet links and other
   executable occurrences because the existing build gate accounts for them
   separately. A new unregistered script outside `data-safe-rich-content` therefore
   passes the publication rich-content assertion. The accepted contract in
   `openspec/specs/rich-content-safety/spec.md:383` requires independent accounting
   outside marked regions; checking only the marked matrix is insufficient.
   Restore that accounting with expectations appropriate to the live artifact;
   do not approve an allowlist generated from the same unchecked output.

2. **P2 — HTTP links to the site's own hostname bypass internal resolution.**
   `web/tests/publication/build.test.ts:68` skips every origin other than exactly
   `https://ikpk.su`, including `http://ikpk.su`. A link to a nonexistent internal
   pathname using HTTP is therefore accepted, although the path is absent from
   both the artifact and redirect map. Classify HTTP and HTTPS URLs on the site's
   own hostname as internal before resolving their pathnames.

All finding paths and line numbers above refer to the full reviewed revision.
