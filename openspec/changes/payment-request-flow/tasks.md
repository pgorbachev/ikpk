## 2. Тесты по спеке (отдельная сессия, до реализации)

- [ ] 2.1 Состав формы: восемь полей, у каждого программно связанная подпись
- [ ] 2.2 Точка входа: форма открывается из модального окна; в содержательной части
      `/oplata` нет ссылок на `/raspisanie-i-tseny`, порождённых переписыванием
      кнопки; вне окна нет подписи «Произвести оплату»
- [ ] 2.3 Клавиатура: фокус входит в окно, не покидает его, возвращается на кнопку;
      Escape закрывает без отправки
- [ ] 2.4 Согласие: при открытии не отмечено; без отметки заявка не уходит; ссылка
      ведёт к документу **на нашем домене** и отвечает успешно
- [ ] 2.5 Проверка заполнения: пустое обязательное поле (имя, фамилия, семинар,
      сумма, почта, телефон, согласие), сумма нечисловая / ноль / отрицательная,
      почта без `@` или без домена, телефон короче десяти цифр; дата и место —
      необязательные; сообщение об ошибке связано с полем программно; фокус на первом
      ошибочном
- [ ] 2.6 Состояния: принято → «отправлена»; отклонено по проверке → показано, что
      исправить, данные сохранены; ошибка адресата → ошибка с контактами; нет ответа
      за 10 секунд → «исход неизвестен»; адресат не задан → «отправка недоступна» и
      успех не показывается ни при каких условиях
- [ ] 2.7 Смена состояния объявляется вспомогательной технологии без перевода фокуса
- [ ] 2.8 Повторное нажатие во время отправки не создаёт вторую заявку; повтор после
      «исход неизвестен» уходит с тем же `requestId`; адресат, уже видевший этот
      `requestId`, нового обращения не создаёт
- [ ] 2.9 Без скриптов: на `/oplata` виден способ связаться напрямую, а элемента
      управления, ведущего к форме, нет
- [ ] 2.10 Диалог: объявлен модальным, имеет доступное имя по заголовку, доступную
      кнопку закрытия; фон исключён из чтения и фокуса
- [ ] 2.11 Отклонение по проверке подсвечивает именно те поля, что названы в
      `errors[].field`
- [ ] 2.9 Защита от ботов: срабатывание видно как ошибка с контактами; поле-приманка
      отсутствует в дереве доступности
- [ ] 2.10 Подписи формы говорят о заявке, а не об оплате, и сообщают, что свяжутся
- [ ] 2.11 Демонстрационный режим: обращение не создаётся, показано состояние
      демонстрации, а не «отправлена»
- [ ] 2.12 Объявленный адресат формы в сборке соответствует режиму сборки
      (позитивная формулировка, не поиск «плохих» адресов)
- [ ] 2.13 Сохранность содержания: три раздела и перечень способов оплаты (карта,
      наличные) на месте; устаревшей подводки про клик по кнопке нет
- [ ] 2.14 Отсутствие скрипта: показано «отправка недоступна» с контактами
- [ ] 2.15 Форма присутствует в собранной странице до выполнения скриптов, со своим
      опознавательным признаком и объявленным адресатом, будучи скрытой
- [ ] 2.16 Опознавательному признаку соответствует только форма заявки: посторонние
      формы сайта (`ArticleFilterBar`, `LeadMagnet`) под него не подпадают. Список
      сверить с деревом на момент написания теста, а не переносить из этого текста
- [ ] 2.17 Цель обработки данных названа в тексте рядом с отметкой согласия, а не
      только ссылкой на общий документ
- [ ] 2.18 Предъявить красный прогон всех тестов раздела 2 — до единой строки
      реализации

## 5. Гейты

- [ ] 5.1 Расширить `scripts/deploy-web.sh`: находить в `dist` формы **по
      опознавательному признаку** (не по элементу `<form>` — посторонних форм на сайте
      три) и сверять объявленный адресат каждой с режимом сборки
- [ ] 5.2 Способ сверки — буквальное равенство значения из `dist` тому значению,
      которое скрипт передал в сборку; regex «по образцу хоста» не писать, образца у
      будущего транспорта нет
- [ ] 5.3 Гейт краснеет в пяти случаях: адресат не соответствует режиму; форма есть,
      объявления нет; объявление есть, формы нет; **форма ожидается, но не найдена ни
      одной**; проверить не удалось
- [ ] 5.4 «Нечего проверять» (нечитаемый каталог, ноль файлов) — отказ, а не успех;
      коды `grep` разбираются явно
- [ ] 5.5 Проверка «содержимое заявки не в логах» сведена к конечному списку точек:
      код формы не выводит значения полей, вывод сборки их не содержит
- [ ] 5.6 **Негативная проверка каждой ветки:** боевой адресат в демо-сборке; форма
      без объявления; объявление без формы; **форма смонтирована только по клику и в
      `dist` отсутствует**; пустой каталог; вывод значения поля в лог. Убедиться, что
      гейт краснеет в каждом случае, и предъявить вывод
- [ ] 5.7 Пройти каждую ветку гейта хотя бы раз — непройденная ветка считается
      непроверенной
