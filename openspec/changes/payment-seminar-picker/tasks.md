## 0. Прежде реализации

- [ ] 0.1 Согласовать с заказчиком подстановку суммы из расписания: по текущему процессу
  сумму называет менеджер (`openspec/specs/online-payment/spec.md:3151`, решение владельца
  2з от 13.08.2026). До ответа задачи 3.x не выполняются, остальные — выполняются.
- [ ] 0.2 Ревью спеки двумя независимыми исполнителями с разными уклонами, затем владелец.
- [ ] 0.3 Красные тесты по сценариям спеки — **отдельная сессия с чистым контекстом**,
  красный прогон предъявлен (отдельный push с одними тестами либо лог с командой и SHA).

## 1. Вывод перечня

- [ ] 1.1 Модуль вывода перечня рядом с `web/src/lib/schedule-window.ts`: из записей
  расписания и **опорной даты аргументом** — семинары с актуальными датами, по возрастанию
  ближайшей даты, у каждого его записи (дата, город, цена).
- [ ] 1.2 Правило актуальности берётся из `isCurrentOrFuture`, не выводится заново.
- [ ] 1.3 Unit-тесты фикстурами: актуальный, законченный, идущий сегодня, порядок,
  повторный вызов с той же опорной датой.

## 2. Разметка и выбор

- [ ] 2.1 Поле «Семинар» — выбор из перечня вместо текстового ввода.
- [ ] 2.2 Данные перечня встраиваются в страницу на сборке через `getScheduleEntries()`,
  не по пути к файлу.
- [ ] 2.3 Выбор даты для семинаров с несколькими актуальными датами.
- [ ] 2.4 «Место проведения» и «Дата начала» — `readonly`, не `disabled` (design, Решение 1).
- [ ] 2.5 Смена семинара переписывает подставленные значения без остатков прежнего выбора.
- [ ] 2.6 Пустой перечень: сообщение о недоступности оплаты, способ связи, отправка не
  предлагается.

## 3. Сумма (после 0.1)

- [ ] 3.1 Подстановка цены выбранной записи значением по умолчанию.
- [ ] 3.2 Отсутствующая цена — пустое поле, не ноль.
- [ ] 3.3 Правка посетителя не затирается перерисовкой.

## 4. Отправка и восстановление

- [ ] 4.1 `payload()` отправляет закрытые поля в составе восьми значений — проверить, что
  блокировка их не выбросила.
- [ ] 4.2 Проверка семинара — совпадение с элементом перечня, а не непустота.
- [ ] 4.3 Восстановление попытки: семинар в перечне есть — восстановить с местом и датой;
  нет — остальные поля восстановить, семинар не выбран, место и дата пусты, посетителю
  сказано выбрать заново.

## 5. Доступность

- [ ] 5.1 Закрытые поля читаются со значением и признаком нередактируемости.
- [ ] 5.2 Подстановка объявляется вспомогательной технологии.
- [ ] 5.3 Выбор даты имеет программно связанную подпись.
- [ ] 5.4 Прогон axe по диалогу в обеих темах, состояния: перечень пуст, семинар не
  выбран, семинар с одной датой, семинар с несколькими датами.

## 6. Гейты и приёмка

  убедиться, что покраснел **именно он** — судить по имени упавшего теста, не по цвету
  прогона; мутация записана командой или патчем плюс два числа.

- [ ] 6.4 Ревью кода двумя независимыми исполнителями, не автором реализации.
