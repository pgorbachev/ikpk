- [ ] 3.2 `[RED]` Идемпотентность: два запроса с одним `requestId` не создают два вызова

- [ ] 3.3 `[RED]` Контракт `GET .../payments/{requestId}/status`: сопоставление ответов

- [ ] 3.4 `[RED]` Секрет не в ответе и не в логе: тест форсирует ошибку замоканного
      ЮKassa (например, `401` от API) и проверяет, что ни HTTP-ответ клиенту, ни

- [ ] 3.5 `[RED]` Лимит частоты: N+1-й запрос создания платежа с одного источника в

- [ ] 3.6 `[RED]` Границы суммы: значения `999`, `200001`, `0`, отрицательное, нечисловое

- [ ] 3.7 `[RED]` Клиент: точка входа ровно одна на `/oplata`, кнопка не переписана в
