## 1. Красные тесты отдельной сессией

- [x] 1.1 В сессии с чистым контекстом, без этой переписки, написать тесты по сценариям дельты и не менять классификатор. Предъявить красный прогон с командой и SHA.
- [x] 1.2 Книжная правка зарегистрированного узла (`peer` при тех же `version`, `resolved`, `integrity` и картах) не удерживает patch `web` или `scripts`. Тот же пропуск — если карты совпадают по составу, но ключи идут в другом порядке, либо карта отсутствует на одной стороне и пуста на другой.
- [x] 1.3 Смена `version`, `resolved`, `integrity` или ребра карты у зарегистрированного узла удерживает весь PR. Узел только на одной стороне тоже удерживает. Сериализация проекции целиком, чувствительная к порядку ключей, этот пункт не закрывает.
- [x] 1.4 Прямое имя из реестра, включая `parse5`, удерживает PR, даже если прочая идентичность узла не отличалась бы.
- [x] 1.5 Нечитаемый реестр по-прежнему оставляет npm PR пакета `web` на ручном пути.
- [x] 1.6 Patch или minor одного имени из toolchain-списка в `cms` помечается к автослиянию. Отдельный PR `cms` на `typescript-eslint` тоже помечается, а совместный подъём `web` и `scripts` остаётся другим PR.
- [x] 1.7 `styled-components`, пакет Strapi, `@types/react` и `@types/react-dom` в `cms`, любое обновление `payments` (включая `typescript-eslint` и `tsx`), major имени из списка и смешанная группа не помечаются.
- [x] 1.8 Прежние разрешения `web`, `scripts` и `github-actions` и запрет major не сдвигаются. Негативная мутация каждого нового разрешения возвращает ручной путь.

- [x] 2.1 Сравнивать зарегистрированный узел проекцией идентичности в `web/scripts/check-dependabot-auto-merge.ts`, а не сериализацией всей записи.
- [x] 2.2 В `web/scripts/lib/dependabot-auto-merge.ts` пускать `cms` только для patch/minor закрытого списка из шести имён. `payments`, имя вне списка и major остаются отказом. Наименее разрешающий член группы сохраняется.

После появления коммита с новым классификатором в `main` перевести `uses` в `.github/workflows/dependabot-auto-merge.yml` с `31fab247adc91d49deb1e45c58f0bc7cf5439b65` на SHA этого коммита. До этой замены прод продолжает старый движок.
