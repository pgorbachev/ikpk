## 3a. Чужие инварианты, которые change ломает молча

Группа отдельная и идёт **раньше кода**, потому что каждый её пункт роняет обязательный прогон по
причине, не связанной с предметом новой работы, — то есть выглядит как поломка чужого.

- [ ] 3a.1 Реестр исполняемого вывода — процедура из **двух** инструментов и **двух** фикстур, в
      обязательном порядке: сначала генератор инвентаря слотов, затем генератор вхождений. Обратный
      порядок стирает все вхождения. Обоим нужны собранные боевое и демо-деревья, обоим — чистое
      рабочее дерево, то есть код закоммичен до регенерации
- [ ] 3a.1a Оценить объём: фасад в общем layout даёт правило на каждый маршрут на каждый исполняемый
      узел. Порядок величины — сотни правил (один `svg` в общем компоненте шапки даёт 574 при 4702
      вхождениях на 287 маршрутов). Это не правка нескольких строк
- [ ] 3a.1c Стили фасада положить в **общий внешний стиль**, не в компонентный: компонентные
      инлайнятся на каждой странице независимо от условного рендера. Цену реестра планировать в **обоих**
      вариантах: хеш считается по содержимому собранного чанка, а не по байтам файла, поэтому признак у
      **287** вхождений переписывает любая правка, попадающая в общий чанк. Выбор между вариантами решает
      байтовый вес страницы, а не цена реестра
- [ ] 3a.1d Регенерацию вести при **обоих** собранных деревьях: при одном инструмент молча пишет
      усечённый реестр, и падает потом сверка по второму выводу — по причине, не похожей на настоящую
- [ ] 3a.1b Учесть, что сдвигается и привязка `placement` (ближайший предшествующий `id` либо
      порядковый номер), а не только идентификатор слота: наш контейнер с `id` переписывает привязку
      соседям
- [ ] 3a.2 Адрес загрузчика чата записывать **со схемой**. Но enforcement назвать честно: класс
      `protocol-relative` срабатывает только для закрытого перечня атрибутов адреса, и `data-*` в него
      не входит — значит это наше правило и наша проверка, а не следствие чужого гейта
- [ ] 3a.2a Проверить, что адреса загрузчика нет ни в одном исполняемом узле вывода: ни в `src`
      скрипта, ни в `src` кадра — только в атрибуте данных. Предмет непуст (адрес в выводе есть) и
      краснеет мутацией, переносящей адрес в `src`
- [ ] 3a.3 Ни одного инлайнового обработчика событий в наших элементах — класс `event-handler` той же

- [ ] 3a.4a Инструмент разбора назвать до кода: гейт выкладки — bash (`scripts/lib/deploy-checks.sh`),

      гейта над тем же `$DIST_DIR`; node в среде выкладки уже требуется сборкой. Без этого пункта
      «разбор разметки» — решение без инструмента
- [ ] 3a.4 Гейт выкладки: назначение определять **разбором разметки** — элемент, его атрибут и
      существенные для смысла атрибуты рядом. Уточнять регулярное выражение бессмысленно, замерено три

      чат работает на каждой странице. TBT, CLS, LCP, Performance **и доступность** —
      чужой DOM кнопки чата считается в том же показателе: `web/lighthouserc.cjs:24`, `'categories:accessibility':`.
      Сравнить с порогами: `web/lighthouserc.cjs:26`, `'total-blocking-time':`
- [ ] 8.2 При падении по TBT различить «наши виджеты» и известный флак TD-11 измерением частоты,
      а не по первому прогону
- [ ] 8.3 Обновить объявленный состав покрытия сравнения облика: секция отзывов на главной и
      кнопка чата на всех страницах. Расхождение состава с фактическим прогоном — отказ, а не
      деталь
- [ ] 8.4 Исключить из сравнения облика поимённо **один** датозависимый фрагмент — строку знаков
      наград. Способ не наш: `visual-regression-gate` предписывает «блок не в манифест **либо** фрагмент
      исключается явно», и взята вторая ветвь; первая вычеркнула бы секцию отзывов целиком. Блока часов
      в этом перечне быть НЕ должно: своего блока часов нет
- [ ] 8.4a Два предмета не смешивать: датозависимость знака — **две сборки**, различающиеся `BUILD_YEAR`
      (момент показа на состав знаков не влияет вовсе); повторяемость эталонов — один момент, два прогона.
      Один тест на сценарии двух требований делает расхождение между ними невидимым для обоих
- [ ] 8.4h Записать в `docs/tech-debt.md` **все** известные отклонения этой возможности — их семь, и ни
      одного там сейчас нет (проверено: TD-1…TD-43, ни одной записи про виджеты или чат): три прежних
      (задачи 7.3c, 7.4a, 8.4c), часы недоступны при неответившем загрузчике, страница выходит из
      покрытия сравнения облика при неутверждённой рамке, портал не настроен и панель показывает
      умолчание сервиса. Их **шесть**, а не семь: доступность внутри стороннего виджета — это и есть
      одно из трёх прежних (задача 7.4a), и складывать её вторым разом значит искать несуществующее
      седьмое
- [ ] 8.4b В состав покрытия включать нашу кнопку (она есть до стороннего скрипта) и **не** включать
      появившийся после активации чужой интерфейс: при перехвате его не существует, и покрытие
      потребовало бы блок, которого нет по построению
- [ ] 8.4c Известным отклонением записать **только** часть про сравнение с принятым эталоном: её
      исполняет прогон из списка признанного долга. Сценарий повторяемости (два снимка при одном моменте
      плюс контроль отрендеренности) реализуется **отдельным** прогоном в гейтующем workflow — внутри
      `visual-baseline.spec.ts` его писать нельзя, файл не может быть одновременно в гейте и в долге
- [ ] 8.4d Покрыть структуру заголовков: инвариант идёт по **четырём** адресам, а не по всем. Спека
      выбор уже сделала — покрытие остаётся четырьмя шаблонами, расширение отдельная работа; здесь
      только зафиксировать это в проверке
- [ ] 8.4e Повторяемость проверять **сравнением снимков между собой** при одном моменте и подставных
      ответах сторонних сервисов, плюс контроль «страница отрендерена»: без него совпадают два снимка
      пустой страницы. С принятым эталоном не сравнивать — эталоны снимаются только в CI, и сравнение
      мерило бы совпадение с чужим окружением; эта часть принадлежит `visual-regression-gate`
- [ ] 8.4f Проверку исключения знака писать на **двух сборках**, различающихся `BUILD_YEAR`: год у знака
      вычисляется на сборке, поэтому подстановка момента в прогон его состава не меняет. Положительный
      контроль обязателен — состав знаков в этих сборках должен различаться. **Место и вход:** сборки
      делает тот же джоб, что уже собирает два дерева; проверка живёт в новом гейтуемом прогоне рядом с
      проверкой повторяемости, не в прогоне эталонов. Отсутствие манифеста покрытия сценарий НЕ
      откладывает — см. 8.6a
- [ ] 8.4g Строке знаков наград вдобавок к исключению зарезервировать **рамку**: позиция и размер не
      зависят от состава знаков внутри неё. Без этого зависимость не «ограничена фрагментом» — при нуле
      знаков строка не рендерится, высота секции меняется, и содержимое ниже сдвигается ВНЕ
      замаскированной области. Измеряется рамка строки и рамка следующего за ней элемента: строка стоит
      в обычном потоке секции. Кадры трёх состояний строки — предусловие 1.4
- [ ] 8.5 Перезахватить визуальные эталоны — **последним шагом**, только в CI, после того как
      облик секции окончателен
- [ ] 8.6a Манифеста покрытия в репозитории нет, но сценарии этой возможности **не отложены**: состав
      покрытия читается исходником прогона эталонов, исключение фрагмента делается маскированием — оба
      приёма доступны сегодня и уже применены в дереве. Когда манифест появится, меняется предмет
      чтения, а не сценарии. Прежняя редакция этого пункта откладывала их и тем выдавала разрешение не
      строить красное состояние там, где оно построимо
- [ ] 8.6 Если `visual-regression-gate` заархивирован раньше этого change — проверить дельты
      **применением** в одноразовом worktree, а не только строгой валидацией

## 9. Приёмочный цикл: ревью и e2e до устранения всех находок

Цикл, а не однократный проход: каждая итерация повторяется, пока находок не останется.

- [ ] 9.1 Прогнать релевантные локальные гейты в изменённых пакетах: `npm run lint`,
      `npm run typecheck`, `npm run build`, `npm run test:build` (затронуты стили и layout),
      `./bin/check-spec-refs`
- [ ] 9.2 Прогнать e2e: Playwright на desktop и mobile — доступность, перекрытие кнопки чата,
      ленивое встраивание, ветка без скриптов
- [ ] 9.3 Ревью кода двумя независимыми исполнителями с разными уклонами, ни один — не автор
      реализации
- [ ] 9.4 Внести подтверждённые находки; отклонённые назвать с причиной
- [ ] 9.5 **Повторить 9.1–9.4 по дельте внесённых правок.** Ревью относится к SHA, а не к имени
      ветки: после правок голова не считается отревьюированной
- [ ] 9.6 Выйти из цикла только когда прогоны зелёные и открытых подтверждённых находок нет.
      Красный `cms/audit:prod` — известное исключение, упоминается в summary, регресс относительно
      зафиксированного состояния блокирует
- [ ] 9.7 Проверить число check-runs на PR: при конфликте `pull_request`-проверки не запускаются
      вовсе, и «зелено» читается как отсутствие проверок
