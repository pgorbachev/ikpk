Порядок групп задан зависимостями из `design.md` (Migration Plan), а не удобством. Группы 1–2
идут до кода: тесты по спеке пишутся в отдельной сессии с чистым контекстом, и их красный прогон
предъявляется. Группа 9 — приёмочный цикл: ревью и e2e-проверки повторяются до устранения всех
находок, а не однократно.

## 1. Предусловия, без которых работа встанет

- [ ] 1.1 Получить у заказчика через владельца идентификатор загрузчика чата и портал
      (`b24-cbqwqo` либо `b24-kbo5ls`). До ответа чат не собирается по требованию спеки — это
      законное состояние, а не блокировка остальных задач
- [ ] 1.2 Получить у заказчика через владельца адрес карточки организации в 2ГИС либо
      подтверждение, что её нет. При отсутствии знак 2ГИС не показывается — change от этого не
      блокируется
- [ ] 1.3 Проверить условия использования марок «Хорошее место» и «Здесь хорошо!» на сайте.
      Знак — наше утверждение, а не плашка сервиса
- [ ] 1.4 Снять один кадр итоговой раскладки секции: вариант A без нашей сводки чисел, с двумя
      знаками наград. Правило «мокапы до внедрения» закрывается кадром, а не рассуждением
- [ ] 1.5 Записать решение по оправе области виджета на тёмной теме (открытый вопрос `design.md`)
      или зафиксировать как известное отклонение

## 2. Тесты по спеке — отдельная сессия, до реализации

- [ ] 2.1 Начать сессию с чистым контекстом: на входе только утверждённые `proposal`, `spec`,
      `design`, `tasks` и код репозитория
- [ ] 2.2 Написать проверку на каждый сценарий спеки либо явно отметить, почему проверки нет и
      чем сценарий закрывается вместо неё
- [ ] 2.3 Проверки размещения секции и отсутствия встраивания на прочих страницах — по выводу
      боевой сборки
- [ ] 2.4 Проверки «своей сводки чисел нет», «текстов и авторов отзывов нет» — по выводу боевой
      сборки, признаком служит содержимое разметки, а не имя компонента
- [ ] 2.5 Проверки ленивого встраивания: до появления секции ни одного запроса к домену виджета;
      появление виджета не сдвигает содержимое
- [ ] 2.6 Проверка ветки без скриптов: ссылка есть, встраивания нет
- [ ] 2.7 Проверки знака награды на фикстурах: год совпадает, год прошёл, источник не объявлен.
      Момент времени передаётся значением
- [ ] 2.8 Проверки часов работы на фикстурах границ: пятница 17:59 и 18:00, суббота 12:00,
      понедельник 09:59 и 10:00. Зона Europe/Moscow
- [ ] 2.9 Проверка «часы и телефон видны при недоступном загрузчике чата»
- [ ] 2.10 Проверки конфигурации чата: адрес задан — встраивание есть; адрес не задан —
      встраивания нет и умолчание не подставлено
- [ ] 2.11 Проверки демо-вывода на признак **встраивания** (адрес виджета, адрес загрузчика) во
      всех атрибутах, включая атрибуты данных
- [ ] 2.12 Симметричные проверки боевого вывода: оба встраивания присутствуют. Предмет — боевой
      каталог, не демо
- [ ] 2.13 Проверка текста документа о персональных данных: назван чат с получателем данных,
      назван сторонний счётчик виджета
- [ ] 2.14 Проверка «своей формы сбора данных для чата нет» — по выводу сборки
- [ ] 2.15 Проверки доступности: наши части секции и блок часов без critical/serious; у
      встраивания есть название; исключён из axe только сам сторонний iframe
- [ ] 2.16 Проверка перекрытия закрытой кнопкой чата: интерактивные элементы и **рамка текста**,
      а не рамка блока
- [ ] 2.17 Проверка детерминированности визуальных эталонов: два прогона на неизменном дереве
      совпадают; результат не меняется при недоступных сторонних сервисах
- [ ] 2.18 Предъявить **красный прогон**: отдельный push коммита только с тестами (упавший
      check-run на этом SHA) либо лог красного прогона с точной командой и SHA. «Тесты лежат
      коммитом раньше» доказательством не является
- [ ] 2.19 Негативная верификация каждой новой проверки: временно нарушить поведение, убедиться,
      что покраснела **именно** она, судить по имени упавшего теста, а не по цвету прогона

## 9. Приёмочный цикл: ревью и e2e до устранения всех находок

Цикл, а не однократный проход: каждая итерация повторяется, пока находок не останется.

- [ ] 9.1 Прогнать релевантные локальные гейты в изменённых пакетах: `npm run lint`,
      `npm run typecheck`, `npm run build`, `npm run test:build` (затронуты стили и layout),
      `./bin/check-spec-refs`
- [ ] 9.2 Прогнать e2e: Playwright на desktop и mobile — доступность, перекрытие кнопки чата,
      ленивое встраивание, ветка без скриптов
- [ ] 9.3 Ревью кода двумя независимыми исполнителями с разными уклонами, ни один — не автор
      реализации
- [ ] 9.4 Внести подтверждённые находки; отклонённые назвать с причиной
- [ ] 9.5 **Повторить 9.1–9.4 по дельте внесённых правок.** Ревью относится к SHA, а не к имени
      ветки: после правок голова не считается отревьюированной
- [ ] 9.6 Выйти из цикла только когда прогоны зелёные и открытых подтверждённых находок нет.
      Красный `cms/audit:prod` — известное исключение, упоминается в summary, регресс относительно
      зафиксированного состояния блокирует
- [ ] 9.7 Проверить число check-runs на PR: при конфликте `pull_request`-проверки не запускаются
      вовсе, и «зелено» читается как отсутствие проверок
