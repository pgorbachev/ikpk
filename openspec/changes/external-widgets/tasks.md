## 3a. Чужие инварианты, которые change ломает молча

Группа отдельная и идёт **раньше кода**, потому что каждый её пункт роняет обязательный прогон по
причине, не связанной с предметом новой работы, — то есть выглядит как поломка чужого.

- [ ] 3a.1 Реестр вхождений исполняемого вывода: вставка компонентов в общий layout сдвигает ключи.
      Обновить **назначенным инструментом из отревьюированной ревизии**, не перегенерацией в прогоне
      (принятая спека это прямо запрещает) и не правкой на месте
- [ ] 3a.2 Адрес загрузчика чата записывать **со схемой**: форма `//host/…` относится к классу
      `protocol-relative`, который сверка исполняемого вывода отвергает
- [ ] 3a.3 Ни одного инлайнового обработчика событий в наших элементах — класс `event-handler` той же
      сверки
- [ ] 3a.4 Гейт выкладки: научить признак различать ссылку формы и загрузчик виджета по назначению.
      Проверить оба тихих исхода — адрес в `src` (боевая выкладка блокируется законной сборкой) и
      адрес в атрибуте данных (проверка слепа, живой чат уедет на стенд)
- [ ] 3a.5 Негативная мутация 3a.4: вернуть каждый из двух исходов и убедиться, что покраснела
      **именно** эта проверка, а не соседняя
- [ ] 3a.6 Симметричный контроль на выкладке боевого сайта: встраивание чата соответствует
      ожидаемому для режима — тем же способом, что уже сделан для ссылок форм и платёжного эндпоинта
- [ ] 3a.7 Объявить конфигурацию адреса загрузчика **там, где её читает проверка**. Значение только в
      окружении выкладки → у симметричной проверки нет предмета; только в сборке → боевая выкладка
      уедет без чата
- [ ] 3a.8 Зарегистрировать каждую новую проверку в трёх реестрах: исключения основного прогона плюс
      включения своего конфига (точное равенство множеств); гейтующий workflow либо список признанного
      долга; ровно один предмет на файл
- [ ] 3a.9 Записать долг с **названными получателями**: список сторонних хостов — для будущей CSP
      (отдельного change под неё нет, а change про переезд раздачи предмет исключает); периодическая
      пересборка — для change «свежесть публикации». Абзац в `design.md` передачей не является

## 9. Приёмочный цикл: ревью и e2e до устранения всех находок

Цикл, а не однократный проход: каждая итерация повторяется, пока находок не останется.

- [ ] 9.1 Прогнать релевантные локальные гейты в изменённых пакетах: `npm run lint`,
      `npm run typecheck`, `npm run build`, `npm run test:build` (затронуты стили и layout),
      `./bin/check-spec-refs`
- [ ] 9.2 Прогнать e2e: Playwright на desktop и mobile — доступность, перекрытие кнопки чата,
      ленивое встраивание, ветка без скриптов
- [ ] 9.3 Ревью кода двумя независимыми исполнителями с разными уклонами, ни один — не автор
      реализации
- [ ] 9.4 Внести подтверждённые находки; отклонённые назвать с причиной
- [ ] 9.5 **Повторить 9.1–9.4 по дельте внесённых правок.** Ревью относится к SHA, а не к имени
      ветки: после правок голова не считается отревьюированной
- [ ] 9.6 Выйти из цикла только когда прогоны зелёные и открытых подтверждённых находок нет.
      Красный `cms/audit:prod` — известное исключение, упоминается в summary, регресс относительно
      зафиксированного состояния блокирует
- [ ] 9.7 Проверить число check-runs на PR: при конфликте `pull_request`-проверки не запускаются
      вовсе, и «зелено» читается как отсутствие проверок
