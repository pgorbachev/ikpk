## Context

Основание и границы — в `proposal.md`. Исследовано состояние origin/main с SHA
2fee597b5335f6c61fd61a622fa2a5f3f475a605.
`web/src/scripts/payment-form.ts` собирает `venue` из input в `payload()`;
`collectFields()` перезаписывает снимок перед отправкой, а `applyFields()` пропускает
значение, если элемента нет. В `payments/src/app.ts` место входит в отпечаток.
Простое удаление input изменит повтор старого запроса.

## Goals / Non-Goals

**Goals:** убрать поле, сохранить совместимость имеющихся снимков и повторов.

**Non-Goals:** новый формат хранилища, постоянное хранение полей, изменение API,
канонического восьмипольного отпечатка или версии ключа. Принятая владельцем граница
дедупликации разных ID с разным местом названа в proposal; иные защиты не ослабляются. Дополнительное получение места с сервера не вводится.

## Decisions

1. Удалить блок места из `web/src/components/payment/PaymentForm.astro`; не добавлять
   скрытый input. Новые запросы явно передают `venue: null`.
2. Для повтора читать исторический `venue` из снимка по текущему `requestId` и применять
   ту же нормализацию, что делал прежний payload: trim, пустая строка → null.
   При пересохранении остальных полей сохранять это значение в том же снимке, включая
   повтор подтверждения дубликата. Не использовать глобальное «последнее место»:
   переключение удержаний не должно смешивать значения.
3. Сохранить имеющийся перенос снимка при серверном переназначении `requestId` по
   существующему протоколу полного совпадения. Снимок хранится в `sessionFields` по ID;
   нельзя подменить уже доступный точный снимок другой удержанной попытки чужим местом.
   Действие новой оплаты не наследует историческое место; после возврата к другой
   удержанной попытке её снимок остаётся доступным.
4. Если снимок утрачен, место не угадывать и не восстанавливать input: отправлять null
   под прежним идентификатором, сохраняя серверные исходы и правила удержания.
   Изменение серверного отпечатка ради такого повтора затронуло бы совместимость всех
   платежей и не требуется для удаления поля.

## Risks / Trade-offs

- [Потеря значения после первого повтора] → проверять последовательные POST, а не
  только восстановление DOM, включая подтверждение дубликата.
- [Историческое место чужой попытки или новой оплаты] → сценарии переключения удержаний,
  переназначения идентификатора и «Оплатить другой семинар».
- [Старое непустое место утрачено вместе с сессией] → прежний отпечаток не воспроизводится;
  допускается существующая безопасная сверка. Ограничение принято владельцем 2026-10-21; удержание и серверная сверка сохраняются.
- [Новая попытка не распознаётся как дубликат исторической с непустым местом] → отпечатки
  различаются даже при совпадении остальных семи значений. Сохранение API и отпечатка
  не устраняет эту границу; владелец принял её 2026-10-21. Проверить исторические
  `pending`, `unknown` и `succeeded`, а также старую кешированную форму с непустым местом.
- [Пересечение с `payment-seminar-picker`] → обновить его существующие артефакты и
  проверить оба порядка применения. Только remove меняет общий состав UI-полей; picker
  задаёт выбор и восстановление в своих существующих требованиях и не перезаписывает
  состав формы. Это предотвращает возврат места при последующем архиве.

## Migration Plan

Изменение ограничено фронтендом. Старые снимки читаются без массового преобразования,
серверные записи не переписываются. После двух независимых ревью и проверок обычная поставка
фронтенда; при отказе откат его версии без отката данных.
