## Context

База — коммит `7b4548d234710e0f0daacc2c8a46787b1e822e2f`. Классификатор в
`web/scripts/lib/dependabot-auto-merge.ts` пускает patch/minor только для npm `web`,
npm `scripts` и `github-actions`. Сравнение узлов реестра в
`web/scripts/check-dependabot-auto-merge.ts` считает узел изменённым, если
`JSON.stringify` всей записи различается. Из-за этого снятие `peer` у
`node_modules/playwright-core` удерживает PR, у которого `version` и `integrity` те же.

На этой же ревизии обязательный `cms checks` запускает eslint, `tsc` и `npm test`.
Скрипт `test` покрывает `src/**/*.test.ts` и `tests/*.test.js`. `cms` `test:e2e` стоит
в nightly, а не в проверке, которая обязательна для слияния PR. У `payments` в
`payments/package.json` нет скрипта тестов: обязательны eslint, `tsc` и audit. Процесс
`payments` стартует через `node --import tsx`.

См. proposal.md — зачем сужать класс. Требование — в дельте
`specs/dependency-update-automation/spec.md`.

## Goals / Non-Goals

**Goals:**

- Сравнивать зарегистрированный узел по идентичности, а не по всей записи lockfile.
- Дать автослияние patch/minor закрытого списка линтера и типов в `cms`.
- Оставить отказ на major, на имени вне списка и на смешанной группе.

**Non-Goals:**

- Не менять `.github/dependabot.yml` и не освобождать `payments` от требования
  группировки. Группа `payments-minor-patch` уже сейчас без `group-by: dependency-name`.
  Это прежнее расхождение конфига с принятым требованием, а не новое разрешение.
  Освобождение группы сделало бы дефект нормой. Классификатор судит пришедший PR по
  наименее разрешающему члену и этим группировку не отменяет.
- Не переносить `cms` в общий scope `web` + `scripts`. Принятое требование группировки
  запрещает одну группу на `cms` и `web`/`scripts`.
- Не менять матрицу статусов eligibility/provenance. Её незаархивированная дельта —
  `dependabot-policy-status`. Разрешённый класс по-прежнему даёт положительный
  eligibility, ручной класс — не разрешение.
- Не переписывать требование о происхождении целиком. В дельте
  `dependabot-policy-status` пример остаточного риска уже сужен до обновления `cms`,
  которого разрешающая таблица не допускает. Вторая полная копия того требования здесь
  не нужна.
- Не слать `@dependabot rebase` и не переоценивать открытые PR в этой поставке.
  Комментарий боту по-прежнему требует отдельного разрешения владельца.

## Decisions

### 1. Идентичность узла, а не вся запись и не один `version`

Сравниваются `version`, `resolved`, `integrity` и карты `dependencies` и
`optionalDependencies`. Отсутствующая карта равна пустой. Порядок ключей не учитывается.
Узел только на одной стороне — различие. Ключи `peer`, `dev`, `optional`, `license`,
`engines`, `bin`, `funding` и любой другой ключ записи сами по себе различия не создают.

`integrity` держит байты архива. Карта зависимостей держит рёбра, записанные на самом
узле: смена ребра без смены `version` всё ещё ручной путь. Прямое имя из реестра
запрещает PR независимо от lockfile.

**Отвергнуто: сравнивать только `version`.** Подмена `resolved`/`integrity` при том же
номере и смена ребра прошли бы молча.

**Отвергнуто: игнорировать только ключ `peer`.** Следующая пересборка lockfile снимет
`dev` или `license` и снова остановит уже разрешённый patch. Список игнорируемых ключей
тогда придётся растить каждым релизом npm.

### 2. Закрытый список имён только для `cms`

Список: `@eslint/js`, `eslint`, `globals`, `typescript`, `typescript-eslint`,
`@types/node`. Только `semver-patch` и `semver-minor`. Имя читается из metadata
Dependabot, не из секции манифеста.

Покрытие, на которое опирается допуск: обязательный контекст `cms checks` гоняет
eslint, `tsc` и `npm test`. Серверный код `cms` импортирует `node:`, поэтому сломанный
`@types/node` краснит `tsc` на включённых файлах. `skipLibCheck` не отменяет ошибки в
этих файлах.

**Отвергнут весь пакет `payments`.** На 21.11.2026 обязательные контексты `main` —
тринадцать имён, среди них `Runtime dependency audit (payments)` и нет
`payments checks`. Audit вызывает `npm audit --omit=dev`. Все имена списка в
`payments` стоят в секции разработки, так что обязательная проверка их не видит.
Автослияние прошло бы при красном eslint и `tsc`. Открытый #492 остаётся ручным.

**Отвергнуты `@types/react` и `@types/react-dom`.** Импорты React в отслеживаемом коде
`cms` лежат в `cms/src/admin/`. `cms/tsconfig.json` исключает этот каталог и не включает
`.tsx`. Обязательный `tsc` на таком подъёме не краснеет.

**Отвергнуто: вся секция разработки.** Секция уже отвергнута как признак. Новая
зависимость в той же секции попала бы в допуск молча.

**Отвергнуто: весь patch/minor `cms`, потому что тесты уже есть.** `npm test` в
обязательном джобе не исполняет Strapi, React и `styled-components` как админку.
Ночной `test:e2e` не является условием слияния этого PR.

### 3. Смешанная группа остаётся отказом без смены конфига

Наименее разрешающий член уже принят. `payments` в таблицу не входит, поэтому состав
его группы разрешения не создаёт. Отдельный PR `cms` на имя из списка не склеивается с
`web` и `scripts`: группировка по-прежнему запрещает одну группу на `cms` и эти пакеты.
Освобождать `payments` от `group-by` этот change не будет: это легализовало бы уже
существующий дефект конфига.

### 4. Pin dispatcher переезжает на коммит с новым классификатором

Вызов policy в `.github/workflows/dependabot-auto-merge.yml` закреплён на
`31fab247adc91d49deb1e45c58f0bc7cf5439b65`. Джоб оценки делает checkout
`job.workflow_sha`, то есть этого pin, а не вершины `main`. На pin и на `main` три файла
движка сейчас совпадают, поэтому поведение одно. После правки классификатора на `main`
прод останется на старом правиле, пока `uses` не укажет на коммит, в дереве которого
новый классификатор уже есть. Переводить pin заранее нельзя.

## Risks / Trade-offs

- [npm запишет значимое отличие в ключ вне идентичности] → байты архива остаются на
  `integrity`, рёбра — на картах, прямое имя реестра — на metadata. Поле, которое не
  меняет ни одно из трёх, не выбирает другой код.
- [Группа `payments` содержит имена из списка `cms`] → пакет `payments` в таблице
  отсутствует, поэтому группа остаётся ручной. Смена группировки — отдельное решение.
- [Открытые PR не переклассифицируются сами] → оценка привязана к событию вершины.
  Старый `neutral` остаётся, пока не будет новой головы. Команду боту эта поставка не
  шлёт.
- [Пример «любое обновление `cms`» в дельте происхождения разойдётся с таблицей] →
  фраза в `dependabot-policy-status` уже говорит про обновление `cms`, которого таблица
  не допускает. Требование о происхождении здесь целиком не копируется.

## Migration Plan

Спека и ревью → утверждение владельца → отдельная сессия красных тестов → реализация
другим исполнителем. Откат — вернуть сравнение всей записи и три строки таблицы:
toolchain-PR снова станут ручными, книжный `peer` снова удержит `web`. Открытые PR при
откате не нужно перебазировать этой поставкой.

Реализация трогает проекцию узла в чтении реестра и предикат таблицы. После того как
этот коммит есть в `main`, строка `uses` в
`.github/workflows/dependabot-auto-merge.yml` переводится на его SHA. Раньше переводить
нельзя: pin должен указывать на дерево, где новый классификатор уже лежит. Branch
protection не меняется. Откат pin возвращает прежний движок, даже если код на `main`
остался новым.
