## 0. Предусловия, которые не зависят от нас

- [ ] 0.1 Внести в `docs/client-requests.md` запрос заказчику **двумя пунктами**: (а) A-запись
  на служебный субдомен (например `new.ikpk.su`) с указанием на прод-VPS, TTL 300; (б) **`CNAME`
  для `_acme-challenge.ikpk.su` и `_acme-challenge.www.ikpk.su`** на зону, которой управляем мы
  — это делегирование подтверждения владения, одно действие с его стороны и ноль его учётных
  данных у нас. Разовая TXT-запись здесь **не** годится и запрашивать её не следует: она даёт
  один выпуск и не продлевает сертификат (`design.md`, Решение 2; спека, «нормативный путь
  один»). Без (а) не выполняются задачи 6.3 и 8.2. Без (б) переключение DNS запрещено **на
  нормативном пути**; единственное исключение — объявленное заранее отступление (0.1в), у
  которого своя цена и свой гейт закрытия
- [ ] 0.1а **Нормативный путь.** Сертификат на три имени: служебное, `ikpk.su`,
  `www.ikpk.su`, до смены A-записи. Подтверждение владения каноническими именами — через запись
  в DNS: проверка по HTTP-пути до переключения невозможна, имена указывают на старый сайт.
  **При объявленном отступлении задача неприменима** — предварительного выпуска в нём нет по
  определению; вместо неё выполняется 0.1д
- [ ] 0.1в Нормативный путь — делегирование из 0.1(б): подтверждение владения автоматическое
  уже при **первом** выпуске, поэтому второго перехода не требуется. Токен API его
  DNS-провайдера не запрашивать: это доступ на запись во всю его зону.
  **Отступление** допускается только при явном отказе заказчика делегировать зону и SHALL быть
  объявлено артефактом **до** переключения (см. 0.1г). В нём **нет ручного продления**:
  предварительный выпуск на канонические имена не делается вовсе, A-запись переключается, и
  сразу после этого сертификат выпускается подтверждением через HTTP-путь — тем же механизмом,
  который затем продлевает. Цена отступления другая и названа: окно, в котором раздача отвечает
  по каноническому имени **без действующего сертификата**, то есть посетитель видит ошибку
  сертификата. Окно ограничено временем одного выпуска, шаг выпуска подготовлен заранее и
  запускается немедленно, фактическая длительность измеряется и сохраняется
- [ ] 0.1г Объявить выбранный путь артефактом до переключения: при отступлении — запись с
  причиной (отказ заказчика делегировать зону) и планом выпуска. Без объявления действует
  нормативный путь, и переключение без сертификата на канонические имена запрещено
- [ ] 0.1б **Нормативный путь.** Проверить состав имён в выпущенном сертификате **до** смены
  A-записи — по самому сертификату, а не по доступности сайта по каноническому имени.
  **При объявленном отступлении неприменима**, замена — 0.1д
- [ ] 0.1д **Только при отступлении.** Проверить состав имён сразу после первого выпуска
  (то есть после смены A-записи) — тем же способом, по самому сертификату, — и **до** объявления
  cutover завершённым. Отступление оправдывает отсутствие предварительной проверки, но не
  последующей: предмет и обязательность те же, меняется только момент
- [ ] 0.2 Завести прод-VPS. Записать в `docs/deploy-vps.md` его назначение и то, чем он
  отличается от стенда — раздельные назначения несущие, а не организационные (см.
  `design.md`, Решение 1)
- [ ] 0.3 Завести на прод-хосте непривилегированную учётную запись выкладки: владелец
  каталога релизов и конфигурации раздачи, узкий `sudo` на проверку и перезагрузку сервера
  раздачи, ключ ограничен по назначению. Root-доступ выкладки на прод-хост SHALL NOT
  использоваться (спека, «Код из стороннего репозитория не исполняется привилегированно»)
- [ ] 0.4 Записать ожидаемый признак хоста (host key) прод-VPS в конфигурацию выкладки
- [ ] 0.5 Один раз создать в дереве сервера root-owned точку подключения конфигурации:
  файл в `sites-available` со статичной строкой `include <путь, которым владеет выкладка>;`
  и симлинк в `sites-enabled`. Дальше этот файл не трогается — содержимое кладёт выкладка
  (`design.md`, Решение 6). Без этого шага у непривилегированной учётной записи нет пути
  записи в дерево сервера вовсе, и задачи 5.5–5.6 невыполнимы
- [ ] 0.6 Проверить, что процесс сервера читает файлы релиза и конфигурации после смены
  владельца каталога (сегодня `chown -R root:root "${WEB_ROOT}"` в `scripts/bootstrap-vps.sh`).
  Сверка явная, а не допущение про маску по умолчанию

## 1. Красные тесты до кода — отдельная сессия с чистым контекстом

Порядок из `AGENTS.md`: после утверждения спеки пишутся **только** тесты, в отдельной
сессии, и предъявляется красный прогон. Ниже — сценарии спеки, у каждого должна быть
проверка либо явная отметка, почему её нет. Мутации для негативной проверки перечислены в
`design.md`, раздел «Негативная проверка: что именно ломать» — там указано, **какой по имени**
тест обязан покраснеть, а не только что прогон краснеет.

- [ ] 1.1 Проверки текста конфигурации боевой раздачи: класс состояния и значение `no-store`
  дословно; правило класса присутствует и при отсутствующем содержимом; отсутствие `public`
  в этом значении
- [ ] 1.2 Проверка «правило раздачи без объявленного класса»: разбор перечисляет **все**
  правила и падает на неотнесённом. Признак общий, не перечень известных адресов
- [ ] 1.3 Проверка общего набора заголовков: находит в тексте все правила со своим
  `add_header` и требует набор в каждом. Отдельным утверждением — правило карты сайта
- [ ] 1.4 Проверка запрета: директивы `Strict-Transport-Security` в конфигурации нет
- [ ] 1.4а Гейт закрытия работы — по **артефактам**, а не по утверждению в отчёте, иначе
  красный тест не построить. Предмет проверки — два файла с известными путями (3.3):
  `deploy/acme/selected-path.md` и `deploy/acme/forced-renewal-evidence.md`; проверяющее
  средство — `bin/check-acme-evidence` (3.4). Проверка падает, когда: свидетельства нет;
  в свидетельстве нет команды, времени, имени способа подтверждения, имён в сертификате,
  вывода, исхода или признака смены сертификата; **исход неуспешен**; **сертификат не
  сменился**; **названный способ не соответствует объявленному пути** — в любую из двух
  сторон (нормативный путь со свидетельством по HTTP-пути; отступление со свидетельством по
  DNS).

  Красные фикстуры — по одной на ветвь: свидетельства нет (ожидается код `2`); свидетельство
  без одной из частей состава; **свидетельство, полное по составу, с выводом упавшего продления
  и неуспешным исходом** — эта фикстура несущая, без неё гейт зелен на задокументированном
  отказе; свидетельство с успешным исходом при неизменившемся сертификате; **`selected-path:
  normative` со свидетельством, снятым через HTTP-путь**; `selected-path: deviation` со
  свидетельством, снятым через DNS. Последние две — обе ветви сверки способа с путём: одна
  фикстура покрывает одну ветвь и оставляет вторую без предмета. Исход «свидетельства нет» отличать от «продление не работает» —
  сообщением, а не только кодом
- [ ] 1.4б Отметить явно: сам факт успешного продления на живом хосте автоматическим тестом не
  проверяется — это стендовая приёмка со свидетельством (задача 3.2). Тест сторожит **наличие и
  состав свидетельства**, а не работу ACME; подменять одно другим нельзя
- [ ] 1.5 Проверки правил схемы и хоста: наличие, сохранение пути и строки запроса, путь
  ACME-проверки не под перенаправлением, длина цепочки не больше двух шагов
- [ ] 1.6 Проверка отказа на неизвестное имя хоста
- [ ] 1.7 Проверки генератора: строка карты, не отнесённая ни к одному механизму, роняет его
  и конфигурация не записывается; отчёт называет числа по механизмам и исключениям; сумма
  равна числу строк карты с кодом 301
- [ ] 1.8 Поведенческие проверки выкладки (в `web/tests/deploy-checks.test.ts` рядом с
  существующими): отказ при несоответствии режима назначению **до** загрузки; отказ при
  необъявленном назначении; отказ при расхождении конфигурации на хосте; отсутствие
  параметра, отключающего проверку подлинности хоста
- [ ] 1.9 Проверки монитора: значение читается с раздачи; недоступность или нечитаемость —
  непройденная проверка, а не «расхождений нет»; ручное переключение релиза на предыдущий
  даёт расхождение
- [ ] 1.10 Проверка «путей публикации ровно один»: два пути — отказ, ноль путей — тоже отказ
- [ ] 1.11 Проверки роли артефакта боевой раздачи: роль `ci`, ноль форм, нет объявленного
  эндпоинта, при этом режим форм заявки боевой (то есть значения переключателей независимы)
- [ ] 1.12 Проверка атомарности переключения релиза и наличия предыдущего релиза
- [ ] 1.13 Проверки аналитики: **каждый** из двух адресов пикселей `<noscript>` в выводе
  боевой сборки — нашего происхождения; для каждого есть своё правило перевода в конфигурации,
  различающее имена, со своей целью; ответ по каждому несёт `no-store`; условие происхождения присутствует в выводе боевой сборки;
  сниппет при этом **в разметке есть** (иначе выполнение подменяется его отсутствием, что
  верно для демо-сборки и неверно здесь); при открытии страницы по неканоническому
  происхождению обращений к счётчикам нет. Третье — браузерной проверкой: текст разметки о
  поведении не говорит
- [ ] 1.14 Проверки порядка остановки прежней публикации — по **каждому** случаю, в котором
  «раздача отвечает», а достижимости нет: конечный код не 200; запрос уводит на другое имя
  хоста; `/release.json` недоступен; `/release.json` нечитаем; объявленный в нём коммит не
  равен ожидаемому. В каждом остановка не выполняется. Предикат утверждается целиком —
  `200` **и** тот же host **и** ожидаемый SHA, — а не по одному из трёх
- [ ] 1.14а Проверка доступности файлов прежних релизов: многозапросная загрузка страницы,
  где разметка взята до переключения, а файлы с хешем запрошены после, даёт 200 на каждый
  файл; адрес без хеша из прежнего релиза не отдаётся. **Границу проверять с двух сторон в
  той же мере, что в требовании** — «пять каталогов, считая действующий»: файл четвёртого
  предыдущего релиза даёт 200, файл пятого предыдущего (первого вытесненного) даёт 404 без
  `immutable`. Одна сторона границы не отличает «граница на месте» от «границы нет вовсе»
- [ ] 1.15 Отметить явно сценарии, у которых автоматической проверки нет, с причиной и
  способом ручной приёмки: живое свидетельство TLS и живой отказ на неизвестное имя требуют
  ответа сервера, о котором сборка не знает
- [ ] 1.16 Предъявить красный прогон: отдельный push коммита **только с тестами** (упавший
  check-run на этом SHA) либо лог с точной командой и SHA. «Тесты лежат коммитом раньше»
  доказательством не является

- [ ] 2.2 Перенести в артефакт классы кеширования и сжатие **без изменения значений**: они

- [ ] 2.4 Общий набор заголовков — отдельным файлом, `include` в каждом правиле со своим
  `add_header` (сегодня их шесть) и в блоке `server`
- [ ] 2.5 `X-Robots-Tag: noindex` для служебного имени, привязанный к имени, а не безусловный
- [ ] 2.6 Отказ на неизвестное имя хоста (`default_server` без содержимого сайта)
- [ ] 2.7 Блок 443 с сертификатом на имя раздачи; блок 80 — перенаправление с сохранением
  пути и строки запроса плюс путь ACME-проверки без перенаправления. `Strict-Transport-Security`
  не добавлять
- [ ] 2.8 Правила уровня сервера для перенаправлений схемы и имени `www`
- [ ] 2.8а Раздача файлов с хешем содержимого в имени из **всех** сохранённых релизов, а не

  конфигурации явно, чтобы следующий читатель не расширил правило «по аналогии»
- [ ] 2.8б Закрепить границу в **одной** мере: не менее **пяти каталогов релизов, считая

  единицу. Та же мера обязана стоять в требовании, здесь и в проверке границы (1.14а)
- [ ] 2.9 `scripts/bootstrap-vps.sh`: прод-профиль готовит пакеты, учётную запись выкладки и
  каталоги, но **не** конфигурацию сайта. Существующий отказ перезаписывать vhost стенда
  сохранить

## 3. Сертификат

- [ ] 3.1 Выпуск и продление в режиме, не изменяющем конфигурацию сайта (`certonly`).
  Проверить, что после продления следующая выкладка не сообщает о расхождении
- [ ] 3.1а **Только при отступлении** (0.1в): немедленно после смены A-записи выпустить
  сертификат на канонические имена подтверждением через HTTP-путь (имена уже указывают на наш
  хост, а путь ACME-проверки не перенаправляется по требованию спеки). Измерить и сохранить
  длительность окна без действующего сертификата. До успешного принудительного продления (3.2)
  **cutover не завершён и change не закрывается**. При нормативном пути задача неприменима —
  отметить как таковую, а не как выполненную
- [ ] 3.2 Продление автоматическое, и это подтверждено **принудительным продлением**, а не
  действующим сроком сертификата: он одинаков и при настроенном продлении, и при его отсутствии.
  Свидетельство сохранить артефактом с полным составом: точная команда, время, имя применённого
  способа подтверждения владения, имена в выпущенном сертификате, вывод, **машинно читаемый исход
  (код завершения команды продления)** и **признак смены сертификата** — сдвинувшийся срок
  окончания действия либо новый серийный номер. Исход обязателен: без него аккуратно описанное
  упавшее продление прошло бы проверку. Признак смены обязателен отдельно от исхода: средство
  продления завершается успешно и когда продлевать было нечего. Неполное свидетельство —
  непройденная проверка. Отказ продления заметен, а не молчалив
- [ ] 3.3 **Интерфейс артефактов задан путями, а не описанием**, иначе проверяющее средство
  писать не по чему: `deploy/acme/selected-path.md` — объявление выбранного пути (нормативный или
  отступление, с причиной), `deploy/acme/forced-renewal-evidence.md` — свидетельство
  принудительного продления. Состав полей каждого — поимённо в самом файле-образце, чтобы
  проверка сверяла состав, а не угадывала его. Поля исхода и смены сертификата задать
  **машинно читаемыми** (например `exit-status:` и пара «срок до / срок после» либо серийные
  номера), а не прозой внутри вывода: разбирать исход из текста сообщений чужого средства —
  значит привязать гейт к их формату
- [ ] 3.4 **Реализовать проверяющее средство** `bin/check-acme-evidence` по образцу
  существующих (`bin/check-spec-refs`, `bin/check-openspec-integration`): читает два файла из
  3.3 и утверждает положительный критерий **конъюнкцией**: состав полон **и** исход успешен
  **и** сертификат сменился (срок окончания сдвинулся вперёд либо серийный номер новый) **и**
  названный способ подтверждения соответствует объявленному пути — **на обеих ветвях**:
  нормативный путь требует подтверждения через DNS, отступление — через HTTP-путь. Сверка
  только для отступления оставляет дыру: путь объявлен нормативным, продление идёт через
  HTTP-путь, гейт зелен, а выбранный механизм не действует. Три исхода кодами выхода: `0` всё на месте; `1` состав
  неполон, исход неуспешен, сертификат не сменился либо способ не тот; `2` файлов нет вовсе
