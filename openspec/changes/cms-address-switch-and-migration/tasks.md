        теперь одна;
      - чтобы якорь работал, `transformCollapsibles` выдаёт `id="section-N"` у озаглавленных
        секций (`web/src/lib/html-cleaner.ts`). Нумерация **позиционная**: считает
        озаглавленные секции источника, включая пустые, — так она совпадает с нумерацией
        старого сайта. `section=2` подтверждён текстом ссылки («Структура и органы
        управления»); `section=3` сохранён из параметра старого URL и совпадает с
        третьей озаглавленной секцией («Уставные документы»). Текст «Положением» у
        16 ссылок называет документ из соседней секции 4, но параметр был `section=3` —
        якорь сохраняет параметр, а не угадывает секцию по слову. Вставка или
        перестановка секции молча сдвигает якоря; слаг из заголовка — после появления
        транслитератора. Секции выводятся раскрытыми, поэтому для `#section-N` скрипт
        не нужен: браузер сам прокручивает к якорю.

      **Известное отклонение (TD-71).** Принятая `static-serving` (предложение про
      `?section=3`) утверждает, что страница поддерживает этот адрес. На деле параметр
      `section` не читает ничто: теряется только прокрутка, не контент (все панели
      `<details open>`). Входящий трафик реальный — футер живого сайта. Закрытие —
      короткий инлайн-скрипт (`docs/plans/005-near-term-plan.md:324`, `?section=N`);
      в этом PR не делается: меняет поведение, закреплённое принятой спекой, и
      оформляется отдельно.

      Редиректов не заведено: адреса старого сайта не были проиндексированными страницами, а
      правило 301 без `$is_args$args` срезало бы параметр раздела — ту глубокую ссылку, которую
      `static-serving` прямо защищает. Первая редакция PR #258 шла редиректами и была отклонена
      двумя независимыми ревью по этой причине.

      **Это промежуточный шаг, и перенос обязан его сохранить.** Панели — артефакт скрейпа;
      задачи 8.4 и 8.7 переносят их тела в поля CMS, и повторное извлечение с живого старого
      сайта вернёт старые ссылки, а с ними и красноту `build-content`. Перенос переносит
      переписанные тела, а не исходные.

      Группа `build-content` ручной публикации: RED (43 вхождения, свидетельство
      `web/tests/evidence/manual-publication-legacy-links.json`) → GREEN по этому классу.

## 2. Перенос контента

- [ ] 2.1 (бывшая 8.1c) Защита правок заказчика при повторном переносе — **непрерывный** запрет редактирования
      на весь период переноса **либо атомарное условное обновление**: запись применяется только
      если целевая ревизия равна той, что оставил предыдущий прогон (conditional update по
      ожидаемой ревизии, ETag/`If-Match` или эквивалент), иначе — блокировка, удерживаемая на всё
      окно «сравнение → запись». Отдельная проверка ревизии с последующей безусловной записью
      **не годится**: между ними редактор успевает сохранить правку, и она затирается. При
      расхождении перенос останавливается и называет запись
