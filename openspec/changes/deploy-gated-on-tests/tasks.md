## 3. Негативная верификация

Каждый аспект конфигурации ломается по очереди, и проверяется, что краснеет тест **с
нужным именем**, а не соседний. Мутация выполняется в своём worktree, фикс к моменту
мутации закоммичен, восстановление подтверждается пустым `git status --porcelain` и
отсутствием diff относительно SHA реализации.

- [ ] 3.1 Убрать триггер `workflow_run` → краснеет проверка про подписку на событие
- [ ] 3.2 Заменить по-событийное условие голым сравнением `conclusion` → краснеет проверка
      про ручной запуск, а не что-то иное
- [ ] 3.3 Убрать `ref` у выгрузки → краснеет проверка про проверенный коммит
- [ ] 3.4 Убрать шаг сверки с вершиной → краснеет проверка про устаревший коммит
- [ ] 3.5 Переставить проверку происхождения после выгрузки → краснеет проверка про
      порядок, и отдельно — про выгрузку чужого кода
- [ ] 3.6 Вернуть `push: main` → краснеет проверка «push сам по себе не публикует»
- [ ] 3.7 Записать по каждой мутации точную команду или патч и два числа: до и после
