# Tasks — состав и подача внешних аккаунтов

**Порядок разделов 2 → 3 обязателен.** Состав делается раньше подачи: рисовать и
проверять условия использования шести марок, чтобы две выбросить, — двойная работа
(Решение 9 в `design.md`).

## 1. Тесты по спеке — отдельной сессией, до реализации

- [ ] 1.1 Начать **отдельную сессию с чистым контекстом**. На входе — только утверждённые
      `proposal.md`, `design.md`, `specs/social-accounts/spec.md` и код репозитория.
      Обсуждение, которым спека рождалась, не переносится
- [ ] 1.2 Написать тесты по каждому сценарию спеки либо явно отметить сценарий как
      закрытый ручной приёмкой с названной причиной и способом сохранения свидетельства.
      Кандидаты на ручную приёмку известны заранее: приёмка различимости Youtube и Rutube
      и приёмка условий использования марок
- [ ] 1.3 Предъявить **красный прогон** одним из двух способов, назвав его явно: отдельный
      push коммита только с тестами (упавший check-run на этом SHA) либо лог с точной
      командой и SHA. «Тесты лежат коммитом раньше» доказательством не является
- [ ] 1.4 Дефект спеки — сценарий, для которого нельзя определить объективный критерий, —
      вернуть в change через `/opsx:update`, а не переформулировать на месте под то, что
      удобно проверить

## 5. Гейты и ревью

- [ ] 5.1 Локально: в `web/` — `npm run lint`, `npm run typecheck`, `npm run build`,
      `npm test`, `npm run test:build`. Затронуты стили и раскладка, поэтому `test:build`
      обязателен
- [ ] 5.2 Локально: `npm run test:e2e:a11y` и `npm run test:e2e:smoke` — предмет правки
      живёт в подвале каждой страницы
- [ ] 5.3 Локально: `./bin/check-spec-refs`. Перед выводом «у меня зелено» — `git fetch
      --prune`: достижимость ревизий меряется по `refs/remotes/origin/*`, а они
      обновляются только выборкой
- [ ] 5.4 Обновить реестры `openspec/.spec-ref-debt` и `openspec/.spec-ref-absent`
      флагами `--write-debt` / `--write-absent` **в этом же PR** и перечислить добавленные
      строки в описании PR — по строкам реестра обоснования не видно, и «дифф покажет»
      здесь не работает
- [ ] 5.5 `./bin/openspec validate --all --strict --no-interactive`
- [ ] 5.6 **Ревью двумя независимыми исполнителями с разными уклонами** (шаги 2 и 5
      конвейера), ни один — не автор проверяемого. Ревью относится к SHA: если после него
      ветка обновлена, утверждение «это уже ревьюировали» на новую голову не переносится
- [ ] 5.7 **Реализация ведётся циклом «правка → ревью → e2e-проверки» до устранения всех
      находок** (требование владельца от 23.08.2026). Цикл закрывается не по исчерпанию
      попыток, а по отсутствию новых находок на неизменной голове; каждый круг называет,
      что проверено и что осталось
