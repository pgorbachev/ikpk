## 1. Регрессионные проверки после утверждения

- [ ] 1.1 В отдельной сессии написать проверки поведения Page и миграции по сценариям спецификации. Включить частичное изменение, вторую Page, сохранённый черновик с другой правкой и повторный запуск.
- [ ] 1.2 Написать проверки реального пути «опубликованный Page → снимок → собранный HTML» с двумя разными тестовыми номерами. Проверить текст, tel:, доступные имена и JSON-LD внутри перечисленных блоков, отдельно выставить программу без ближайшей даты, проверить реквизиты и собственный городской медцентра.
- [ ] 1.3 Проверить изменения каждого поля по отдельности, отпечаток, повторную замену, автономную сборку и отказ при неполной опубликованной записи. Проверить обе панели сведений и сохранность постороннего номера. Зафиксировать красный прогон.

## 2. CMS, переход и снимок

- [ ] 2.1 Добавить два поля Page, подписи в редакторе контактов, серверную проверку публикации и проверку фактических прав пользователя этой страницы.
- [ ] 2.2 Реализовать идемпотентное заполнение существующих версий записи и выполнить проверку обновления на копии базы. Поддержать ожидаемые изменения схемы, данных и снимка в штатном процессе первого выпуска.
- [ ] 2.3 Дополнить экспорт static_pages, тип статической страницы, закреплённый снимок и его метаданные. Проверить отказ для ошибочных живых данных и воспроизводимость обновлённого снимка.

## 3. Сборка и приёмка

- [ ] 3.1 Подключить все потребители пары к данным сборки, включая подписи ссылок, JSON-LD, обе роли в контактах и условные подсказки семинаров и программ.
- [ ] 3.2 Обновлять контактные строки разделов «Основные сведения» и «Структура и органы управления» через штатную обработку HTML.
- [ ] 3.3 Адаптировать проверки, завязанные на буквальные номера. Получить зелёный прогон, проверить релевантные гейты и отсутствие прежних номеров в проверяемых местах после замены.
