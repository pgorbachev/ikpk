## 1. Регрессионные проверки после утверждения

- [ ] 1.1 В отдельной сессии написать проверки поведения Page и миграции по сценариям спецификации. Включить частичное изменение, вторую Page, сохранённый черновик с другой правкой и повторный запуск. Проверить первый импорт в чистую CMS и повторный импорт после редакторской правки.
- [ ] 1.2 Написать проверки реального пути «опубликованный Page → снимок → собранный HTML» с двумя разными тестовыми номерами. Проверить текст, tel:, доступные имена и JSON-LD внутри перечисленных блоков, отдельно выставить программу без ближайшей даты, проверить реквизиты и собственный городской медцентра.
- [ ] 1.3 Проверить изменения каждого поля по отдельности, отпечаток, повторную замену, автономную сборку и отказ при неполной опубликованной записи. Проверить обе панели сведений и сохранность постороннего номера. Зафиксировать красный прогон.

## 2. CMS, переход и снимок

- [ ] 2.1 Добавить два поля Page, подписи в редакторе контактов, подсказку о Body, скрытие полей на других Page и серверный отказ при записи в другую Page. Проверить валидацию и права на контактах через UI и API.
