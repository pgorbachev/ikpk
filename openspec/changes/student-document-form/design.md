## Context

В `web/src/lib/navigation.ts` общий список навигации уже задаёт пункт «Оплата». Страница `oplata` уже читается из снимка CMS. Для узкого редакторского доступа есть прецедент в экранах редактирования контактов и текста книг.

## Decisions

- Хранить адрес отдельным полем существующей Page со slug `oplata`, передавать его через снимок Page. Переиспользовать существующий раздел «Страницы» и паттерн ограниченного доступа и публикации. Оформить ссылку как обычный переход. В сборке использовать имеющийся механизм CRM-ссылок для демостендов.
- При разборе адреса проверять HTTPS, точное имя хоста, отсутствие credentials и нестандартного порта, путь публичной CRM-формы и сохранять исходный query. Начальный адрес взять целиком из сообщения владельца: `https://b24-cbqwqo.bitrix24site.ru/crm_form_k5ush/?telemetry_sign=v1%3A6%3Adirect_link.2b373ae14476af8c466795c40598e242f26f55b15de21454f4c9dcb4d5acb8c4`.
- Для первой выкладки использовать штатную миграцию инициализации поля и парную выкладку CMS и сайта. Заполнять только отсутствующее значение, сохранить соседние поля и черновики. Проверить публикацию на совместимом снимке стенда. Полнота снапшота и публичная ссылка входят в приёмку переключения production. При сбое использовать штатное восстановление пары.

## Risks / Trade-offs

Поле влияет на общую навигацию, поэтому проверяем обе версии меню и права CMS. На боевом портале открываем форму только для проверки перехода, без отправки данных.
