## Purpose

Редактор управляет календарной датой статьи, а CMS создаёт адрес, пригодный для постоянной ссылки на статью.

## ADDED Requirements

### Requirement: Дата статьи выбирается с точностью до дня

Форма статьи SHALL позволять выбрать календарную дату без поля времени до и после публикации. При открытии формы создания новой статьи CMS SHALL показывать текущий календарный день Europe/Moscow как выбранное значение, доступное для изменения. Сохранённый черновик SHALL сохранять выбранный день при повторном открытии формы в другую дату. Сохранённая дата SHALL сохраняться при записи без даты, включая явное пустое значение, и при повторной публикации. Редактор SHALL иметь возможность заменить её явно выбранным днём. Если даты ещё нет, значение по умолчанию SHALL определяться по Europe/Moscow в момент первой успешной публикации. Доверенный перенос SHALL сохранять исходные даты.

#### Scenario: Форма новой статьи сразу показывает текущую дату

- **WHEN** редактор открывает форму новой статьи
- **THEN** поле даты уже содержит текущий московский день, который можно изменить или очистить

#### Scenario: Выбранный день сохраняется в черновике

- **WHEN** редактор сохраняет черновик с автоматически выбранным или вручную изменённым днём и открывает его на следующий московский день
- **THEN** форма показывает ранее сохранённый день

#### Scenario: Публикация черновика без даты

- **WHEN** черновик сохранён без даты и впервые успешно опубликован в другой календарный день
- **THEN** CMS сохраняет московский день публикации и передаёт его сайту как дату статьи

#### Scenario: Попытка публикации не удалась

- **WHEN** первая попытка публикации без даты завершилась ошибкой, а повторная попытка удалась на следующий московский день
- **THEN** дата статьи соответствует дню успешной попытки

#### Scenario: Очистка сохраняет записанную дату

- **WHEN** редактор очищает дату в ранее сохранённом черновике или ранее опубликованной статье и сохраняет либо публикует запись
- **THEN** CMS сохраняет ранее записанную дату, которую форма показывает при следующем открытии

#### Scenario: Редактор выбирает дату

- **WHEN** редактор выбирает календарный день во время первой публикации или при правке ранее опубликованной статьи
- **THEN** форма принимает день без настройки времени, а успешная публикация передаёт выбранный день сайту

#### Scenario: Повторная публикация сохраняет день

- **WHEN** статья переиздаётся, в том числе после снятия с публикации, без явного выбора новой даты
- **THEN** сайт получает ранее сохранённый календарный день

### Requirement: CMS управляет адресом статьи

CMS SHALL генерировать уникальный безопасный для URL slug при первом успешном сохранении непустого заголовка, если slug ещё не задан. Поле slug в редакторской форме SHALL быть доступно только для чтения. Через обычный API изменение slug вручную SHALL быть запрещено. CMS SHALL сохранять существующий slug при последующих изменениях черновика, публикации, переименовании, снятии с публикации и повторной публикации. Это правило SHALL сохранять существующие и доверенно импортированные адреса.

#### Scenario: Первое сохранение заголовка

- **WHEN** редактор впервые успешно сохраняет непустой заголовок статьи без slug
- **THEN** CMS вычисляет slug из заголовка и показывает результат только для чтения

#### Scenario: Переименование черновика

- **WHEN** редактор меняет заголовок черновика со сформированным slug до первой публикации
- **THEN** CMS сохраняет ранее сформированный slug и показывает его только для чтения

#### Scenario: Заголовки совпадают

- **WHEN** несколько статей публикуются с одинаковым заголовком
- **THEN** у каждой свой безопасный slug и адрес уже существующей статьи не меняется

#### Scenario: Переименование опубликованной статьи

- **WHEN** редактор меняет заголовок ранее опубликованной статьи и публикует её снова, в том числе после снятия с публикации
- **THEN** постоянная ссылка статьи сохраняется

#### Scenario: Попытка подставить другой slug

- **WHEN** обычный клиент пытается задать собственное значение slug через API
- **THEN** переданное значение не меняет адрес статьи

#### Scenario: Повторный доверенный перенос

- **WHEN** доверенный перенос создаёт статью с исходным slug и датой, а затем повторяет импорт
- **THEN** дата и slug соответствуют исходным значениям
