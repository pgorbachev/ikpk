## 2. Тесты по спеке (отдельная сессия, до реализации)

- [ ] 2.1 Написать проверку обнаружения: изменение величины в стилях покрытого блока даёт
      неуспех; неизменный код даёт успех
- [ ] 2.2 Написать проверки независимости от даты: один и тот же код при двух значениях
      текущей даты, различающихся годом, даёт одинаковый результат
- [ ] 2.3 Написать проверки различения «расхождений нет» и «сравнение не выполнено»:
      эталон отсутствует — неуспех **и эталон не создан**; блок не найден — неуспех с
      именем блока; среда не поднялась — неуспех, а не пропуск
- [ ] 2.4 Написать проверку принадлежности эталона окружению: доступен только эталон из
      другого окружения — неуспех, как при отсутствующем
- [ ] 2.5 Написать проверки порога покрытия: покрытие сократилось — неуспех с обоими
      числами; покрытие расширено вместе с порогом — успех
- [ ] 2.6 Написать проверку содержания сообщения: имя блока, адрес страницы, величина
      расхождения, сохранённое свидетельство
- [ ] 2.7 Написать проверки вхождения в контур: проверка присутствует в workflow, от
      которого зависит публикация, и в обязательных проверках ветки. Для разбора workflow
      использовать существующий `web/tests/helpers/workflows.ts`, а не писать свой парсер
- [ ] 2.8 Отметить явной записью сценарии, для которых автоматической проверки не будет, с
      названной причиной и способом ручной проверки. Кандидат — фактический состав
      обязательных проверок ветки
- [ ] 2.9 Предъявить красный прогон: отдельный push коммита **только с тестами** либо лог
      с точной командой и SHA. «Тесты лежат коммитом раньше» доказательством не является

## 6. Негативные проверки

- [ ] 6.1 Нарушить раскладку покрытого блока (правкой стиля) в **своём worktree**, при
      закоммиченной реализации; убедиться, что покраснел **именно этот** гейт — судить по
      имени покрасневшей проверки, а не по цвету прогона
- [ ] 6.2 Записать мутацию воспроизводимо: точная команда или патч плюс два числа —
      величина расхождения до и после. Пересказ не годится
- [ ] 6.3 Проверить полноту мутации измерением: зелёный прогон после мутации означает либо
      декоративный гейт, либо что мутация не убрала предмет — различить обязательно
- [ ] 6.4 Подтвердить восстановление постусловием: пустой `git status --porcelain` и
      отсутствие diff относительно SHA реализации; для мутации сгенерированного вывода —
      контрольная сумма дерева (`find . -type f -exec shasum {} + | sort | shasum`) либо
      пересборка
- [ ] 6.5 Негативно проверить порог покрытия: убрать один блок из покрытия, не трогая
      порог, — убедиться, что гейт краснеет именно на этом, с обоими числами
- [ ] 6.6 Негативно проверить различение состояний: удалить эталон одного блока и убедиться,
      что прогон красный и эталон не создан
- [ ] 6.7 Удалить временный worktree после проверок (`git worktree remove`)
