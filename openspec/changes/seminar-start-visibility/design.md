## Context

Сайт строит статический HTML из снимка CMS. `startAt`/`endAt` представляют календарные дни; старые datetime значения сериализуют день, а не подтверждённый час. Опубликованный HTML сам по себе не обновляется в полночь.

## Goals / Non-Goals

**Goals:** использовать дату начала как единственный обязательный источник границы, убрать вчерашние и начавшиеся сегодня проведения со всех датированных предложений, обновлять открытую страницу без публикации.

**Non-Goals:** определение фактического часа начала, изменение полей CMS или импорта, удаление исторических страниц, изменение уже созданных платежей.

## Decisions

1. **Граница.** Нормализовать `startAt` к публичному календарному дню существующей функцией `calendarDay`; для каждого дня использовать его начало в `Europe/Moscow`. Датированная запись видима строго до этого момента. `endAt`, час в свободном тексте и локальная зона браузера на решение не влияют. Без корректного `startAt` запись не становится предложением.
2. **Статический HTML.** Сборка использует опорную дату снимка для воспроизводимости, а браузер применяет текущие часы при загрузке. Клиент получает все потенциально будущие записи, чтобы ведущий анонс мог перейти к следующему.
3. **Открытая вкладка.** Один скрипт пересчитывает все датированные предложения на ближайшей границе 00:00 МСК, при `visibilitychange` и фокусе. Фильтр расписания получает готовую видимость и обновляет месяцы, счётчики и пагинацию.
4. **История.** Страница описания семинара и карточка курса без будущих дат остаются доступными; предложение записаться на начавшееся проведение скрывается. Уже созданная платёжная попытка продолжает работать по существующему контракту.

## Risks / Trade-offs

- Без JavaScript старый статический HTML может оставаться устаревшим после перехода дня; серверная динамика вне этого изменения.
- Неверные часы устройства влияют на браузерную видимость; опубликованный снимок определяет начальный HTML.
- Новый контент по-прежнему требует публикации снимка CMS; скрытие уже известных записей не требует новой публикации.

## Verification

Регрессионный тест: проведение №389 за 22 октября показано до 00:00 МСК и скрыто начиная с этой границы; 23 октября оно не становится «ближайшим». Проверить многодневные и несколько сеансов одного курса, открытый браузер, возврат после сна, фильтры месяцев и новую оплату. Проверить сборку и независимое ревью после изменения.
