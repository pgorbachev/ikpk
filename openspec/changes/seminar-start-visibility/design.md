## Context

Сайт строит статический HTML из снимка CMS. `startAt`/`endAt` представляют календарные дни; старые datetime значения сериализуют день, а не подтверждённый час. Примечание `additionalText` вида «Начало в HH:MM» задаёт час начала по Москве. Опубликованный HTML сам по себе не обновляется при наступлении этого момента.

## Goals / Non-Goals

**Goals:** использовать дату начала и явно указанный час как границу, убрать начавшиеся проведения со всех датированных предложений, обновлять открытую страницу без публикации.

**Non-Goals:** угадывание часа из произвольного текста, изменение полей CMS или импорта, удаление исторических страниц, изменение уже созданных платежей.

## Decisions

1. **Граница.** Нормализовать `startAt` к публичному календарному дню существующей функцией `calendarDay`. Однозначное примечание «Начало в HH:MM» (или HH-MM) задаёт московский час этого дня; без него используется 00:00 МСК. Парсер принимает только эту фразу и корректное время; `endAt` и локальная зона браузера не влияют. Без корректного `startAt` запись не становится предложением.
2. **Статический HTML.** Сборка использует момент сборки, а не опорную дату снимка: вчерашняя запись не попадёт в новый HTML даже при старом снимке. Контролируемые тестовые сборки задают момент явно. Браузер применяет текущие часы при загрузке и обновляет уже опубликованную страницу.
3. **Открытая вкладка.** Один скрипт пересчитывает все датированные предложения на ближайшей границе начала, при `visibilitychange` и фокусе. Фильтр расписания получает готовую видимость и обновляет месяцы, счётчики и пагинацию. Исходная дата и примечание доступны браузеру для общего вычислителя границы.
4. **История.** Страница описания семинара и карточка курса без будущих дат остаются доступными; предложение записаться на начавшееся проведение скрывается. Уже созданная платёжная попытка продолжает работать по существующему контракту.

## Risks / Trade-offs

- Без JavaScript HTML, опубликованный до перехода дня, может оставаться устаревшим до следующей сборки; новая сборка отбирает записи по собственному времени.
- Неверные часы устройства влияют на браузерную видимость; момент сборки определяет начальный HTML.
- Новый контент по-прежнему требует публикации снимка CMS; скрытие уже известных записей не требует новой публикации.

## Verification

Регрессионный тест: проведение с примечанием «Начало в 18:00» показано до 18:00 МСК и скрыто начиная с этой границы; запись №389 с примечанием «Начало в 19:00 (московское время)» использует 19:00 МСК. Запись без часа исчезает в 00:00 МСК. Проверить многодневные и несколько сеансов одного курса, открытую страницу, возврат после сна и фильтры месяцев.
