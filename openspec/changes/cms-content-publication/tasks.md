## 4. Журнал происхождения и ревизии

- [ ] 4.1 Неизменяемый журнал: запись на событие изменения контента — номер из возрастающей
      последовательности, отпечаток контента, номер предшествующей записи, маркер события; плюс
      высшая достигнутая отметка, не уменьшающаяся при операциях с базой
- [ ] 4.2 Ревизия контента снимка как **производная** величина, а не номер последней записи:
      новое содержимое и ручной возврат текста → номер новой записи; опознанное восстановление
      базы → номер первой записи с тем же отпечатком (ниже отметки)
- [ ] 4.3 Негативная проверка на этот случай: после восстановления базы гейт публикации обязан
      покраснеть; прежняя редакция делала это недостижимым
- [ ] 4.4 Совпадение отпечатка без маркера требует подтверждения человеком
- [ ] 4.5 Журнал не переписывается; попытка изменить или удалить запись отклоняется
- [ ] 4.6 Сохранность журнала входит в резервное копирование; недоступный или пустой журнал при
      непустой истории публикаций останавливает публикацию и требует подтверждения
- [ ] 4.7 Маркер восстановления ставится процедурой восстановления базы (действие вне системы
      управления); забытый маркер даёт случай «совпадение без маркера»
- [ ] 4.8 Атомарность присвоения номера записи при конкурентных прогонах
- [ ] 4.9 Стартовые значения: отметка равна нулю до первой записи, первая запись — маркер
      «первичный перенос»

## 8. Триггеры публикации

- [ ] 8.1 Аутентифицированный запрос из системы управления запускает существующий обязательный
      прогон на вершине основной ветки
- [ ] 8.2 Перечень событий: публикация, изменение опубликованной записи, снятие с публикации,
      удаление, замена медиафайла опубликованного контента
- [ ] 8.3 Параметры запроса не влияют на собираемое; неаутентифицированный запрос игнорируется
- [ ] 8.4 Очередь на один ожидающий прогон без отмены текущего; серия правок сходится к
      публикации последнего состояния
- [ ] 8.5 Сверка при потерянном оповещении: расхождение опубликованного состояния с контентом
      обнаруживается без участия оповещения
- [ ] 8.6 Календарный публикующий прогон: названное максимальное отставание, явно заданный
      часовой пояс, независимость от настроек машины

- [ ] 9.1 Для каждого нового гейта негативная проверка в своём worktree: вернуть дефект,

      прогона)
- [ ] 9.2 Записать каждую мутацию воспроизводимо: точная команда или патч плюс два числа — до и

- [ ] 9.3 Подтвердить восстановление постусловием под предмет мутации: для отслеживаемых файлов

      вывода — контрольная сумма дерева по относительным путям с сортировкой

- [ ] 9.5 Сверить ответы гейтов над одним предметом (достижимость страниц, целостность каталога,
