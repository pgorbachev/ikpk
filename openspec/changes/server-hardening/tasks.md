# Задачи

Change в состоянии `queued`. Задачи ниже — свёрнутое backlog-описание, а не план к исполнению:
детализация делается при подъёме в `active`, после сверки спеки с `origin/main`.

## 1. Предусловия подъёма

- [ ] 1.1 `server-provisioning` заархивирован, требования переехали в `openspec/specs/`.
- [ ] 1.2 Стенд работает, обновление через CMS проверено.
- [ ] 1.3 Спека сверена с `origin/main` заново: за время в очереди могли появиться основные
      спеки, которым дельта противоречит, — строгая валидация этого не видит.
- [ ] 1.4 Проверена применимость дельты применением в одноразовом worktree, а не только
      валидацией.

## 2. Права выкладки

- [ ] 2.1 Собрать фактический перечень привилегированных действий выкладки по коду
      `scripts/deploy-web.sh`, а не по её описанию.
- [ ] 2.2 Правка `scripts/deploy-web.sh` под непривилегированную учётную запись.
- [ ] 2.3 Поимённый перечень запрещённых на запись предметов, включая собственные ключи доступа.
- [ ] 2.4 Судьба нынешнего root-пути: закрыть либо оставить с названной причиной и владельцем.

## 3. Сетевые ограничения

- [ ] 3.1 Запись о способе доступа помимо сети в объявленном состоянии — предусловие.
- [ ] 3.2 Подтверждение доступности каждого объявленного открытым порта до закрепления правил.
- [ ] 3.3 Автоматический откат при неподтверждённом соединении.

## 4. Двусторонняя сходимость

- [ ] 4.1 Третье значение политики — `converge` — в объявленном состоянии.
- [ ] 4.2 Снятие учётной записи только после резервной копии её домашнего каталога.

## 5. Доверенный механизм

- [ ] 5.1 Назвать машину и сверить с машиной активного пути публикации.
- [ ] 5.2 Владелец и режим механизма и его учётных данных; недоступность на запись проверяемой
      учётной записи.

## 6. Один артефакт на стенд и прод

- [ ] 6.1 Свойства, значением не выражаемые, — поимённо с решением по каждому: TLS, домен,
      закрытость стенда от индексации, доступ заказчика.
- [ ] 6.2 Сверка объявленных состояний двух окружений, а не двух живых серверов.

## 7. Незакрытые находки прежних кругов ревью

Перенесены вместе с требованиями и не потеряны:

- [ ] 7.1 Требования, сформулированные про объём change, а не про поведение продукта
      («SHALL NOT вводиться этим change») — после архивирования такие фразы означают не то, что
      задумано.
- [ ] 7.2 Две проверки над одним корпусом с разными перечнями и разными правилами счёта.
- [ ] 7.3 Сценарии требования о доверенном механизме непроверяемы на одноразовом контейнере —
      отметить цель проверки явно.
