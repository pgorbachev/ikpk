## 1. Красные тесты до кода — отдельная сессия с чистым контекстом

Порядок из `AGENTS.md`: после утверждения спеки пишутся **только** тесты, в отдельной
сессии, и предъявляется красный прогон. Ниже — сценарии спеки, у каждого должна быть
проверка либо явная отметка, почему её нет. Мутации для негативной проверки перечислены в
`design.md`, раздел «Негативная проверка: что именно ломать» — там указано, **какой по имени**
тест обязан покраснеть, а не только что прогон краснеет.

- [ ] 1.1 Проверки текста конфигурации боевой раздачи: класс состояния и значение `no-store`
  дословно; правило класса присутствует и при отсутствующем содержимом; отсутствие `public`
  в этом значении
- [ ] 1.2 Проверка «правило раздачи без объявленного класса»: разбор перечисляет **все**
  правила и падает на неотнесённом. Признак общий, не перечень известных адресов
- [ ] 1.3 Проверка общего набора заголовков: находит в тексте все правила со своим
  `add_header` и требует набор в каждом. Отдельным утверждением — правило карты сайта
- [ ] 1.4 Проверка запрета: директивы `Strict-Transport-Security` в конфигурации нет
- [ ] 1.5 Проверки правил схемы и хоста: наличие, сохранение пути и строки запроса, путь
  ACME-проверки не под перенаправлением, длина цепочки не больше двух шагов
- [ ] 1.6 Проверка отказа на неизвестное имя хоста
- [ ] 1.7 Проверки генератора: строка карты, не отнесённая ни к одному механизму, роняет его
  и конфигурация не записывается; отчёт называет числа по механизмам и исключениям; сумма
  равна числу строк карты с кодом 301
- [ ] 1.8 Поведенческие проверки выкладки (в `web/tests/deploy-checks.test.ts` рядом с
  существующими): отказ при несоответствии режима назначению **до** загрузки; отказ при
  необъявленном назначении; отказ при расхождении конфигурации на хосте; отсутствие
  параметра, отключающего проверку подлинности хоста
- [ ] 1.9 Проверки монитора: значение читается с раздачи; недоступность или нечитаемость —
  непройденная проверка, а не «расхождений нет»; ручное переключение релиза на предыдущий
  даёт расхождение
- [ ] 1.10 Проверка «путей публикации ровно один»: два пути — отказ, ноль путей — тоже отказ
- [ ] 1.11 Проверки роли артефакта боевой раздачи: роль `ci`, ноль форм, нет объявленного
  эндпоинта, при этом режим форм заявки боевой (то есть значения переключателей независимы)
- [ ] 1.12 Проверка атомарности переключения релиза и наличия предыдущего релиза
- [ ] 1.13 Отметить явно сценарии, у которых автоматической проверки нет, с причиной и
  способом ручной приёмки: живое свидетельство TLS и живой отказ на неизвестное имя требуют
  ответа сервера, о котором сборка не знает
- [ ] 1.14 Предъявить красный прогон: отдельный push коммита **только с тестами** (упавший
  check-run на этом SHA) либо лог с точной командой и SHA. «Тесты лежат коммитом раньше»
  доказательством не является
