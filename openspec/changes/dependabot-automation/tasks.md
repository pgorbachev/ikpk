- [ ] 2.3 Написать проверки инварианта платформенных записей: дедупликация вложенной

- [ ] 2.5 Написать проверки требования о вершине `main`: промежуточный коммит не

- [ ] 2.6 Отметить явной записью те сценарии, для которых автоматической проверки не

- [ ] 6.2 Внести `Scripts unit tests` в обязательные: сейчас job живёт внутри `Tests`,

- [ ] 6.3 Сначала проверить дешёвый механизм: после слияния PR автоматически просить
      Dependabot пересобрать оставшиеся PR разрешённого класса встроенным токеном.
      Предъявить результат эксперимента — продвинулась ли серия без вмешательства
- [ ] 6.4 Если 6.3 не подтвердилась — включить очередь слияния и завести субъект с правом
      на pull request: GitHub App, ограниченное этим репозиторием, а не персональный

- [ ] 6.5 Убедиться, что учётные данные очереди недоступны из контекста, исполняющего код

- [ ] 6.6 Проверить, что очередь слияния доступна для этого репозитория при текущем плане

- [ ] 6.7 **Негативная проверка продвижения серии:** подготовить два PR разрешённого
      класса, слить первый, убедиться, что второй сливается сам без ручных действий.
      Записать время между слияниями — именно этот случай ломался на `strict`
- [ ] 6.8 Проверить негативно: PR разрешённого класса с падающим `Scripts unit tests` не
