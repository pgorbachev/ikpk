## 7. Авто-слияние (последним, после доказанных гейтов)

- [ ] 7.1 Реализовать workflow, помечающий PR к слиянию, в привилегированном контексте без
      checkout кода PR и без установки зависимостей
- [ ] 7.2 Ограничить права шага чтением содержимого и операциями с pull request
- [ ] 7.3 Реализовать классификацию по метаданным Dependabot: разрешены `semver-patch` и
      `semver-minor` для прямых зависимостей разработки и любые обновления
      `github-actions`
- [ ] 7.4 Реализовать безусловный отказ для мажоров и для runtime-зависимостей `web`,
      включая случай смешанного группового PR
- [ ] 7.5 Проверить на живом PR каждого класса: патч зависимости разработки — слился;
      мажор — остался открытым; runtime-зависимость `web` — осталась открытой
- [ ] 7.6 Проверить, что при падении обязательной проверки помеченный PR не сливается
- [ ] 7.7 Решить, что делать с отменёнными прогонами при серии слияний: `Tests` объявляет
      `concurrency: cancel-in-progress`, поэтому при быстрой череде merge промежуточные
      прогоны отменяются, а деплой на них пропускается — публикуется только вершина.
      Наблюдалось 09.08.2026: из шести прогонов `Tests` на `main` четыре отменены, деплой
      на них `skipped`, плюс один деплой упал на защите «проверенный коммит всё ещё
      вершина». Само по себе это корректно, но при авто-слиянии станет нормой, и надо
      явно решить, считается ли непубликация промежуточного коммита нормой или требует
      сигнала
