## 1. Правила редактора

- [x] 1.1 Сервер задаёт `name` проведения и не принимает его из редакторского запроса.
- [x] 1.2 Карточка семинара не забирает чужое проведение; перенос только из формы проведения.
- [x] 1.3 Публичный заголовок расписания читает опубликованное название семинара.
- [x] 1.4 Окончание раньше начала блокирует публикацию; неполный черновик сохраняется.
- [x] 1.5 Пустое название семинара не получает slug `seminar`; заданный slug не пересчитывается.
- [x] 1.6 Запрос Content API с токеном полного доступа обрабатывается как доверенный перенос
      (D5); запрос панели и токен любого другого типа — нет.
- [x] 1.7 Доверенный перенос сохраняет slug нового семинара с названием; пустой — из
      названия; занятый или негодный — отказ с адресом; при обновлении переданный slug не
      сохраняется. Недоверенный запрос slug не задаёт ни при создании, ни при обновлении.
- [x] 1.8 Перенос (`scripts/import.ts`) находит существующую запись любого типа по
      `legacy_id` и среди неопубликованных, обновляет черновик и не публикует запись без
      опубликованной версии. Поиск семинара для связи проведения (по slug) — тоже с
      черновиками. Статус публикации перенос не меняет: у проведения неопубликованного
      семинара опубликованная версия нетронута, данные идут в черновик (решение владельца
      08.10.2026).
      Сценарии, которые проходят и на текущем коде (редактор, настраиваемый токен, перенос без
      адреса и без названия, повторный перенос не меняет адрес), — охрана регресса; новое
      поведение доказывают сценарии, падающие до реализации.

## 2. Формы и роль

- [x] 2.1 Русские подписи, скрытое `name`, подпись даты и города в списке проведений.
- [x] 2.2 Роль администратора контента без прав супер-администратора.
- [ ] 2.3 Пройти сценарий на стенде под этой ролью: семинар, два проведения, чужое проведение.

## 3. Приёмка

- [ ] 3.1 Независимая приёмка реализации.
- [ ] 3.2 Обновление сайта из CMS — change `site-refresh-from-cms`. Живой сценарий на стенде ещё не пройден.
- [ ] 3.3 Повторный перенос живых данных на стенд с семинаром, которого на стенде ещё нет
      (новый на прежнем сайте, либо один из трёх из D5, удалённый со стенда перед прогоном):
      после кнопки его страница отвечает 200 по адресу прежнего сайта, без ручной правки.
