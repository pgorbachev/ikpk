`teachers` остаётся JSON. PR #186 не слит и не копируется.

`content-manager` `generateUIDField` подставляет `contentType.modelName`, если
`targetField` пуст. Пустое название обязано получить пустой slug, а не эту заглушку.
Название «Семинар» по-прежнему может иметь адрес `seminar`: общего запрета нет.

## Decisions

### D1. Штатный Content Manager

Формы, связь и модальное создание — штатные. `admin_label` — служебная подпись
«дата · город» для списка и связи. Это не публичный заголовок. `name` проведения
скрыто и не редактируется. Преподаватели проведения (JSON) скрыты до отдельной
поставки связей; преподаватели самого семинара остаются обычной связью.

### D2. Имя проведения и публичный заголовок

Сервер игнорирует `name` из редакторского запроса. Пустое имя заполняется названием
семинара при создании и при первом присоединении. Уже заданное имя, включая импорт,
сохраняется, пока семинар у проведения явно не сменён в его собственной форме.
Доверенный импорт сохраняет исходное имя через серверный контекст, не через параметр запроса.

Публичные заголовок, поиск и alt расписания читают `seminar.name` опубликованного снимка.
Черновик переименования в снимок не входит и на сайт не попадает.

### D3. Связь

Повторная отправка своей связи допустима. Свободное проведение присоединяется.
Проведение другого семинара отклоняется и через карточку, и прямым запросом к обратной связи.
Перенос выполняется только полем «Семинар» в форме проведения.

Создание из карточки по-прежнему сначала пишет дочернюю запись, затем связывает родителя.
Черновик без семинара и без имени допустим. Публикация без семинара или с безымянным
семинаром отклоняется. Обязательность публикации не ослабляется ради модального окна.

### D4. Даты, slug, роль

Окончание раньше начала отклоняет публикацию. Неполная дата черновик не блокирует.
Пустое название нового семинара не создаёт slug. После заполнения названия slug
создаётся и дальше не меняется при переименовании. Роль `content-admin` не является
супер-администратором. Учётная запись создаётся только если заданы
`CONTENT_ADMIN_EMAIL` и `CONTENT_ADMIN_PASSWORD`; пароль в журнал не пишется.

### D5. Что такое доверенный перенос в рабочем контуре

Найдено 07.10.2026 при обновлении стенда данными живого ikpk.su: три новых семинара
получили адрес из названия, прежние адреса отдавали 404:

| адрес прежнего сайта (slug) | адрес из названия |
|---|---|
| `osoznanie-i-upravlenie-svoej-zhiznyu` | `avtorskij-seminar-praktikum-osoznanie-i-upravlenie-svoej-zhiznyu` |
| `funkcionalnaya-biohimiya-zabolevanij-zheludochno-kishechnogo-trakta` | `funkczionalnaya-biohimiya-zabolevanij-zheludochno-kishechnogo-trakta` |
| `vebinar-vozvrashenie` | `mezhseminarskaya-vstrecha-vebinar-vozvrashhenie` |

Причина двойная. Правило slug (D4) не различало редактора
и перенос. А серверный контекст доверенного импорта (`runTrustedImport`) включали только
тесты: настоящий перенос `scripts/import.ts` идёт в Content API с токеном, и сервер
считал его обычным редактором. Обещание D2 «доверенный импорт сохраняет исходное имя» к
рабочему переносу не относилось.

«Доверенный импорт» в D2 и «доверенный перенос» здесь и в спецификации — одно и то же.

Решение: доверенным считается запрос Content API с токеном **полного доступа**. Признак —
учётные данные запроса, которые сервер проверил сам, поэтому подделать его телом нельзя.
В Strapi 5.51.2 их видно и внутри document middleware: `strapi.requestContext.get()`
отдаёт `ctx.state.auth`, у токена Content API стратегия называется `content-api-token`
(`@strapi/admin/dist/server/server/src/strategies/content-api-token.js`), а тип токена —
`credentials.type`; доверие даёт только `full-access`. Токен только для чтения (съём
снимка, `cms/src/seminar-management/capture-token.ts`) писать не может вовсе, поэтому
отдельного правила для него не нужно; токен настраиваемого типа доверенным не считается.
Расширения прав это не даёт: владелец такого токена и без того может создать и изменить
любую запись. Запросы панели (JWT администратора, любая роль, включая `content-admin`)
и токен только для чтения (съём снимка) доверенными не бывают.

Переданный slug сохраняется только при **создании** семинара. Занятый или негодный slug —
отказ, а не суффикс `-1`: перенос обязан сохранить адрес прежнего сайта, и тихо
изменённый адрес обнаружится только после смены домена. Пустой slug создаётся из
названия. При обновлении существующего семинара переданный slug не сохраняется, дальше
действуют правила редактора (D4). Принятый край: семинар, впервые созданный переносом
без названия, получает пустой slug, и когда следующий прогон пришлёт название, адрес
создастся из названия, а не из прежнего сайта. Рабочий перенос всегда шлёт название, так
что случай теоретический; он назван, а не закрыт. Перенос обновляет
записи по `legacy_id` и шлёт `slug` и в `PUT` (`scripts/import.ts`), а адрес опубликованной
страницы не должен двигаться от повторного прогона. Обратная сторона — уже неверно
созданный адрес повторный перенос не починит: его правят данными, как три адреса стенда.

Правило о том, что панель адрес не задаёт, временное: change
`cms-content-authoring-and-migration` вводит правку адреса редактором с историей адресов,
и его поставка это правило заменяет. До неё адрес в панели не редактируется.

## Risks

- Перенос ищет существующую запись по `legacy_id` только среди опубликованных: REST без
  `status` отдаёт опубликованное. Снятый с публикации семинар он не найдёт, пойдёт в
  создание и упрётся в правило занятого адреса. Отказ здесь верен — тихий дубль был бы
  хуже, — но повторяемость переноса ломается; поиск с учётом черновиков — требование
  повторного переноса и задача 1.8. `PUT` без `status` в Strapi 5 пишет опубликованную
  версию, то есть найденный черновик был бы тихо опубликован; поэтому требование прямо
  запрещает переносу публиковать запись без опубликованной версии. Поиск в
  `scripts/import.ts` общий для всех типов, поэтому правило распространяется на все
  переносимые типы, а не только на семинары.
- Опубликованное проведение, чей семинар редактор снял с публикации: решение владельца
  08.10.2026 — опубликованная версия остаётся нетронутой, перенос обновляет только
  черновик. Перенос вообще не меняет статус публикации записей: ни публикует, ни снимает.

- Публичный заголовок импортированных проведений с особым `name` изменится на название
  семинара. Исходные строки в CMS остаются.
- Кнопки «Обновить сайт» в этой поставке нет.
- Назначение преподавателя на проведение скрыто, пока не принята схема authoring.

## Migration

Имена импорта не переписываются. Пустой `admin_label` заполняется при запуске
из даты и города уже существующих строк; непустая подпись не затирается.
Существующие slug семинаров не пересчитываются. Три семинара стенда, получившие адрес
из названия 07.10.2026, исправлены на стенде правкой данных; повторный перенос после
этой поставки такой правки не требует.
