## Context

Парный host helper и CMS worker собирают staging194 одной командой `build:demo193`.
Текущие указатели, журнал парной публикации и состояние CMS refresh уже позволяют
проверить подлинность релиза перед housekeeping.

## Goals / Non-Goals

Использовать существующие снимки, папку сборки, подтверждение по digest, переключение
указателя и очистку. Вариант применяется к парной публикации и кнопке CMS на 194.
Production, обычная demo-сборка и отдельная операция static-main сохраняют свою конфигурацию.

## Decisions

1. Оба входа передают явный аргумент существующей команде сборки. Runner и проверка
   Astro допускают аргумент при конфигурации demo193 для фиксированного origin 194,
   отключённой оплате и заявленном отсутствии чата. Существующие prebuild, Pagefind,
   каталог вывода и проверки происхождения продолжают работать.
2. Сохранить `DEMO_FORMS=stub` и применять исключение только там, где компонент
   получает ссылку записи из конкретного проведения в снимке CMS. Использовать тот же
   конвейер нормализации и проверки URL, что в обычной сборке. Общая подмена ссылок
   остаётся для остальных форм и редакционного HTML. Единый флаг форм также управляет
   аналитикой и robots, поэтому снять его для всей сборки нельзя.
3. Использовать одну проверку статического HTML и снимка для двух входов. Парная
   публикация включает её в существующую браузерную приёмку. CMS worker выполняет
   её автоматически над готовым кандидатом перед сменой указателя. Для каждой
   пары «страница и проведение» сравнить ожидаемые CTA с фактическими. Проверка
   читает HTML локально. Действующая проверка стенда продолжает применяться к
   прочим ссылкам. Перед переключением подтвердить идентичность снимка и digest
   проверенного дерева существующими средствами путей публикации.
4. Оставить journal, release metadata и CMS refresh state под управлением действующих
   путей публикации. После парной операции проверить соответствие активного релиза
   журналу, после CMS refresh проверить соответствие сохранённому состоянию worker.

## Risks / Trade-offs

Адреса действующих форм могут вести в CRM. Приёмка сравнивает адреса и состояние HTML,
сохраняя внешние запросы к этим адресам заблокированными. Два временных адреса остаются
в CMS до редакторской замены. Проверка до смены указателя оставляет прежний активный релиз при любой ошибке сверки.

## Migration Plan

Собрать из допущенного источника, провести существующую парную публикацию на 194 и сверить
вывод. Затем выполнить один штатный CMS refresh, повторить сверку и запустить штатную
проверку housekeeping. При сбое использовать rollback соответствующего пути.
