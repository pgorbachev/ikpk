## 3. Механизм продвижения последовательности

- [x] 3.1 Способ первый: после слияния PR просить Dependabot пересобрать оставшиеся PR
      разрешённого класса — командой-комментарием от встроенного токена.
      **Закрыто с отрицательным, но не блокирующим результатом (evidence §17).** Проверено
      живьём трижды подряд (#174, #176, #175, все слиты нативным marker'ом
      `enabled_by: github-actions[bot]`): `dependabot-rebase.yml`
      (`pull_request_target: types: [closed]`) не дал НИ ОДНОГО прогона ни на одном из трёх
      закрытий, хотя workflow активен и GitHub зафиксировал настоящие события
      `closed`/`merged` в таймлайне PR. То есть триггер-событие для этого способа не
      приходит вовсе при слиянии через нативный `enablePullRequestAutoMerge` — не «команда
      не распознана», а раньше: сигнал, которым команда должна была отправиться, ни разу
      не сработал. Способ 1 в его спроектированном виде не подтверждён работающим.
      **Задача закрывается не потому, что способ работает, а потому что цель, ради которой
