## 3. Схема CMS

- [ ] 3.1 Поле порядка у семинара, программы, преподавателя; пустое — в конец, вторичная
      сортировка по идентификатору
- [ ] 3.2 Удалить хранимое поле статуса из схемы семинара
- [ ] 3.3 Множественное медиа-поле у семинара, программы, института
- [ ] 3.4 Три поля секций семинара с именами по смыслу (учебный план, режим обучения,
      рекомендации); поля произвольного содержимого о документах не создавать
- [ ] 3.5 Документы: состояние сведений из трёх значений плюс повторяемый набор записей
      {документ, выдающее лицо, условие, основание}; условие структурно и покрывает исходное
      образование и результат обучения
- [ ] 3.6 Связь преподавателя с институтом; адрес его страницы выводится из связи
- [ ] 3.7 Схема события расписания под состав данных; институт и программа не дублируются
- [ ] 3.8 Убрать цену и длительность из схемы семинара
- [ ] 3.9 Легаси-поля необязательны во всех типах
- [ ] 3.10 HTML-поле тела с визуальным редактором вместо markdown; плагин подтвердить проверкой:
      текущая версия Strapi, без внешних CDN, сохраняет таблицы, разметка внутри принятого
      allowlist
- [ ] 3.11 Грамматика идентификатора и области уникальности по типам: институт и статическая
      страница — среди сегментов первого уровня вместе с маршрутами сборки, программа — в
      институте, семинар — в программе, преподаватель — в институте, статья — в `/statyi`,
      видео-плейлист — в `/video`
- [ ] 3.12 История адресов: постоянное хранение, запрет занять адрес из истории любой записи
- [ ] 3.13 Обязательность полей по типам с отказом на публикации записи
- [ ] 3.14 Роли: редактор — только контент; проверить отказ на изменении ролей и структуры типов

## 4. Адреса и маршруты

- [ ] 4.1 Вычисление адреса записи из связей
- [ ] 4.2 Порождаемый маршрут для новых статических страниц; существующие страницы продолжают
      раздаваться по своим адресам
- [ ] 4.3 Смена идентификатора или связи не роняет сборку и порождает постоянное перенаправление
- [ ] 4.4 Перенаправление из истории ведёт на текущий адрес одним переходом; цепочки не
      накапливаются
- [ ] 4.5 Переименование института или программы порождает перенаправления для всех записей ниже
      по иерархии
- [ ] 4.6 Генерация правил перенаправления выводится из истории адресов; правил с несуществующей
      целью нет
- [ ] 4.7 Снятая с публикации запись исчезает из списков, расписания и карты сайта; ссылок и
      перенаправлений в никуда не остаётся

## 5. Медиа

- [ ] 5.1 Файлы из системы управления передаются существующему шагу производных вместе с
      `media-originals/`; манифест по объединённому набору
- [ ] 5.2 Неуспех сборки при используемом изображении без производных или без известных размеров
- [ ] 5.3 Проверка, что медиа системы управления отдаётся со статических адресов, а внешние
      ссылки в содержимом сохраняются
- [ ] 5.4 Ограничения загрузки: только растровые форматы, отказ векторной графике и документам,
      предел размера с указанием предела
- [ ] 5.5 Проверка неизменности оригиналов после сборки

## 6. Безопасность редакторского ввода

- [ ] 6.1 Контент из системы управления проходит существующий центральный sink принятой границы;
      второй конвейер и вторую политику не вводить
- [ ] 6.2 Черновик с непроходящей разметкой сохраняется с предупреждением; публикация такой
      записи отклоняется с указанием непринятого элемента или атрибута
- [ ] 6.3 Гейт: опубликованное содержимое совпадает с тем, что видел редактор, за вычетом только
      того, о чём он предупреждён
