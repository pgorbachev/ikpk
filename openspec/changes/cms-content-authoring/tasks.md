## 9. Гейты и негативная проверка

- [ ] 9.1 Для каждого нового гейта выполнить негативную проверку в своём worktree: вернуть
      дефект, убедиться, что покраснел **именно** этот гейт (судить по имени теста, а не по
      цвету прогона)
- [ ] 9.2 Записать каждую мутацию воспроизводимо: точная команда или патч плюс два числа —
      до и после
- [ ] 9.3 Подтвердить восстановление постусловием под предмет мутации: для отслеживаемых
      файлов — пустой `git status --porcelain` и отсутствие diff к опорному SHA; для
      сгенерированного вывода — контрольная сумма дерева по относительным путям с
      сортировкой
- [ ] 9.4 Проверить, что ни один гейт не проходит вакуумно: пустой список записей,
      отсутствующий каталог и ноль элементов дают «не выполнено», а не успех
- [ ] 9.5 Сверить ответы гейтов, работающих над одним предметом (достижимость страниц,
      целостность каталога): расхождение либо устранить, либо назвать
