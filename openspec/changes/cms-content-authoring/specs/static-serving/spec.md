## ADDED Requirements

### Requirement: Адреса системы управления не попадают под кеш-политику статики

Адреса административной панели и API системы управления SHALL быть выделены в собственный
класс и SHALL получать `Cache-Control`, запрещающий хранение ответа в кеше (`no-store`).
Правило для адресов вне перечисленных классов SHALL NOT распространяться на них.

Требование появилось потому, что система управления встаёт за тот же nginx, что раздаёт
сайт, а правило для адресов вне классов назначает `public, max-age=0, must-revalidate`.
Слово `public` в ответе админки или API разрешает промежуточным кешам хранить ответ,
содержащий данные конкретного сотрудника, — а `max-age=0, must-revalidate` этого не
запрещает: он требует перепроверки, а не отказа от хранения.

Требование выполняется и когда система управления вынесена в отдельный server-блок или на
отдельное имя: тогда достаточно доказать, что правила раздачи статики к её адресам не
применяются.

#### Scenario: ответ админки не разрешён к хранению

- **WHEN** запрошен адрес административной панели
- **THEN** ответ содержит `Cache-Control` с `no-store`
- **AND** значение `public` в нём отсутствует

#### Scenario: ответ API системы управления не разрешён к хранению

- **WHEN** запрошен адрес API системы управления
- **THEN** ответ содержит `Cache-Control` с `no-store`

#### Scenario: правило для адресов вне классов не покрывает систему управления

- **WHEN** проверяется текст генерируемой конфигурации раздачи
- **THEN** адреса административной панели и API не попадают под правило для адресов вне
  перечисленных классов
- **AND** ни одно правило не назначает им `public`
