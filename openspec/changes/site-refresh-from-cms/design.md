## Context

Замер на стенде `193.124.115.99` без переключения действующего релиза: Astro и Pagefind
установленного кода заняли около 11,5 минут и около 487 МиБ в cgroup. Сайт на порту 80
оставался доступен. CMS не отвечала около 80 секунд, пока считались производные изображений.
`npm ci` на том же замере на короткое время останавливал CMS.

Штатный `scripts/publication-launcher.mjs` по-прежнему публикует только проверенную пару
и в этом change не ослабляется. Кнопка не вызывает его и не удаляет его проверки.

## Goals / Non-Goals

**Goals:**

- Одна фоновая операция. Закрытие вкладки её не отменяет. Повторное нажатие показывает ту же операцию.
- Снимок — только опубликованные записи. Сборка — `npm run build` в уже установленном дереве.
- Готовые производные переиспользуются, чтобы не повторять простой CMS. Путь system unit — `nice` и предел кучи V8. `MemoryMax` к этому пути не применяется и общий расход процесса, включая Sharp, не считается ограниченным, пока это не измерено на стенде.
- До переключения сбой оставляет `current`. После переключения неуспешная проверка HTTP и `release.json` видна как ошибка нового релиза.
- Возврат предыдущего каталога — отдельная команда панели, без автоматического отката.

**Non-Goals:**

- Новый сервер, правка конфигурации хоста, обновление main, CMS или зависимостей по нажатию.
- Playwright, полный vitest и повторный CI на каждое контентное нажатие.
- Выкладка этой ревизии на демо до ревью.

## Decisions

1. Состояние операции лежит в файле `site-refresh.json` каталога shared корня сайта, не внутри релиза. Если процесс сборки умер на фазе сборки, состояние становится «прервано», и действующая ссылка не считалась переключённой. Если процесс умер после начала переключения, состояние — ошибка проверки, не успех.
2. Окружение сборки — явный список переменных. Пароль администратора и прочие секреты в него не копируются. В текст состояния токены затираются. Запуск из system unit идёт через nice и предел кучи V8: пользовательский systemd-run там не стартует, потому что нет сессии. Это не предел всего процесса. Состояние пишется атомарно в каталог, который unit разрешает службе; объявление релиза — пара commit и snapshotId, как у штатного release.json.
3. Если нет постоянного дерева с astro и tsx или не задан адрес проверки, операция отказывает до сборки. Зависимости ставит провижининг, не нажатие. Доставка — архив коммита, без игнорируемых файлов рабочего каталога. Commit нового релиза — SHA этого коммита. Commit действующего сайта на его место не подставляется.
4. Ручное восстановление для администратора — кнопка «Вернуть предыдущий релиз». Она меняет ссылку `current` на записанный предыдущий каталог и снова проверяет `release.json`. Браузерный smoke для этого шага не запускается.

## Risks / Trade-offs

- Сборка на 948 МиБ может снова замедлить CMS. Замер 487 МиБ был у пользовательского systemd-run, не у пути nice. Пока первая сборка кнопки на стенде не измерена, общий расход памяти не считается ограниченным. Проверка CMS во время этой сборки остаётся на живой приёмке.
- Если проверка после переключения не проходит, посетитель может видеть новый релиз, пока администратор не вернёт предыдущий. Интерфейс так и говорит.
- [Риск] Неподготовленный стенд: нет постоянного дерева с зависимостями. Отказ до сборки, без `npm ci`.

## Migration Plan

Код кнопки ставится отдельным обновлением кода, не нажатием. До этой установки кнопка на стенде отсутствует. Откат кода — предыдущий релиз CMS, не эта кнопка.
