## 1. Красные тесты по спеке (отдельная сессия, чистый контекст)

Порядок обязателен: это новый change, поэтому тесты пишутся до реализации и красный
прогон предъявляется. Сессия получает на входе только утверждённые артефакты этого change
и код репозитория.

Тесты делятся на два слоя, и слой указан у каждой задачи не для порядка: решение о
диспатче живёт в чистой функции, а отбор прогонов и обращения к API — в адаптере. Тест
чистой функции не видит мутацию в адаптере, поэтому гейт, поставленный не в тот слой,
остаётся зелёным при возвращённом дефекте.

- [ ] 1.1 **Функция.** Таблица состояний: для каждого состояния из требования («нет»,
      «идёт», «покрыто», «состоялся без успеха») — какие проверки попадают в диспатч и
      какие вызывают сигнал. Отдельные фикстуры на `conclusion: failure` и на
      `conclusion: cancelled`, а не одна на «без успеха»
- [ ] 1.2 **Функция.** Исходы, не названные поимённо: `timed_out`, `neutral`, `skipped`,
      `stale`, `action_required`, `startup_failure` — каждый трактуется как неуспех
- [ ] 1.3 **Функция.** Смешанный набор прогонов одной проверки: успешный плюс отменённый —
      покрыто, диспатча нет, сигнала нет
- [ ] 1.4 **Функция.** Смешанное состояние батча: часть покрыта, часть отсутствует —
      диспатчатся ровно отсутствующие
- [ ] 1.5 **Функция.** Покрытие засчитывается по прогону, поднятому не push-событием
- [ ] 1.6 **Функция.** Сигнал: состояние «состоялся без успеха» даёт неуспех с названием
      проверки и SHA; состояния «идёт» и «прогона нет» неуспеха не дают
- [ ] 1.7 **Адаптер.** Ни один запрос перечня прогонов не содержит `event=`. Проверять по
      составу выполненных запросов поверх мока `fetch`; готового образца в дереве больше
      нет — тест такого вида жил в удалённом наборе монитора публикации
- [ ] 1.8 **Адаптер.** Механизм не обращается к перезапуску: ни одного запроса на
      `/rerun` ни при каком состоянии прогонов
- [ ] 1.9 **Адаптер.** Запрашивается только SHA текущей вершины: при истории из двух
      коммитов запросов по перекрытому SHA нет
- [ ] 1.10 **Адаптер.** Неизмеримость: недоступный или неразбираемый перечень прогонов
      даёт неуспех, а не вывод о полноте батча
- [ ] 1.11 **Адаптер.** Цели диспатча выводятся из признака состава батча: диспатч
      возможен только в workflow, имеющий `push` на `main`, и выход за это множество
      недостижим по построению, а не по совпадению
- [ ] 1.12 **Файлы.** Состав батча выводится из триггеров, а не из захардкоженного
      перечня имён: пятый workflow с `push` на `main` в фикстурах входит в батч без правки
      кода
- [ ] 1.13 **Файлы.** У каждой проверки батча есть явный запуск, и сохранён инвариант
      триггеров: `pull_request` без фильтров по путям, `push` на `main` без `paths` и
      `paths-ignore`
- [ ] 1.14 Предъявить красный прогон: отдельный push коммита только с тестами (упавший
      check-run на этом SHA) либо лог с точной командой и SHA
- [ ] 1.15 Для каждого сценария спеки — проверка либо явная отметка, почему проверки нет

**Чего писать НЕ надо, и почему:** теста «реконсилятор не входит в условие публикации» —
он уже существует (`web/tests/deploy-gating.test.ts`, `it('в условие публикации входит
ровно один названный workflow'`), и второй ответ на тот же вопрос запрещён без названного
расхождения. Состав обязательных контекстов защиты ветки предметом в дереве не является
вовсе — см. задачу 6.4, ручная приёмка.

## 5. Негативная проверка каждого нового гейта

Выполняется в своём worktree, фикс к моменту мутации закоммичен, восстановление
подтверждается пустым `git status --porcelain` и отсутствием diff относительно SHA фикса.
Мутация записывается воспроизводимо: точная команда или патч плюс два числа — до и после.
Судить по имени покрасневшего теста, а не по цвету прогона.

- [ ] 5.1 **В адаптере** вернуть автоперезапуск прогона, завершившегося неуспехом
      (обращение к `/rerun`) — краснеет 1.8. Мутация в чистой функции здесь бесполезна:
      она про rerun не знает
- [ ] 5.2 **В адаптере** вернуть `event=push` в строку запроса перечня прогонов — краснеет
      1.7
- [ ] 5.3 Считать незавершённый прогон отсутствующим — краснеет 1.1
- [ ] 5.4 Свести класс «без успеха» к перечню `failure` и `cancelled` — краснеет 1.2
- [ ] 5.5 Считать проверку непокрытой при наличии отменённого прогона рядом с успешным —
      краснеет 1.3
- [ ] 5.6 Заставить чтение перечня прогонов возвращать вывод о полноте батча при ошибке —
      краснеет 1.10
- [ ] 5.7 Заменить вывод состава батча на перечень из четырёх имён — краснеет 1.12
- [ ] 5.8 Снять `workflow_dispatch` — **по очереди у каждого из четырёх** workflow батча,
      четыре отдельные мутации. «У одного из» невоспроизводимо, а у двух триггер был и до
      change, поэтому на них легко получить мутацию, не задевшую предмет
- [ ] 5.9 Расширить цели диспатча за пределы батча — краснеет 1.11
- [ ] 5.10 Убрать из сообщения об отказе имя проверки или SHA — краснеет 1.6

## 6. Живые наблюдения и ручная приёмка

Для каждого пункта сохранить свидетельство: точную команду и её вывод. «Убедиться» без
сохранённого вывода приёмкой не считается.

- [ ] 6.1 Реконсилятор поднял отсутствующие прогоны. Сверять `head_sha` поднятых прогонов
      с вершиной, **прочитанной механизмом**, а не с текущей на момент проверки: при
      сдвиге вершины между чтением и диспатчем прогон относится к новой вершине, и это
      исправное поведение, а не отказ
- [ ] 6.2 Записать наблюдение, сработал ли `workflow_run` в `deploy.yml` от прогона
      `Tests`, поднятого явным запуском с токеном по умолчанию. Что триггер не фильтрует
      по событию апстрим-прогона — читается из файла; неизвестно другое: подавляется ли
      событие анти-рекурсией, когда апстрим-прогон создан диспатчем от токена по
      умолчанию. Ответ добывается опытом
- [ ] 6.3 Повторный оборот на уже покрытой вершине не поднимает ни одного прогона
- [ ] 6.4 Состав обязательных контекстов защиты ветки не изменился. Причина ручной
      приёмки: настройка живёт вне дерева, внутрирепозиторного предиката нет, а `gh api`
      на защиту ветки требует прав администратора и в vitest недоступен. Свидетельство —
      сохранённый вывод `gh api` до и после
