## 1. Красные тесты по спеке (отдельная сессия, чистый контекст)

Порядок обязателен: это новый change, поэтому тесты пишутся до реализации и красный
прогон предъявляется. Сессия получает на входе только утверждённые артефакты этого change
и код репозитория.

- [ ] 1.1 Тесты выбора диспатчируемых проверок по фикстурам: для каждого из четырёх
      состояний прогона («нет», «идёт», «успех», «состоялся без успеха») — какие проверки
      попадают в диспатч и какие нет
- [ ] 1.2 Тест на смешанное состояние: часть батча покрыта, часть отсутствует —
      диспатчатся ровно отсутствующие
- [ ] 1.3 Тест на признак без фильтра по событию: прогон, поднятый явным запуском,
      засчитывается как покрытие
- [ ] 1.4 Тест на сигнал: состояние «состоялся без успеха» даёт неуспех с названием
      проверки и SHA, а состояние «идёт» — не даёт
- [ ] 1.5 Тест на неизмеримость: недоступный или неразбираемый перечень прогонов даёт
      неуспех, а не вывод о полноте батча
- [ ] 1.6 Тест на состав триггеров: у всех workflow батча есть явный запуск, а
      существующие триггеры push и pull_request сохранены
- [ ] 1.7 Тест на границы: workflow реконсилятора не входит ни в условие публикации, ни в
      перечень обязательных для слияния контекстов
- [ ] 1.8 Предъявить красный прогон: отдельный push коммита только с тестами (упавший
      check-run на этом SHA) либо лог с точной командой и SHA
- [ ] 1.9 Тест на состав батча по признаку: батч выводится из триггеров workflow, а не из
      захардкоженного перечня имён. Добавление в фикстуры пятого workflow с `push` на
      `main` включает его в батч без правки кода
- [ ] 1.10 Для каждого сценария спеки — проверка либо явная отметка, почему проверки нет

## 5. Негативная проверка каждого нового гейта

Выполняется в своём worktree, фикс к моменту мутации закоммичен, восстановление
подтверждается пустым `git status --porcelain` и отсутствием diff относительно SHA фикса.
Мутация записывается воспроизводимо: точная команда или патч плюс два числа — до и после.

- [ ] 5.1 Вернуть автоперезапуск прогона, завершившегося неуспехом, — убедиться, что тест
      краснеет
- [ ] 5.2 Вернуть фильтр по `event=push` в признак наличия прогона — убедиться, что тест
      краснеет
- [ ] 5.3 Считать незавершённый прогон отсутствующим — убедиться, что тест краснеет
- [ ] 5.4 Снять `workflow_dispatch` у одного из workflow батча — убедиться, что тест
      краснеет
- [ ] 5.5 Заставить чтение перечня прогонов возвращать вывод о полноте батча при ошибке —
      убедиться, что тест краснеет
- [ ] 5.6 Заменить вывод состава батча на перечень из четырёх имён — убедиться, что тест
      краснеет на пятом workflow
- [ ] 5.7 Судить о каждой мутации по имени покрасневшего теста, а не по цвету прогона
