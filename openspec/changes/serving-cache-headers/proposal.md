## Why

Раздача сайта не сообщает браузеру ни слова о кешировании: ни один ответ nginx не
содержит `Cache-Control`. Измерено на стенде `http://193.124.115.99/` 2026-08-10
(заголовок `Date: Mon, 10 Aug 2026 22:36:45 GMT`):

| Адрес | Код | `Cache-Control` | `Content-Encoding` |
|---|---|---|---|
| `/` | 200 | нет | `gzip` |
| `/_astro/CtaBand.CeDd4XWy.css` | 200 | нет | нет |
| `/favicon.svg` | 200 | нет | нет |
| `/sitemap-index.xml` | 200 | нет | нет |

Следствия: файлы с хешем в имени — вечные по построению — перезапрашиваются с
условным запросом на каждой навигации, а таблицы стилей, векторная графика, XML и
поисковый скрипт едут по сети несжатыми (13 166 байт CSS вместо ~3 КБ; 119 987 байт
`pagefind-ui.js`). Сжатие HTML, которое всё-таки есть, задано не
нами: это умолчание `gzip on` из `/etc/nginx/nginx.conf` дистрибутива, а `gzip_types`
там закомментирован — поэтому сжимается только `text/html`. Опираться на это умолчание
нельзя: оно не наше, в тексте нашего конфига его нет, и переустановка или другой образ
хоста его меняют молча.

Желаемая политика описана в `docs/nginx-migration-notes.md:17-24`. Этот change
превращает её из заметки в требование с воспроизводимой проверкой — но **не переносит
дословно**: состав классов пересчитан по фактической сборке, и заметка оказалась ей не
равна (см. следующий раздел).

### Что показала сборка, чего не знала заметка

Инвентарь снят с `web/dist` после `npm ci && npm run build` на голове ветки change
(`change/serving-cache-headers@87af699d38b03a641f4659d79cbce76ba6875579`). Четыре факта
изменили состав классов:

1. **Под `/_astro/` лежат 7 файлов, и все они CSS.** Файлов JavaScript и sourcemap'ов там
   нет ни одного: весь скрипт страниц встроен в HTML. Единственный внешний скрипт сайта —
   поисковый `/pagefind/pagefind-ui.js`, он подставляется по открытию поиска. То есть
   выигрыш сжатия для JavaScript лежит не там, где его искала заметка.
2. **Каталога `/pagefind/` в заметке нет вовсе** — его не было, когда она писалась. В нём
   297 файлов, 2,6 МБ, и они распадаются на две части: 285 с хешем содержимого в имени
   (`.pf_fragment`, `.pf_index`, `.pf_meta`) и 12 с постоянными именами, включая манифест
   `pagefind-entry.json`. Требования у этих частей противоположные.
3. **Файлы данных поиска уже являются gzip-потоками.** Повторное сжатие их увеличивает —
   измерено на файле фрагмента: 1696 → 1742 байта. Перечень сжимаемых типов обязан их не
   задеть, а это не самоочевидно: расширения `.pf_*` nginx не знает и относит к типу по
   умолчанию.
4. **Файла `sitemap.xml` в сборке нет.** Этот адрес существует только как постоянное
   перенаправление на `/sitemap-index.xml`
   (`deploy/nginx-redirects.conf:13`), поэтому буквальный класс «`sitemap*.xml`» из
   заметки описывает его неверно.

**Кеша никогда не было — это новое поведение, а не дефект** (решение владельца №6 по
плану итерации). Поэтому маршрут — спека, а не red/green по наблюдённому багу.

## What Changes

### Политика кеш-заголовков

Классы адресов получают явный `Cache-Control`. Столбец «откуда» отделяет перенесённое
из заметки от того, что добавлено этим change по фактам сборки, — чтобы утверждение
«политика взята из заметки» не покрывало собой наши собственные решения:

| Класс адресов | `Cache-Control` | Откуда |
|---|---|---|
| `/_astro/*` (имя содержит хеш содержимого) | `public, max-age=31536000, immutable` | заметка |
| данные поиска: `*.pf_fragment`, `*.pf_index`, `*.pf_meta` (имя содержит хеш) | `public, max-age=31536000, immutable` | наше решение |
| `/fonts/*` | `public, max-age=2592000` (30 суток) | наше решение |
| `/favicon.*` | `public, max-age=86400` | заметка |
| `/sitemap*.xml`, **кроме адресов с правилом перенаправления** | `public, max-age=3600` | заметка + поправка |
| страницы (HTML) и всё остальное | `public, max-age=0, must-revalidate` | заметка |

Страницы адресуются **без завершающего слэша** (`/kontakty`, файл
`/kontakty/index.html`), поэтому «`*.html`» из заметки — это класс *страниц*, а не класс
адресов, оканчивающихся на `.html`. Правило по расширению не подошло бы ни к одному
реальному адресу сайта; как это решается — в `design.md`.

Два добавленных класса — не расширение объёма ради полноты, у каждого своя причина.

**Данные поиска** имеют то же свойство, что и `/_astro/`: имя порождается из содержимого,
значит годовое обещание безопасно. Загрузчик поиска с постоянными именами в этот класс
**не входит** — решает не он, а манифест `pagefind-entry.json`, который указывает на файлы
данных по хешам. Закреплённый в кеше старый манифест отправлял бы посетителя за файлами
прошлой сборки, а выкладка хранит пять релизов и старые удаляет: поиск не показал бы
устаревшее, он перестал бы работать.

**Шрифты** — единственное отступление от заметки, и причина в том, что без них change
делал бы хуже, чем сейчас. Сегодня `Cache-Control` нет вовсе, и браузер кеширует шрифты
эвристически — без обращения к сети. Явный `max-age=0, must-revalidate` эвристику
отменяет, а шрифты объявлены `<link rel="preload">` в `<head>` каждой страницы, то есть
лежат на критическом пути первой отрисовки. Цена собственного срока названа: заменить
шрифт можно только переименованием файла. Для медиа та же цена не принята — обоснование
в `design.md`, Решение 7.

### Сжатие

`gzip` и перечень сжимаемых типов задаются **в нашем конфиге**, а не наследуются от
дистрибутива. Сегодня несжатыми едут CSS, SVG, XML и поисковый скрипт — то есть почти
всё, что от сжатия выигрывает. JavaScript в перечне нужен именно ради поиска: под
`/_astro/` файлов JavaScript нет, а `pagefind-ui.js` — 119 987 байт, самый крупный
текстовый ответ сайта.

### Чего этот change НЕ делает — названные решения, не умолчания

- **Security-заголовки** (`X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, `Permissions-Policy`) и **CSP** из того же
  `docs/nginx-migration-notes.md:26-35` — **явно вне scope**. Они идут отдельно, по
  находке B4 security-аудита (`docs/security-audit-2026-08-08.md`), вместе с HTTPS: у
  них своя цена (CSP сначала Report-Only, `frame-src` под RUTUBE) и своя приёмка.
  Разделение осознанное: смешав их с кешем, мы получили бы change, который нельзя
  утвердить по частям.
- **brotli** — вне scope. Причина техническая: модуль `ngx_brotli` в пакете nginx
  Ubuntu не поставляется, его нужно собирать или брать из сторонней сборки; это
  решение об инфраструктуре, а не строка конфига.
- **HTTPS/TLS, HSTS** — вне scope (стенд слушает только `listen 80`).
- **Долгий TTL для медиа** (`/media/*` — 1162 файла, ~79 МБ, `og-image.png`, корневые
  `.svg`) — вне scope. Причина названа: эти имена **не содержат хеша** содержимого,
  поэтому долгий `max-age` для них означал бы «нельзя заменить картинку до истечения
  срока», а замену изображения редактор делает как обычную правку содержимого. Плата за
  это — условный запрос вместо ответа из кеша на каждой навигации — принята сознательно и
  зафиксирована требованием, а не оставлена умолчанием. Шрифты из этого исключения
  **выведены**: см. класс `/fonts/*` выше.
- **Правила перенаправления** — уже в проекте (`include` файла редиректов в vhost);
  этот change их не трогает, но обязан не сломать. Все 264 правила заданы точным
  совпадением адреса, а оно в nginx выигрывает у префикса и регулярного выражения —
  поэтому правила кеша отобрать у них адрес не могут, пока сами не записаны точным
  совпадением. Это свойство удерживается требованием, а не оставлено знанием автора.

## Impact

- **`scripts/bootstrap-vps.sh:70-101`** — носитель конфигурации: vhost пишется целиком
  heredoc'ом `NGINX`, и сейчас в нём нет ни одного `add_header` и ни одной директивы
  сжатия. Другого места, где конфигурация раздачи описана, в репозитории нет
  (`infra/` из заметок ещё не существует).
- **Тесты `web/tests/`** — новый гейт по тексту генерируемого конфига.
- **Живой стенд** — правится **руками** по процедуре `docs/deploy-vps.md:101-120`:
  повторный `bootstrap-vps.sh` отказывается перезаписывать существующий vhost (код
  выхода 3), а обход `FORCE_VHOST=1` снёс бы правки certbot. Отсюда именованное
  ограничение, вынесенное в спеку: **текст скрипта и живой сервер расходятся, и этот
  дрейф ничем не гейтится.**
- **GitHub Pages не затрагивается.** Боевая публикация идёт на Pages, где заголовки
  задаёт платформа и мы их не устанавливаем. Политика этого change действует там, где
  nginx наш: стенд сейчас, боевой хост после переезда. Это ограничение области, а не
  недоделка — но без него легко прочитать «кеш настроен» как «настроен на ikpk.su».
- **`docs/deploy-vps.md:101-120`** — процедура одноразовой ручной правки развёрнутого
  сервера. Сегодня она описывает только добавление `include` редиректов; после этого
  change по ней надо вносить и директивы политики, иначе следующий, кто ей
  воспользуется, оставит хост без кеша и сжатия и не узнает об этом.
- **`docs/tech-debt.md`** — дрейф «текст скрипта ↔ живой vhost» регистрируется записью
  долга. Ограничение названо в спеке, но спека уезжает в `openspec/specs/` вместе с
  архивом change, а долг должен остаться там, где проект его перечитывает.
- `docs/nginx-migration-notes.md` — источник политики; после архива требования живут в
  `openspec/specs/static-serving/`, а заметка остаётся историческим контекстом.
  Security-заголовки и CSP в ней остаются намерением.
- **Смежная дельта:** `article-list-pagination` (после PR #88 — дельты на capability
  `article-catalog`) утверждает ту же поверхность раздачи с другой стороны:
  перенаправления вариантов адресов каталога со завершающим слэшем, 301 для
  `/statyi/page/1`, 404 за диапазоном. Общий предмет — `deploy/nginx-redirects.conf` и
  порядок сопоставления `location`. Противоречия нет; менять форму правил кеша, не
  перечитав ту дельту, нельзя.
