## Why

Раздача сайта не сообщает браузеру ни слова о кешировании: ни один ответ nginx не
содержит `Cache-Control`. Измерено на стенде `http://193.124.115.99/` 2026-08-10
(заголовок `Date: Mon, 10 Aug 2026 22:36:45 GMT`):

| Адрес | Код | `Cache-Control` | `Content-Encoding` |
|---|---|---|---|
| `/` | 200 | нет | `gzip` |
| `/_astro/CtaBand.CeDd4XWy.css` | 200 | нет | нет |
| `/favicon.svg` | 200 | нет | нет |
| `/sitemap-index.xml` | 200 | нет | нет |

Следствия: файлы с хешем в имени — вечные по построению — перезапрашиваются с
условным запросом на каждой навигации, а таблицы стилей и скрипты едут по сети
несжатыми (13 166 байт CSS вместо ~3 КБ). Сжатие HTML, которое всё-таки есть, задано не
нами: это умолчание `gzip on` из `/etc/nginx/nginx.conf` дистрибутива, а `gzip_types`
там закомментирован — поэтому сжимается только `text/html`. Опираться на это умолчание
нельзя: оно не наше, в тексте нашего конфига его нет, и переустановка или другой образ
хоста его меняют молча.

Желаемая политика уже описана в `docs/nginx-migration-notes.md:17-24` — она перенесена
сюда без изобретения. Этот change превращает её из заметки в требование с
воспроизводимой проверкой.

**Кеша никогда не было — это новое поведение, а не дефект** (решение владельца №6 по
плану итерации). Поэтому маршрут — спека, а не red/green по наблюдённому багу.

## What Changes

### Политика кеш-заголовков

Четыре класса адресов получают явный `Cache-Control` — значения дословно из
`docs/nginx-migration-notes.md:17-24`:

| Класс адресов | `Cache-Control` |
|---|---|
| `/_astro/*` (имя содержит хеш содержимого) | `public, max-age=31536000, immutable` |
| `/favicon.*` | `public, max-age=86400` |
| страницы (HTML) | `public, max-age=0, must-revalidate` |
| `/sitemap*.xml` | `public, max-age=3600` |

Страницы адресуются **без завершающего слэша** (`/kontakty`, файл
`/kontakty/index.html`), поэтому «`*.html`» из заметки — это класс *страниц*, а не класс
адресов, оканчивающихся на `.html`. Правило по расширению не подошло бы ни к одному
реальному адресу сайта; как это решается — в `design.md`.

### Сжатие

`gzip` и перечень сжимаемых типов задаются **в нашем конфиге**, а не наследуются от
дистрибутива. Сегодня несжатыми едут CSS, JS, SVG и XML — то есть почти всё, что от
сжатия выигрывает.

### Чего этот change НЕ делает — названные решения, не умолчания

- **Security-заголовки** (`X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, `Permissions-Policy`) и **CSP** из того же
  `docs/nginx-migration-notes.md:26-35` — **явно вне scope**. Они идут отдельно, по
  находке B4 security-аудита (`docs/security-audit-2026-08-08.md`), вместе с HTTPS: у
  них своя цена (CSP сначала Report-Only, `frame-src` под RUTUBE) и своя приёмка.
  Разделение осознанное: смешав их с кешем, мы получили бы change, который нельзя
  утвердить по частям.
- **brotli** — вне scope. Причина техническая: модуль `ngx_brotli` в пакете nginx
  Ubuntu не поставляется, его нужно собирать или брать из сторонней сборки; это
  решение об инфраструктуре, а не строка конфига.
- **HTTPS/TLS, HSTS** — вне scope (стенд слушает только `listen 80`).
- **Долгий TTL для медиа** (`/media/*`, `/fonts/*`, `og-image.png`) — вне scope.
  Причина названа: эти имена **не содержат хеша** содержимого, поэтому долгий
  `max-age` для них означает «нельзя заменить картинку или шрифт до истечения срока».
  Это отдельное решение с отдельной ценой, и заметка-источник их не перечисляет.
- **Правила перенаправления** — уже в проекте (`include` файла редиректов в vhost);
  этот change их не трогает, но обязан не сломать.

## Impact

- **`scripts/bootstrap-vps.sh:70-101`** — носитель конфигурации: vhost пишется целиком
  heredoc'ом `NGINX`, и сейчас в нём нет ни одного `add_header` и ни одной директивы
  сжатия. Другого места, где конфигурация раздачи описана, в репозитории нет
  (`infra/` из заметок ещё не существует).
- **Тесты `web/tests/`** — новый гейт по тексту генерируемого конфига.
- **Живой стенд** — правится **руками** по процедуре `docs/deploy-vps.md:101-120`:
  повторный `bootstrap-vps.sh` отказывается перезаписывать существующий vhost (код
  выхода 3), а обход `FORCE_VHOST=1` снёс бы правки certbot. Отсюда именованное
  ограничение, вынесенное в спеку: **текст скрипта и живой сервер расходятся, и этот
  дрейф ничем не гейтится.**
- **GitHub Pages не затрагивается.** Боевая публикация идёт на Pages, где заголовки
  задаёт платформа и мы их не устанавливаем. Политика этого change действует там, где
  nginx наш: стенд сейчас, боевой хост после переезда. Это ограничение области, а не
  недоделка — но без него легко прочитать «кеш настроен» как «настроен на ikpk.su».
- `docs/nginx-migration-notes.md` — источник политики; после архива требования живут в
  `openspec/specs/static-serving/`, а заметка остаётся историческим контекстом.
