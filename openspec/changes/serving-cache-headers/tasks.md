Пометки у проверок обязательны и означают разное происхождение цвета:

- **[RED]** — проверка обязана падать до реализации, красный прогон предъявляется
  (отдельный push коммита только с тестами либо лог с точной командой и SHA);
- **[GREEN-BY-DESIGN]** — характеризационная проверка: предмет уже существует в коде,
  поэтому она зелёная с первого прогона. Красный прогон для неё **не предъявляется** и
  его отсутствие не является пропуском дисциплины; вместо него обязательна негативная
  мутация — иначе неизвестно, что проверка ловит.

## 4. Негативная проверка гейта

В **отдельном worktree**; фикс к моменту мутации закоммичен; каждая мутация записывается
командой или патчем и **двумя числами — до и после**; суждение по **имени** покрасневшего
теста, а не по цвету прогона.

- [ ] 4.1 Удалить правило `/_astro/` → падает проверка 2.2/2.3 по этому классу
- [ ] 4.2 Подменить значение: `max-age=31536000` без `immutable` → падает 2.2
- [ ] 4.3 Закомментировать блок политики страниц → падает 2.2, а не проходит по
      найденной в комментарии строке
- [ ] 4.4 Удалить `gzip_types`, оставив `gzip on` → падает 2.6. Проверка «сжатие
      включено» без этого была бы зелёной на дистрибутивном умолчании
- [ ] 4.5 Добавить второй `add_header Cache-Control` в один блок → падает 2.4
- [ ] 4.6 Добавить `always` в правило `/_astro/` → падает 2.5
- [ ] 4.7 Переименовать разделитель heredoc → падает 2.1 с сообщением «проверить не
      удалось». Ветка вакуума обязана быть пройдена хотя бы раз, иначе она такое же
      обещание, как непроверенный гейт
- [ ] 4.8 Переставить `\$uri/` перед `\$uri/index.html` → падает 2.7
- [ ] 4.9 Постусловие после каждой мутации: пустой `git status --porcelain` и отсутствие
      diff относительно SHA коммита с реализацией. Worktree удалить
      (`git worktree remove`)
