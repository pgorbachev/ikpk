## Context

Мотивация и измерения — в `proposal.md` («Why»); требования — в
`specs/static-serving/spec.md`. Здесь только то, что определяет реализацию.

Опорное состояние: worktree создан от `main@e26b4fee15d94c5fa4072714d055459cb37edfa8`
(на момент работы `origin/main` ушёл на `aa7678cff3d7a63aeeac581ff36b901ca2ea9a70`; его
дельта касается `web/package.json`, `web/package-lock.json`,
`web/playwright.config.ts` и двух новых файлов `web/tests/helpers/` — ни одного факта
этого change она не задевает, номера строк ниже верны для обоих).

Ограничения, из которых всё вытекает:

- **Носитель конфигурации один.** vhost порождается heredoc'ом `NGINX` в
  `scripts/bootstrap-vps.sh:70-101`, который исполняется на хосте внутри внешнего
  heredoc `REMOTE`. Файла конфигурации в репозитории нет; каталога `infra/` из
  `docs/nginx-migration-notes.md` не существует.
- **Адреса страниц — без расширения и без завершающего слэша.** Это закреплено в
  `try_files \$uri \$uri/index.html \$uri/ =404` (`scripts/bootstrap-vps.sh:96`), и
  комментарий рядом объясняет, почему порядок несущий: `\$uri/` раньше
  `\$uri/index.html` дал бы 301 на адрес со слэшем и разошёлся бы с каноническим адресом.
- **Существующий vhost скрипт не перезаписывает** (`scripts/bootstrap-vps.sh:49-63`,
  код выхода 3; обход — `FORCE_VHOST=1`). Живой стенд правится руками по процедуре
  `docs/deploy-vps.md:101-120`.
- **Сжатие HTML на стенде уже работает, но не нашим конфигом** — это `gzip on` из
  `/etc/nginx/nginx.conf` дистрибутива. `gzip_types` там закомментирован, поэтому CSS,
  JS, SVG и XML едут несжатыми (измерено, см. `proposal.md`).
- **Прецедент проверки текста скрипта в проекте есть:** `web/tests/repo-hygiene.test.ts:121-130`
  сначала выбрасывает строки-комментарии, и только потом ищет директиву — потому что
  первая редакция той проверки проходила на закомментированном `include`.

## Goals / Non-Goals

**Goals:**

- Политика раздачи существует в тексте репозитория, а не в умолчаниях образа хоста.
- Проверка отличает «политика задана» от «проверить не удалось».
- Новые правила не отбирают у страниц их адресный контракт.

**Non-Goals:**

- Не выносить конфигурацию в выкладываемый артефакт. Это закрыло бы дрейф «текст ↔
  живой хост», но это и есть отдельная работа, названная в спеке ограничением: смена
  носителя конфигурации меняет и выкладку, и процедуру первичной настройки.
- Не проверять синтаксическую корректность конфигурации локально: nginx не является
  зависимостью проекта и на раннере не предустановлен. Корректность проверяет сам хост —
  `nginx -t` перед `reload` (`scripts/bootstrap-vps.sh:108`), и `reload` не выполняется
  при неудаче.
- Не трогать security-заголовки, CSP, brotli, TLS, TTL медиа — перечислено в
  `proposal.md` с причинами.

## Decisions

### Решение 1: политика страниц — на уровне `server`, остальные три — правилами по адресу

Класс страниц задаётся `add_header` в блоке `server`, то есть работает как умолчание для
всего, что не перехвачено правилом по адресу. Три остальных класса — правилами
(`location`).

Почему не `location ~* \.html$`, как читается «`*.html`» в заметке-источнике: под это
правило не попадёт **ни один** фактический адрес страницы. Сайт запрашивают как
`/kontakty`, файл `/kontakty/index.html` подставляет `try_files`, и адрес запроса
расширения не содержит. Правило по расширению было бы декоративным — ровно тот класс
проверок, который проект уже разбирал: зелёный цвет там, где предмет не проверяется.

Побочное следствие названо и принято: умолчание накрывает и то, что в четырёх классах не
перечислено (медиа, шрифты, `robots.txt`). Для них `max-age=0, must-revalidate` означает
условный запрос с ответом 304 — расход одного round-trip против невозможности заменить
файл, имя которого не содержит хеша. Спека это фиксирует отдельным сценарием.

Альтернатива — перечислить медиа отдельным правилом с долгим сроком — отклонена в
scope: имена медиа не хешируются, и долгий срок сделал бы замену картинки невидимой для
вернувшегося посетителя.

### Решение 2: только `add_header`, без `expires`

Директива `expires` задаёт `Cache-Control: max-age=…` вместе с legacy-заголовком
`Expires` и не умеет выразить ни `immutable`, ни `must-revalidate` (`expires -1` даёт
`no-cache`). Смешивание двух механизмов дало бы для одного адреса два источника
значения. Поэтому `expires` не используется вовсе, а значения задаются дословно строкой.

### Решение 3: каждое правило повторяет свой заголовок целиком

В nginx набор `add_header` **не складывается** по уровням: если блок объявил хотя бы один
`add_header`, заголовки внешнего уровня в его ответах не появляются. Отсюда две
дисциплины:

- каждое из трёх правил по адресу объявляет свой `Cache-Control` полностью, а не
  «дополняет» серверный;
- один и тот же заголовок не объявляется дважды в одном блоке — иначе он придёт в ответе
  дважды.

**Это же — предупреждение следующему change.** Security-заголовки, добавленные только в
блок `server`, не появятся в ответах `/_astro/`, `/favicon.*` и `/sitemap*.xml` — молча,
без ошибки конфигурации. Когда до них дойдёт дело, набор придётся либо повторять в
каждом правиле, либо вынести в отдельный файл и подключать `include` в каждом блоке.
Записано здесь потому, что обнаружить это по симптомам дорого: заголовок есть на
главной, и проверка «заголовок присутствует» зелёная.

### Решение 4: `always` — только у политики страниц

`add_header` без `always` добавляет заголовок лишь к части кодов ответа (200, 201, 204,
206, 301, 302, 303, 304, 307, 308); 404 в этот перечень не входит.

- у серверного умолчания стоит `always` — тогда страница ошибки тоже получает политику
  страниц, и «страницы нет» не кешируется эвристически;
- у правила `/_astro/` `always` **не ставится** — годовой `immutable` на ответе «файла
  нет» пережил бы любую выкладку у этого клиента. Требование и его причина (окно
  переключения symlink) — в спеке.

Дополнительно то же свойство обеспечивается вторым, независимым механизмом: `error_page
404 /404.html` делает внутреннее перенаправление, и ответ формирует правило страниц —
так что 404 под `/_astro/` приходит с политикой страниц при сохранённом коде 404. Два
механизма на одно свойство здесь не избыточность, а причина не полагаться на порядок
правил: явное отсутствие `always` работает и если `error_page` когда-нибудь уберут.

### Решение 5: формы правил по адресу

- `/_astro/` — префиксное правило с приоритетом (`^~`): содержимое каталога заведомо
  хешировано сборкой, регулярные выражения здесь не нужны;
- `/favicon.*` и `/sitemap*.xml` — по регулярному выражению, дословно по классам из
  заметки: имя, а не конкретные два файла. `favicon.ico` и `favicon.svg` существуют
  сегодня; `sitemap-index.xml` и `sitemap-0.xml` порождает `@astrojs/sitemap` и число
  частей растёт с сайтом.

Следствие, которое надо знать: правило по адресу забирает запрос у `location /` вместе с
его `try_files`. Для всех трёх классов это безвредно — адреса ведут в существующие файлы,
а `root` и `error_page` наследуются от `server`. Проверяется сценариями требования
«Введение правил раздачи сохраняет адресный контракт».

### Решение 6: сжатие задаётся полностью, `text/html` в перечень не входит

`gzip on` плюс явный `gzip_types`. `text/html` в перечень **не добавляется**: nginx
сжимает его всегда, а повторное упоминание даёт предупреждение `duplicate MIME type` в
`nginx -t` — предупреждение, не ошибку, поэтому его легко занести и не заметить.

Дополнительно ставится `gzip_vary on` (ответ помечается `Vary: Accept-Encoding` — иначе
промежуточный кеш может отдать сжатый ответ клиенту без поддержки сжатия) и
`gzip_min_length` порядка нескольких сотен байт: на очень коротких ответах сжатие
увеличивает объём. Это защитные умолчания реализации, а не контракт — в спеке их нет
намеренно.

### Решение 7: гейт разбирает heredoc, а не файл целиком

Проверка (vitest, новый файл `web/tests/serving-config.test.ts` — то есть внутри job
`unit-and-build` workflow `Tests`, единственной проверки, входящей в гейт публикации):

1. читает `scripts/bootstrap-vps.sh`;
2. вырезает **тело heredoc'а `NGINX`** — от строки, открывающей запись vhost, до
   закрывающего разделителя. Если блок не найден или пуст — проверка **падает** с
   сообщением «проверить не удалось». Это прямое требование спеки и защита от того, что
   скрипт перепишут, а гейт останется зелёным на пустом множестве;
3. выбрасывает строки-комментарии (приём из `web/tests/repo-hygiene.test.ts:121-125`) и
   только затем ищет директивы;
4. разбирает тело на блоки правил, чтобы утверждать заголовок **в нужном блоке**, а не
   где-нибудь в файле: значение `immutable`, найденное в блоке страниц, требование не
   удовлетворяет.

Почему не «прогнать nginx и посмотреть заголовки» — см. Non-Goals. Почему не грепать
файл целиком — потому что `add_header` в поясняющем комментарии или в подсказке оператору
(`scripts/bootstrap-vps.sh:50-59` печатает инструкцию текстом) удовлетворил бы греп, не
изменив ни одного ответа сервера.

Негативная проверка — в отдельном worktree, фикс закоммичен до мутации, мутация
записывается командой или патчем и двумя числами. Мутации по одной на класс: удаление
правила, подмена значения, комментирование блока, удаление `gzip_types`, переименование
разделителя heredoc (проверка «предмет исчез»).

## Risks / Trade-offs

- **Правило по адресу отбирает `try_files`** → сценарии адресного контракта в спеке плюс
  ручная приёмка: `/kontakty` без слэша, `/contacts` c 301, несуществующий адрес.
- **Дрейф «текст в репозитории ↔ живой vhost»** → назван ограничением в спеке;
  свидетельство приёмки фиксирует момент правки. Закрытие — отдельный change
  (конфигурация как выкладываемый артефакт либо сверка живого конфига с ожидаемым).
- **Годовой `immutable` — необратимое обещание** → опирается на свойство сборки: имена
  под `/_astro/` содержат хеш содержимого. Свойство даёт Astro, и этот change его не
  проверяет. Если сборка когда-нибудь положит туда файл со стабильным именем, класс
  окажется неверным, а посетители получат его старую версию на год. Проверка этого
  свойства по артефакту сборки — кандидат в follow-up, здесь не заявляется.
- **Будущие security-заголовки потеряются в правилах по адресу** → Решение 3, записано
  адресно для того change.
- **Гейт проверяет намерение, а не ответ сервера** → и это названо прямо: спека требует
  свидетельства с живой раздачи отдельным требованием, а не считает зелёный тест
  доказательством работающего кеша.

## Migration Plan

1. Правка heredoc в `scripts/bootstrap-vps.sh` — на новых хостах политика появляется с
   первого `bootstrap`.
2. Живой стенд: правка руками по процедуре `docs/deploy-vps.md:101-120` — резервная
   копия vhost, внесение директив, `nginx -t`, `systemctl reload nginx`. Повторный
   `bootstrap-vps.sh` **не запускать** (он отказом и защищён), `FORCE_VHOST=1` не
   использовать: на стенде это снесло бы конфигурацию целиком.
3. Свидетельство `curl -sS -D-` по четырём классам до и после правки.
4. Откат: восстановить vhost из `.bak` и `reload`. До `reload` предыдущая конфигурация
   продолжает работать, поэтому упавший `nginx -t` состояние стенда не меняет.
