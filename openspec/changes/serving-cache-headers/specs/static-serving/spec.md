## Purpose

Задаёт контракт раздачи собранной статики нашим nginx: какие заголовки кеширования
получает каждый класс адресов, чем сжимаются ответы и какие свойства адресов раздача
обязана сохранять. Область охватывает конфигурацию сайта, которой мы владеем; заголовки
сторонней площадки публикации в неё не входят.

## ADDED Requirements

### Requirement: Кеш-политика задана классами адресов

Раздача SHALL отдавать `Cache-Control` со значением, определяемым классом адреса:

| Класс адресов | `Cache-Control` |
|---|---|
| путь начинается с `/_astro/` | `public, max-age=31536000, immutable` |
| имя файла оканчивается на `.pf_fragment`, `.pf_index` или `.pf_meta` | `public, max-age=31536000, immutable` |
| путь начинается с `/fonts/` | `public, max-age=2592000` |
| имя файла начинается с `favicon.` в корне сайта | `public, max-age=86400` |
| имя файла начинается с `sitemap` и оканчивается на `.xml` в корне сайта, **кроме адресов, для которых задано правило перенаправления** | `public, max-age=3600` |
| ответ типа `text/html` (страница сайта) | `public, max-age=0, must-revalidate` |
| всё остальное | `public, max-age=0, must-revalidate` |

Значения SHALL совпадать дословно, включая `immutable`: `max-age` без `immutable` не
запрещает браузеру условный запрос, а именно его отсутствие — смысл неизменяемых классов.

**Неизменяемый класс SHALL покрывать только имена, несущие хеш содержимого.** Годовой срок
с `immutable` — необратимое обещание: посетитель, получивший такой ответ, не перезапросит
адрес до истечения срока, и выкладкой это не чинится. Поэтому в неизменяемый класс входит
только то, чьё имя меняется вместе с содержимым, и адрес с постоянным именем SHALL NOT
попадать в него, даже если содержимое по этому адресу меняется редко.

**Класс шрифтов — наше решение, а не перенос из заметки-источника,** и его цена названа
здесь: имена шрифтов постоянны, поэтому заменить шрифт, не сменив имени файла, нельзя —
вернувшийся посетитель до месяца будет получать старый. Замена шрифта SHALL выполняться
переименованием файла. Класс существует потому, что шрифты лежат на критическом пути
отрисовки (страницы объявляют их через `<link rel="preload">`), а срок без него был бы
нулевым — см. требование о сохранении уже достигнутого поведения кеша.

**Класс карт сайта SHALL уступать правилам перенаправления.** Адрес `/sitemap.xml`
перенаправляется на `/sitemap-index.xml` постоянным перенаправлением, файла с таким именем
в сборке нет, и адрес зарегистрирован во внешних сервисах — поэтому под класс карт сайта он
не попадает, и его ответ определяется правилом перенаправления, а не кеш-политикой карт.
Совпадение по классу имён SHALL NOT перехватывать адрес, для которого задано правило
перенаправления.

Класс страниц SHALL определяться по факту «это страница», а не по завершению адреса на
`.html`. Сайт адресует страницы без расширения и без завершающего слэша (`/kontakty`,
`/statyi/<slug>`), поэтому правило по расширению `.html` не подошло бы ни к одному
адресу, по которому сайт фактически запрашивают, и класс страниц остался бы пустым.

Раздача SHALL NOT опираться на значения, заданные вне конфигурации сайта: политика,
унаследованная от конфигурации дистрибутива или образа хоста, требованием не считается —
она меняется молча и в нашем тексте не видна.

#### Scenario: Файл с хешем содержимого в имени

- **WHEN** запрошен существующий файл под `/_astro/` (например
  `/_astro/CtaBand.CeDd4XWy.css`)
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=31536000, immutable`

#### Scenario: Данные поиска с хешем содержимого в имени

- **WHEN** запрошен файл данных поискового индекса, имя которого несёт хеш содержимого
  (например `/pagefind/fragment/ru_129b2ce.pf_fragment`, `/pagefind/index/ru_22aa6c8.pf_index`
  или `/pagefind/pagefind.ru_206ebec66e.pf_meta`)
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=31536000, immutable`

#### Scenario: Загрузчик и манифест поиска — с постоянными именами

- **WHEN** запрошен файл поиска с постоянным именем: `/pagefind/pagefind-entry.json`,
  `/pagefind/pagefind-ui.js`, `/pagefind/pagefind.js` либо `/pagefind/wasm.ru.pagefind`
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=0, must-revalidate`
- **AND** долгий срок этим адресам не назначается: `pagefind-entry.json` — манифест,
  который указывает на файлы данных по их хешам, и закреплённый в кеше старый манифест
  отправлял бы клиента за файлами, которых после следующей выкладки уже нет

#### Scenario: Шрифт

- **WHEN** запрошен `/fonts/inter-latin.woff2` либо `/fonts/inter-cyrillic.woff2`
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=2592000`

#### Scenario: Страница по адресу без расширения

- **WHEN** запрошена страница по адресу без расширения и без завершающего слэша
  (например `/kontakty`), которую раздача отдаёт из файла `/kontakty/index.html`
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=0, must-revalidate`

#### Scenario: Главная страница

- **WHEN** запрошен `/`
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=0, must-revalidate`

#### Scenario: Иконка сайта в обоих форматах

- **WHEN** запрошен `/favicon.ico` либо `/favicon.svg`
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=86400`

#### Scenario: Карта сайта и её части

- **WHEN** запрошен `/sitemap-index.xml` либо `/sitemap-0.xml`
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=3600`

#### Scenario: Адрес карты сайта, у которого есть правило перенаправления

- **WHEN** запрошен `/sitemap.xml`
- **THEN** ответ 301 на `/sitemap-index.xml`, а не 200 с политикой карт сайта
- **AND** кеш-политика этот адрес у правила перенаправления не отбирает

#### Scenario: Страница карты сайта для человека

- **WHEN** запрошен `/sitemap` — HTML-страница со ссылками, а не XML-файл
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=0, must-revalidate`
- **AND** совпадение начала имени с классом карт сайта на неё не распространяется: класс
  задан именами файлов, оканчивающихся на `.xml`

#### Scenario: Адрес вне перечисленных классов

- **WHEN** запрошен файл, не попадающий ни в один класс со своим сроком и не являющийся
  страницей (например `/og-image.png`, `/media/<файл>`, `/robots.txt`)
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=0, must-revalidate`
- **AND** долгий срок жизни таким адресам не назначается: их имена не содержат хеша
  содержимого, поэтому кеш нельзя было бы инвалидировать заменой файла

### Requirement: Заголовок кеширования не теряется и не удваивается

Ровно один заголовок `Cache-Control` SHALL присутствовать в ответе, если это:

- успешный ответ (200) по адресу любого класса;
- ответ 404, отдающий страницу ошибки сайта;
- ответ постоянного перенаправления, порождённый правилом адресации.

Требование существует потому, что в nginx набор добавляемых заголовков не складывается
по уровням конфигурации: обработчик, объявивший свой заголовок, теряет заголовки
внешнего уровня, а объявленный дважды на одном уровне — удваивается. Оба исхода
наблюдаемы снаружи и оба неверны: потеря даёт ответ без политики, удвоение — ответ с
двумя политиками, разрешение которого остаётся на усмотрение клиента.

**Область требования сужена намеренно, и граница названа.** Правило `/_astro/` объявляет
свой заголовок **без** `always` — этого требует запрет годовой неизменяемости на ответах
об отсутствии. Следствие: ответы под этим правилом с кодами, которые `add_header` без
`always` не покрывает и которые не проходят через страницу ошибки (403 на запрос каталога,
5xx), приходят **без** `Cache-Control`. Это принято, а не упущено: такие ответы порождает
сам сервер, они не несут `Last-Modified`, и эвристическое кеширование к ним неприменимо —
то есть отсутствие заголовка ничего в кеше клиента не закрепляет. Расширять требование на
все коды ответа означало бы поставить `always` и туда, где оно опасно.

#### Scenario: Класс со своим правилом не теряет заголовок

- **WHEN** запрошен существующий адрес любого класса из требования «Кеш-политика задана
  классами адресов»
- **THEN** в ответе присутствует заголовок `Cache-Control`
- **AND** он встречается один раз, а не дважды

#### Scenario: Перенаправление со старого адреса тоже несёт политику

- **WHEN** запрошен адрес, для которого задано правило перенаправления
- **THEN** ответ 301 содержит ровно один `Cache-Control` со значением политики страниц
- **AND** правило перенаправления своего значения не объявляет — оно наследует умолчание,
  и это единственное, что удерживает 264 таких правила от ответа без политики

### Requirement: Неизменяемость не распространяется на ответы об отсутствии

Ответ с кодом 404 на адрес под `/_astro/` SHALL NOT содержать
`Cache-Control: public, max-age=31536000, immutable`. То же SHALL действовать для любого
другого неизменяемого класса.

Причина не теоретическая: выкладка переключает symlink `current`, и запрос, попавший в
окно переключения, может получить 404 на существующий в новой сборке файл. Ответ
«отсутствует» с годовым `immutable` закрепил бы это в кеше клиента на год — страница у
такого посетителя осталась бы без стилей, и починить это выкладкой было бы нельзя.

Страница ошибки SHALL отдаваться с политикой страниц: `public, max-age=0,
must-revalidate`. Иначе клиент кеширует «страницы нет» эвристически, по `Last-Modified`,
и появление страницы по этому адресу до него не доходит.

#### Scenario: Отсутствующий файл с хешем в имени

- **WHEN** запрошен несуществующий адрес под `/_astro/`
- **THEN** ответ 404 не содержит `max-age=31536000` и не содержит `immutable`

#### Scenario: Отсутствующая страница

- **WHEN** запрошен адрес, которому не соответствует ни файл, ни правило
  перенаправления
- **THEN** ответ 404 отдаёт страницу ошибки сайта
- **AND** содержит `Cache-Control: public, max-age=0, must-revalidate`

#### Scenario: Страница ошибки запрошена напрямую

- **WHEN** запрошен `/404.html` — файл страницы ошибки существует в сборке и доступен по
  своему адресу
- **THEN** ответ 200 содержит `Cache-Control: public, max-age=0, must-revalidate`
- **AND** он не отличается от политики, с которой та же страница приходит кодом 404

### Requirement: Сжатие задано конфигурацией сайта и покрывает текстовые типы

Конфигурация сайта SHALL включать сжатие gzip и SHALL перечислять сжимаемые типы
содержимого явно.

Перечень SHALL включать как минимум: CSS, JavaScript, SVG, XML, JSON, обычный текст.
Требование задано перечнем, а не словом «текстовые», потому что умолчание nginx — только
`text/html`: при включённом сжатии и незаданном перечне таблицы стилей и скрипты едут
несжатыми, а проверка «сжатие включено» на HTML остаётся зелёной.

**Перечень SHALL называть тип содержимого, который отдаёт наш хост, а не каноническое
написание типа.** Фактическое отображение «расширение → тип» задаёт таблица типов nginx, а
не конфигурация сайта, поэтому для классов, у которых в ходу два написания, перечень SHALL
включать **оба**:

| Класс | Обязательные строки перечня |
|---|---|
| XML | `text/xml` **и** `application/xml` |
| JavaScript | `application/javascript` **и** `text/javascript` |

Требование записано в такой форме потому, что промах по написанию **не наблюдаем в тексте
конфигурации**: перечень с одним каноническим написанием оставляет карту сайта и поисковый
скрипт несжатыми, а проверка «XML в перечне есть» остаётся зелёной. Наш хост отдаёт `.xml`
как `text/xml` и `.js` как `application/javascript` — то есть в обоих классах каноническое
написание оказывается не тем. Оба написания названы также потому, что таблица типов
меняется обновлением пакета nginx, а не нашим решением. Плата за это нулевая:
предупреждение о дубликате типа возникает при повторе одного и того же типа, а
перечисленные — разные типы.

Достаточным доказательством сжатия для этих классов текст конфигурации SHALL NOT считаться:
таблицей типов конфигурация сайта не управляет, поэтому факт сжатия подтверждается только
свидетельством с живой раздачи (требование о свидетельстве ниже).

Перечень SHALL NOT включать типы, содержимое которых уже сжато: шрифты `woff2`,
растровые изображения `png`, `jpeg`, `webp`, архивы. Повторное сжатие расходует
процессор хоста и не уменьшает ответ.

**Перечень SHALL NOT включать тип по умолчанию для неизвестных расширений**
(`application/octet-stream`). Под него попадают файлы данных поиска, а они **уже являются
gzip-потоками**: сжатие их не уменьшает, а увеличивает (измерено на файле фрагмента:
1696 → 1742 байта). Раздача отдаёт их как есть, без `Content-Encoding`, а распаковывает
их сам клиент поиска — этого достаточно, и вмешательство раздачи здесь только вредит.

Сжатие HTML SHALL продолжать действовать после того, как перечень задан нами. Перечень
типов его не отменяет и не включает: nginx сжимает `text/html` всегда, а упоминание этого
типа в перечне даёт предупреждение о дубликате. Требование записано потому, что сжатие
HTML сегодня работает не нашим конфигом, и «мы задали перечень» легко принять за «мы
задали и HTML».

#### Scenario: Таблица стилей

- **WHEN** клиент, объявивший поддержку gzip, запрашивает `.css` под `/_astro/`
- **THEN** ответ содержит `Content-Encoding: gzip`

#### Scenario: Скрипт поиска

- **WHEN** клиент, объявивший поддержку gzip, запрашивает `/pagefind/pagefind-ui.js`
- **THEN** ответ содержит `Content-Encoding: gzip`
- **AND** проверка ставится именно на этот адрес: под `/_astro/` файлов JavaScript нет
  вовсе, весь скрипт страниц встроен в HTML, и скрипт поиска — единственный внешний

#### Scenario: Векторная графика и карта сайта

- **WHEN** клиент, объявивший поддержку gzip, запрашивает `/favicon.svg` или
  `/sitemap-index.xml`
- **THEN** ответ содержит `Content-Encoding: gzip`

#### Scenario: Страница

- **WHEN** клиент, объявивший поддержку gzip, запрашивает страницу сайта
- **THEN** ответ содержит `Content-Encoding: gzip`

#### Scenario: Уже сжатое содержимое

- **WHEN** клиент, объявивший поддержку gzip, запрашивает `/fonts/inter-latin.woff2` либо
  файл данных поиска (`.pf_fragment`, `.pf_index`, `.pf_meta`, `wasm.*.pagefind`)
- **THEN** ответ не содержит `Content-Encoding: gzip`

#### Scenario: Клиент без поддержки сжатия

- **WHEN** клиент не объявляет поддержку gzip
- **THEN** ответ приходит несжатым и пригодным к чтению

### Requirement: Введение политики не ухудшает уже достигнутое кеширование

Раздача SHALL NOT ухудшать поведение кеша для адресов, которые до введения политики
кешировались клиентом без обращения к сети.

Требование внесено потому, что сегодня `Cache-Control` не отдаётся вовсе, и браузер
применяет к таким ответам эвристику по `Last-Modified` — то есть повторная навигация не
порождает запроса. Явная политика `max-age=0, must-revalidate` эвристику отменяет и
заменяет её условным запросом на каждую навигацию. Для части адресов это осознанная плата
за возможность заменить файл, но для тех, что лежат на критическом пути отрисовки и не
меняются, плата не оправдана: изменение, задуманное как улучшение, сделало бы первую
отрисовку медленнее, чем она есть сейчас.

Адреса, для которых явная политика была бы строже эвристики и цена этого не принята, SHALL
получать собственный класс со сроком — сегодня это шрифты. Адреса, для которых цена
условного запроса принята, SHALL быть названы вместе с причиной, а не остаться
умолчанием по недосмотру.

#### Scenario: Шрифт на критическом пути

- **WHEN** посетитель, у которого шрифт уже в кеше, открывает вторую страницу сайта
- **THEN** шрифт берётся из кеша без обращения к сети
- **AND** условный запрос перед отрисовкой текста не выполняется

#### Scenario: Принятая плата названа

- **WHEN** адрес получает политику `max-age=0, must-revalidate` и до введения политики
  кешировался эвристически (изображения `/media/`, `og-image.png`)
- **THEN** переход на условный запрос при каждой навигации зафиксирован как принятая
  плата с причиной, а не обнаружен после выкладки

### Requirement: Введение правил раздачи сохраняет адресный контракт

Раздача SHALL сохранять поведение адресов, действовавшее до введения кеш-политики:

- страница по адресу без завершающего слэша SHALL отдаваться кодом 200, а не
  перенаправлением на адрес со слэшем;
- правила перенаправления со старых адресов SHALL продолжать действовать;
- несуществующий адрес SHALL продолжать отдавать страницу ошибки сайта.

Требование внесено потому, что правила по классам адресов в nginx перехватывают запрос у
обработчика по умолчанию: адрес, попавший под новое правило, обслуживается уже не тем
кодом, который держит перечисленные свойства. Без этого требования кеш-заголовки можно
было бы «настроить», сломав канонические адреса, и ни одна проверка политики этого бы не
заметила.

Правило кеш-политики SHALL NOT задаваться формой, способной перехватить адрес у правила
перенаправления. Правила перенаправления заданы точным совпадением адреса, и точное
совпадение в nginx выигрывает у любой другой формы — поэтому правило кеша, заданное
префиксом или регулярным выражением, их не отбирает, а заданное точным совпадением того же
адреса — отберёт молча.

#### Scenario: Адрес без завершающего слэша

- **WHEN** запрошен `/kontakty`
- **THEN** ответ 200, без перенаправления на `/kontakty/`

#### Scenario: Старый адрес

- **WHEN** запрошен адрес, для которого задано правило перенаправления (например
  `/contacts`)
- **THEN** ответ 301 на новый адрес

#### Scenario: Правил перенаправления пока нет

- **WHEN** файл правил перенаправления пуст
- **THEN** конфигурация остаётся корректной и раздача работает

### Requirement: Политика проверяется по тексту генерируемой конфигурации

Проверка SHALL читать текст конфигурации сайта, который порождает средство первичной
настройки хоста, и утверждать по нему требования этой capability, которые в тексте
выразимы: значения `Cache-Control` по классам, отсутствие потери и удвоения заголовка,
наличие сжатия и состав перечня сжимаемых типов, сохранность правил адресации.

Проверка SHALL утверждать значение класса **в том правиле, которое этот класс задаёт**, а
не по вхождению значения в текст конфигурации: значение неизменяемого класса, оказавшееся
в правиле страниц, требование не удовлетворяет, а удовлетворяющая ему проверка не
отличает верную конфигурацию от перепутанной.

Проверка SHALL падать, если предмет проверки не найден — блок, порождающий
конфигурацию, отсутствует, переименован или пуст. Отсутствие текста для разбора SHALL
трактоваться как «проверить не удалось», а не как «нарушений нет».

Проверка SHALL утверждать директивы по исполняемому тексту конфигурации, а не по
вхождению подстроки в файл целиком: закомментированная строка и упоминание директивы в
пояснении SHALL NOT считаться заданной политикой.

#### Scenario: Правило удалено

- **WHEN** из конфигурации удалено правило любого класса адресов
- **THEN** проверка падает и называет отсутствующий класс

#### Scenario: Значение изменено

- **WHEN** значение `Cache-Control` любого класса отличается от заданного спекой (иное
  число секунд, потерянный `immutable`, `no-store` вместо ревалидации)
- **THEN** проверка падает

#### Scenario: Значение оказалось в чужом правиле

- **WHEN** значение неизменяемого класса задано не в его правиле, а в правиле другого
  класса
- **THEN** проверка падает, а не засчитывает вхождение значения в текст

#### Scenario: Политика закомментирована

- **WHEN** директивы политики присутствуют в файле, но закомментированы
- **THEN** проверка падает

#### Scenario: Предмет проверки исчез

- **WHEN** блок, порождающий конфигурацию сайта, отсутствует или не содержит
  директив
- **THEN** проверка падает с сообщением о том, что проверить не удалось

#### Scenario: Перечень сжимаемых типов пуст

- **WHEN** сжатие включено, но перечень сжимаемых типов не задан
- **THEN** проверка падает: включённое сжатие без перечня покрывает только HTML

#### Scenario: Перечень называет только одно из двух написаний типа

- **WHEN** перечень сжимаемых типов содержит для XML или для JavaScript только одно из двух
  обязательных написаний (например `application/xml` без `text/xml`)
- **THEN** проверка падает и называет отсутствующую строку
- **AND** зачёт по принципу «годится любое из написаний» требованию не соответствует:
  фактический тип задаёт таблица типов nginx, и ответ по промахнувшемуся классу приходит
  несжатым при зелёной проверке

#### Scenario: Правило кеша перехватывает перенаправление

- **WHEN** правило кеш-политики задано точным совпадением адреса, для которого существует
  правило перенаправления
- **THEN** проверка падает: перенаправление было бы отобрано молча, и снаружи это видно
  только запросом того самого адреса

### Requirement: Действие политики на живой раздаче подтверждается свидетельством

Введение политики SHALL подтверждаться свидетельством с работающей раздачи: снятые
заголовки ответа до и после правки, с указанием адреса, времени и точной команды.
Проверка текста конфигурации свидетельством не является — она утверждает намерение, а не
результат.

Свидетельство SHALL сниматься для каждого класса адресов и SHALL включать проверку сжатия
хотя бы для одного типа, который не сжимается умолчанием nginx (CSS или SVG), и для
страницы — чтобы сжатие HTML, сегодня работающее не нашим конфигом, было подтверждено
после правки, а не предположено.

**Именованное ограничение.** Свидетельство доказывает **момент**, а не состояние.
Живая конфигурация правится руками — средство первичной настройки отказывается
перезаписывать существующий vhost, а принудительная перезапись снесла бы правки,
внесённые на хосте отдельно. Поэтому текст в репозитории и файл на хосте расходятся
после любой ручной правки, и **этот дрейф не гейтится ничем**: проверка текста его не
видит по построению, а выкладка конфигурацию сайта не переписывает. Ограничение
фиксируется как известное; его закрытие (конфигурация как выкладываемый артефакт либо
сверка живого конфига с ожидаемым) — предмет отдельного change, а не этого.

#### Scenario: Приёмка после правки живой раздачи

- **WHEN** политика внесена в живую конфигурацию и раздача перезагружена
- **THEN** сохранено свидетельство: для каждого класса адресов — заголовки ответа до
  правки и после, адрес, время и команда
- **AND** видно, что `Cache-Control` соответствует классу, а CSS и страница отдаются
  сжатыми

#### Scenario: Расхождение текста и живой раздачи

- **WHEN** живая конфигурация отличается от текста в репозитории
- **THEN** это состояние остаётся необнаруженным автоматическими проверками, и
  ограничение названо в спецификации, а не выдано за покрытое
