## 2. Красные тесты в отдельной сессии

- [ ] 2.1 Идемпотентность: повторный запуск даёт успех и нулевое число изменений; запуск после
  прерывания доводит состояние; изменение объявленного значения приводит к изменению и оно
  названо.
- [ ] 2.2 Один артефакт: провижининг стенда и боевого сервера выполняется одним исполняемым
  артефактом; отдельного артефакта для боевого сервера нет.
- [ ] 2.3 Окружение — вход: запуск без явного окружения отказывает; окружение не выводится из
  имени хоста, адреса или наличия файлов; отсутствие обязательного значения останавливает с
  его названием.
- [ ] 2.4 Секреты: отказ при отсутствии обязательного секрета без подстановки умолчания;
  контрольное значение секрета в окружении не встречается в аргументах, выводе, логах и
  артефактах; запуск без контрольного значения — непройденная проверка; в отслеживаемых файлах
  значений секретов нет.
- [ ] 2.5 Права: учётная запись выкладки не может выполнять произвольные команды с повышением;
  перечень разрешённых ей команд непуст и поимённый; запись вне каталога релизов и конфигурации
  раздачи отклоняется; служба и выкладка — разные учётные записи.
- [ ] 2.6 Закрытость службы: обращение снаружи к её порту не устанавливает соединения;
  обращение через сервер раздачи отвечает; порт вне объявленного перечня закрыт; служба
  поднимается после перезапуска машины.
- [ ] 2.7 Доверенный механизм: расположен вне проверяемого рабочего дерева; учётных данных нет
  в окружении кода из проверяемого дерева до подтверждения источника.
- [ ] 2.8 Резервная копия: разрушающее действие без копии не выполняется; неуспех снятия копии
  останавливает действие и назван; восстановление подтверждается сравнением состояний.
- [ ] 2.9 Проверка результата: успех называет число выполненных проверок больше нуля;
  несоответствие одного свойства даёт неуспех с его названием; ноль выполненных проверок —
  неуспех; недостижимый сервер — неуспех, а не отсутствие несоответствий.
- [ ] 2.10 Предъявить красный прогон по именам тестов и негативно проверить каждый новый гейт
  своей целевой мутацией; мутацию записать воспроизводимо — команда или патч плюс два числа.

## 4. Сценарий провижининга

- [ ] 4.1 Каркас: явный вход окружения, загрузка значений, отказ при отсутствии обязательного,
  раздельные счётчики проверенного и изменённого.
- [ ] 4.2 Шаги «сверить — при расхождении привести» для учётных записей, каталогов, прав и
  привилегированного перечня.
- [ ] 4.3 Шаги для сервера раздачи и службы системы управления, включая политику перезапуска и
  привязку к локальному интерфейсу.
- [ ] 4.4 Шаги сетевых ограничений: закрыто по умолчанию, открыты только объявленные порты.
- [ ] 4.5 Установка доверенного механизма вне рабочего дерева и передача ему учётных данных.
- [ ] 4.6 Резервное копирование как предусловие разрушающих шагов и процедура восстановления.
- [ ] 4.7 Записать в самом сценарии порог перехода на систему управления конфигурацией: третий
  сервер либо второй регулярный оператор.
