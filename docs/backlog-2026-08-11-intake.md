# Ненормативный снимок задания (intake). Требования живут в OpenSpec

**Дата приёма задания:** 2026-08-11
**Статус:** ненормативный. Этот файл **не является источником требований** и не
задаёт объём работ.

## Зачем этот файл

Владелец передал backlog устно/в переписке. Чтобы объём был проверяемым — чтобы
через неделю можно было спросить «а это вообще просили?» и «не просочилось ли
лишнее?» — задание записано дословно, одним снимком, на дату приёма.

Дальше это **не источник истины**. Порядок сверки — из
[AGENTS.md](../AGENTS.md#source-of-truth): требования живут в активных changes в
`openspec/changes/`, принятое поведение — в `openspec/specs/`. При любом
расхождении между этим файлом и спецификацией **побеждает спецификация**, без
обсуждения: снимок сделан один раз и не переживает уточнений, а change
версионируется вместе с кодом.

Практическое следствие: этот файл не обновляется по ходу работ. Если задание
изменилось — оно меняется в change, а не здесь. Формулировки ниже намеренно
остаются такими, какими были получены, включая те, что при проектировании
разложились иначе.

## Вне scope

Названо владельцем как исключённое из этой итерации. Не «потом» и не «если
останется время» — в этой итерации не трогаем:

- telegram-счётчик;
- НМО-фильтр и бейджи;
- дефицит без данных источника;
- каталог выпускников;
- B2B-тарифы;
- региональные представительства.

Отдельно про telegram-счётчик: на момент приёма задания работа по нему
существует незакоммиченным черновиком в рабочем дереве владельца, а не в
`main` (на `e26b4fee15d94c5fa4072714d055459cb37edfa8` каталога change нет).
Исключение из scope означает, что этот черновик в итерации не трогается — ни
доводится, ни удаляется.
