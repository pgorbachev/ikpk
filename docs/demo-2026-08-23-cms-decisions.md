# Два решения по модели контента CMS. Ненормативный вход для OpenSpec

**Предмет:** два вопроса, возникшие при внесении решений после демонстрации в change
`cms-content-authoring-and-migration` (PR #132). Оба меняют схему данных, поэтому решались
до написания требований, а не по ходу
**Как получено:** вопросы заданы владельцу в диалоге при работе над change, 23.08.2026
**Решения принял:** владелец (pgorbachev)
**Статус:** ненормативный, как [решения после демо](demo-2026-08-19-decisions.md) и
[выбор облика по мокапам](demo-2026-08-23-mockup-choice.md). Требования пишет автор change;
при расхождении побеждает спека

Отдельный файл, а не строка в файле решений от 19.08: тот объявлен входом, который «дальше
не обновляется», и дописывание в него задним числом сделало бы его историю непроверяемой.
Тот же довод, по которому отдельным файлом записан выбор облика.

Файл существует потому, что без него оба решения не имели в репозитории **никакого**
источника: они прозвучали в диалоге, а спека на них опиралась словами «решение владельца от
23.08.2026». Ревью это нашло — нормативная правка держалась на непроверяемой ссылке.

## Решения

| № | Вопрос | Решение |
|---|---|---|
| W2 | Под плоской схемой адрес персоны — `/specialisty/<код>`, из института он больше не выводится. Прежнее требование «преподаватель без института не публикуется» держалось именно на адресе. Оставляем связь обязательной для публикации? | **Необязательна.** Персона без института публикуется: адрес у неё есть, в каталоге специалистов она видна. Связь остаётся источником состава преподавателей на странице института |
| W3 | «Категории берутся из программ» (Q10/Q17) — это связь с программами или отдельный справочник? | **Категория есть программа с признаком**, что она является категорией статей; значение признака по умолчанию — «да». Отдельного справочника категорий не заводим |

Серия `W`, а не `Q`: буквой `Q` помечены вопросы разбора списка с демонстрации, а эти два
возникли позже и не из списка заказчика. Нумерация продолжает `W1` (иконки соцсетей) из файла
решений от 19.08.

## Что из этого следует, но решением не является

Названо здесь, чтобы не выглядело решением владельца: механизм отказа при снятии признака у
программы, оставшейся единственной категорией опубликованной статьи, и порядок «разметка
категорий раньше включения обязательности» — выводы автора change из решения W3, а не слова
владельца. Они живут в требованиях, и спорить с ними надо там.
