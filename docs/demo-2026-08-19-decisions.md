# Решения по доделкам после демо. Ненормативный вход для OpenSpec

**Предмет:** список D1–D28 из [`demo-2026-08-19-intake.md`](demo-2026-08-19-intake.md)
**Как получено:** разбор скиллом `grilling`, пять раундов, 26 вопросов, 2026-08-20
**Решения принял:** владелец (pgorbachev) в диалоге
**Статус:** ненормативный. Требования живут в `openspec/changes/`, принятое поведение —
в `openspec/specs/`. При расхождении **побеждает спека**.

Файл существует, чтобы решение не растворилось в переписке: через месяц нужно уметь
ответить, почему адрес семинара выглядит так, а не иначе, и кто это выбрал. Дальше эти
решения переезжают в changes и здесь не обновляются.

## Решения

| № | Предмет | Решение |
|---|---|---|
| Q7/Q13 | Отзывы (D8) | Официальный виджет отзывов Яндекс.Карт, динамический. Фильтр «только 4–5 и развёрнутые» **не реализуется**: виджет этого не умеет, а при рейтинге 4.9 и 33 отзывах отбирать нечего |
| Q19 | Фото из отзывов (D8) | Чужие фото к себе **не копируем** — остаются в виджете. Банк фото пополняется своими съёмками заказчика |
| Q24 | Место виджета | Только главная, отдельной секцией. Отдельная страница «Отзывы» — когда отзывов станет заметно больше 33 |
| Q8/Q14/Q20 | Адреса (D7) | Плоская симметричная схема: `/instituty/<код>`, `/programmy/<код>`, `/seminary/<код>`. У сущности один канонический адрес; программы и институты — каталоги, а не уровни пути. Семинар связан с несколькими программами без последствий для адреса. Старые адреса — вечные редиректы |
| Q9/Q15/Q21 | Преподаватели (D4) | Тип `Person` с признаком **одного значения**: `teacher` \| `method_author`. Первичное деление делает ИИ один раз, дальше редактирует админ. Критерий на сегодня — русский/иностранец: 11 иностранцев в `method_author`, остальные 18 (включая Шрайнера) в `teacher`. В «Сведения об образовательной организации» попадают только `teacher` |
| Q10/Q17 | Каталог статей (D22–D25) | Подпись даты с карточки убрать; порядок по дате оставить; сортировку по алфавиту убрать. Добавить группировку по категориям: категории берутся из программ, у статьи их может быть несколько, **редактируются админом**, первичная разметка — ИИ один раз. Категории — фильтр **без собственных адресов** |
| Q11/Q16 | Даты семинаров (D3) | На странице программы — ближайшая дата по каждому семинару; на странице семинара — все запланированные. Если запланированных нет — «уточняйте у менеджера» с телефоном |
| Q23 | Свежесть данных | Пересборка при добавлении семинара **плюс** ночная пересборка по расписанию. Клиентское довычисление не делаем |
| Q12 | Допуск (D9) | Утверждение «программы адаптированы и для врачей, и без медобразования» идёт в блок «Преимущества». Письменных подтверждений по программам **не запрашиваем** — заявлено заказчиком на встрече 2026-08-19 |
| Q18 | Формы записи (D28) | Остаются внешними ссылками на CRM-формы Bitrix24, открываются новым окном. Персональные данные на наш домен не переносятся. **Кода писать не нужно — уже работает** |
| Q22 | Чат (D19) | Виджет Bitrix24 ставим внизу; вне часов работы менеджера показывает часы и телефон; на демо-стенде гасится наравне с аналитикой |
| Q25 | Разделы главной (D21) | Секция «Новости» переименовывается в «Предложения». Секция «Акции и скидки» (включая «Приведи друга») остаётся **отдельной** — не сливаем |
| Q26 | Расписание вверх (D3) | Точечная правка, мокапы не нужны: переносится существующий блок, типографика, палитра и сетка не меняются |
| — | Соцсети (D16) | Instagram и Facebook убрать, остальные четыре оставить |

## Решения, отменяющие прежние

Оба прежних решения записаны в репозитории, и оба принимались по другому основанию —
паритету с живым сайтом. Требование владельца контента его перебивает, поэтому это не
конфликт, а смена нормы. Но менять придётся и обоснования, иначе они начнут врать.

| Отменяется | Где записано | Чем было обосновано |
|---|---|---|
| Возврат Instagram и Facebook (2026-07-27) | `web/src/lib/social.ts:31-37`, гейт `web/tests/content-quality.test.ts:486-513` | «При переносе из футера пропали — потеря функционала относительно оригинала» |
| Сохранение четырёх порядков сортировки (2026-08-11) | `openspec/specs/article-catalog/spec.md:112-120` | «Порядок по заголовку — наше добавление; четыре порядка остаются, к паритету с двумя не приводим» |

Гейт соцсетей при правке делается **симметричным**: сегодня он утверждает только «ни одна
не исчезла», после правки обязан утверждать и «эти две не вернулись». Иначе ссылки тихо
приедут обратно при следующей сверке с живым сайтом — ровно тем путём, каким пришли.

## Принято вопреки рекомендации

Записано не ради спора, а чтобы через месяц была видна цена, если она проявится.

| Решение | Рекомендация была | Названная цена |
|---|---|---|
| Симметричные адреса `/instituty/<код>` | оставить институты в корне | адреса трёх институтов уже проиндексированы и меняются вместе со всеми |
| Признак `Person` одного значения | набор ролей | человек, оказавшийся и преподавателем, и автором методики, потребует миграции поля |
| Акции и предложения раздельно | слить в одну секцию | на главной остаются две соседние секции по четыре карточки |
| Только пересборка, без клиентского довычисления | плюс довычисление в браузере | внутри суток «ближайший» может оставаться прошедшим до ночной пересборки |

## Дефект, найденный при разборе и не входящий в список заказчика

На главной блок «Ближайший семинар» показывает **14–16 авг** — запись «Антистрессовая
кинезиология. Введение. Уровень 1», `2026-08-14 → 2026-08-16`, закончившуюся до демо.
Ближайшая настоящая — 10 сентября. Логика верна (`web/src/lib/home.ts:137-146` отсекает
прошедшее по `now`), данные свежие — протухла **сборка**.

Отсюда следствие для проверки: **гейт на сборке этот класс не ловит по построению** —
сборка фильтрует по своему `now` и всегда права в момент, когда её проверяют. Ловить надо
свежесть развёрнутого сайта, а не вывод сборки. Это единственный пункт, по которому
решения ещё нет.
