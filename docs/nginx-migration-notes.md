## Политика кеш-заголовков и сжатие — РЕАЛИЗОВАНО (change `serving-cache-headers`)

Таблица ниже больше не намерение: она перенесена в heredoc `NGINX`
`scripts/bootstrap-vps.sh` и утверждена требованиями. Источник требований — не эта
заметка, а `openspec/specs/static-serving/spec.md` (после архива change; до архива —
`openspec/changes/serving-cache-headers/specs/static-serving/spec.md`). Читайте эту
заметку как исторический контекст решения, а не как текущий контракт.

Состав классов пересчитан по фактической сборке и в трёх местах разошёлся с тем, что
здесь предполагалось изначально:

- **поиск** (`/pagefind/`) в этой заметке не упомянут вовсе — каталога не было, когда
  она писалась. По факту в нём два класса с противоположными требованиями: хешированные
  файлы данных (`.pf_fragment`, `.pf_index`, `.pf_meta`) получили тот же годовой
  `immutable`, что и `/_astro/`; загрузчик и манифест `pagefind-entry.json` с постоянными
  именами — политику страниц, потому что манифест указывает на файлы данных по хешу, и
  закреплённый в кеше старый манифест отправил бы клиента за файлами, которых после
  следующей выкладки уже нет;
- **шрифты** (`/fonts/*`) получили отдельный класс `public, max-age=2592000` (30 суток),
  которого в этой заметке нет вовсе. Причина — они лежат на критическом пути отрисовки
  (`<link rel="preload">`), а без явного класса на них действовала бы политика страниц
  (`max-age=0`) — то есть change сделал бы кеш шрифтов хуже, чем он был при отсутствии
  какой-либо политики (браузер кеширует их эвристически по `Last-Modified`);
- **`*.html` из этой заметки не описывает ни одного реального адреса**: сайт адресует
  страницы без расширения и без завершающего слэша (`/kontakty`, не `/kontakty.html`).
  Класс страниц в реализации задан на уровне `server` как умолчание, а не правилом по
  расширению;
- **`/sitemap.xml` в класс карт сайта не входит** — этого файла нет в сборке, адрес
  существует только как перенаправление на `/sitemap-index.xml`
  (`deploy/nginx-redirects.conf`), и правило кеша обязано ему не мешать (точное
  совпадение адреса в nginx выигрывает у любой другой формы правила).

Итоговые классы (полностью — в спеке):

| Класс адресов | `Cache-Control` |
|---|---|
| `/_astro/*` (хеш в имени) | `public, max-age=31536000, immutable` |
| данные поиска `.pf_fragment`/`.pf_index`/`.pf_meta` (хеш в имени) | `public, max-age=31536000, immutable` |
| `/fonts/*` | `public, max-age=2592000` |
| `/favicon.*` | `public, max-age=86400` |
| `/sitemap*.xml`, кроме адресов с правилом перенаправления | `public, max-age=3600` |
| страницы и всё остальное (умолчание `server`) | `public, max-age=0, must-revalidate` |

Сжатие: `gzip on` плюс явный `gzip_types` (CSS, оба написания XML — `text/xml` и
`application/xml`, оба написания JavaScript — `application/javascript` и
`text/javascript`, SVG, JSON, обычный текст). `text/html` в перечне нет намеренно —
nginx сжимает его всегда, повторение дало бы предупреждение `duplicate MIME type`.
Оба написания для XML и JavaScript — не избыточность: таблицу «расширение → тип» задаёт
`mime.types` nginx, а не этот конфиг, и наш хост отдаёт `.xml` как `text/xml`, `.js` как
`application/javascript` — каноническое написание для обоих оказалось не тем, что отдаёт
хост.

**Security-заголовки и CSP из раздела ниже по-прежнему только намерение** — они
намеренно вне scope `serving-cache-headers` (идут отдельным change вместе с HTTPS, по
находке B4 `docs/security-audit-2026-08-08.md`) и остаются описанными только здесь.

## CSP (Этап 1 report-only → Этап 5 enforce): frame-src

Видео-фасад встраивает RUTUBE-плеер по клику. В `Content-Security-Policy`
`frame-src` должен включать `https://rutube.ru` (иначе плеер не загрузится
под enforce). Основной видео-канал (ссылки, не iframe) — VK Видео
`vkvideo.ru/@clubikpk`.

## Деплой превью-сборки (временный, до полноценного staging Этапа 1)

Атомарный деплой статики: `scripts/deploy-web.sh <host>`
(builds → tar в `releases/<ts>` → swap symlink `current` → `nginx -t` + reload,
хранит 5 релизов). Ключ — через `SSH_KEY` (тело ключа только локально в
`~/.ssh`, в репозиторий не коммитится).

Гейт-нюансы:
- Если порты 80/443 на сервере уже заняты другим сервисом/реверс-прокси,
  vhost сайта поднимается на отдельном порту (напр. 8080) — деплой файлов
  этим не затрагивается, меняется только `listen` в nginx-конфиге сайта.
  Это **временное превью**, без HTTPS/редиректов/заголовков.
- Полноценный `staging.ikpk.su` (выделенный VPS + HTTPS + gzip/brotli +
  security/cache headers + 301-map из url_map.csv) — задача Этапа 1.
