# Мокапы: ближайшая дата семинара на странице программы (D3, данные)

**Предмет выбора — только раскладка даты в карточке семинара.** Само поведение уже
решено и здесь не обсуждается: по решению Q11
([`docs/demo-2026-08-19-decisions.md`](../../../demo-2026-08-19-decisions.md)) страница
программы показывает **ближайшую** дату по каждому семинару, полный список запланированного
остаётся на странице семинара, а при отсутствии запланированного показывается
«уточняйте у менеджера» с телефоном. Телефон — мобильный из D12,
`web/src/lib/navigation.ts:51`, `MOBILE_PHONE`.

Мокапы обязательны по правилу «Изменения облика: мокапы до внедрения»
([`AGENTS.md`](../../../../AGENTS.md)): добавление видимого элемента в карточку — это
раскладка, а не точечное исправление дефекта.

## Как это снято

- **база:** `origin/main@1ea953b7933cc19cd3ad1f8ba70260c5bf10b2b3` (кратко `1ea953b7`)
- **сборка настоящая, не рисунок:** `npx astro build` четырьмя проходами
  (`dist-ref` — нынешний `main`, `dist-a`/`dist-b`/`dist-c` — варианты, переключатель
  `DATE_VARIANT`), затем Playwright по собранному выводу через свой статический сервер
  на нулевом порту
- **страница:** `/institut-barralya/visceralnye-tehniki` — взята потому, что она смешанная:
  **7 семинаров, у 4 есть будущая дата, у 3 нет**. Вариант, где виден только один из двух
  исходов, выбирать не из чего
- **вьюпорты:** 1280×800 и 375×812, `deviceScaleFactor=1`, `reducedMotion=reduce`, анимации
  сняты стилем
- **снят сам блок семинаров** (`[data-testid="course-group-seminars"]`), а не вся страница:
  предмет выбора — карточка, и полностраничный снимок на 5000 px его прячет
- **скрипт съёмки:** [`shot-program-dates.mjs`](shot-program-dates.mjs) (копия временного
  файла из `web/`, в merge он не уезжает)

**Даты на снимках — не сегодняшние, и это не дефект.** Сборка идёт с фикстурного снимка
контента, у него `referenceDate` = `2026-03-31` (`fixtures/content-snapshot/snapshot.json`),
поэтому «ближайшим» оказывается ближайшее после этой даты. На боевой сборке опорной датой
будет дата живого снимка. Проверять по снимкам надо раскладку, а не конкретные числа.

## Машинный протокол

Счётчики печатает сам скрипт съёмки; они же — негативная проверка самого мокапа:

```
ref desktop: карточек 7, с датой 0, фолбэк 0
ref mobile:  карточек 7, с датой 0, фолбэк 0
a/b/c, оба вьюпорта: карточек 7, с датой 4, фолбэк 3
```

Опорная сборка даёт **ноль** обоих признаков — значит признаки приходят из правки, а не
жили на странице раньше.

## Находки съёмки

1. **Вариант C в первой съёмке накладывал кнопку на дату.** `.course-group-seminar-actions`
   — это `flex` в строку, поэтому блок даты и кнопка делили одну строку и наезжали друг на
   друга; телефон уходил под кнопку. Исправлено вертикальной колонкой для этого варианта,
   снимки пересняты. Первую съёмку не оставляю «как честную»: выбирать надо между
   раскладками, а не между раскладкой и её дефектом.
2. **Вариант A в первой съёмке слипался:** «Даты пока не назначены —уточняйте». Пробел
   после тире съедался при сборке выражения; исправлено неразрывным пробелом.
3. **Ширина лида в C уменьшается на десктопе** — правая колонка становится шире из-за
   подписи «Ближайший семинар». В A и B ширина текста не меняется.
4. **На мобильном A и B читаются одинаково хорошо, C прижимает дату вправо** над кнопкой во
   всю ширину — выглядит нарочито, но не ломается.

## Выбор

**2026-09-22 владелец выбрал вариант B** — чип с датой в верхней строке карточки. Довод:
дата видна до чтения названия и одинаково работает на обеих ширинах, а колонка кнопки и
ширина текста не меняются.

Внедряется только B: варианты A и C жили в коде временным переключателем `DATE_VARIANT`
ради съёмки и в реализацию не уехали. Тёмная тема получила свою пару цветов чипа — цвета
заданы литералами, поэтому сами бы не подстроились.
