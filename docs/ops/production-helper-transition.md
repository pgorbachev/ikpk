## Что делает изменение

`scripts/lib/rehearsal_config.py` по-прежнему отказывается от любой посторонней разницы с шаблоном. Единственное новое разрешение: у профилей `initial-prod`, `production-static` и `production-paired` уже записанный `paymentStatusProbeUrl` сохраняется байт-в-байт. Миграция может только дописать отсутствующие поля, которые и раньше дописывала (`siteRefreshState`, `sitePublicationMarker`, `publicationLock`, `temporaryRoot`). Если отличий больше, чем сохранённый probe и эти добавления, установка останавливается до записи helper-файлов.

Отсутствующий probe из шаблона не подставляется. Для `staging194` отличие probe по-прежнему отказ. Если отличий нет, файл не переписывается.

Это не создаёт `/var/www/ikpk/.publication.lock`, не меняет unit-файлы и не обходит flock. Переменная `IKPK_PUBLICATION_LOCK_HELD` не используется.

## Когда процедуру можно исполнять на хосте

Только из immutable CI-артефакта `host-helper.tar.gz` того SHA, который уже влит в `main` и прошёл `Tests`. Локальный worktree на хост не ставится. Вызов установщика — существующий `scripts/install-rehearsal-host.sh` без `--prefix` и без `--install-disabled`. Если есть `/etc/systemd/system/ikpk-site-housekeeping.path`, установка без профиля останавливается; обходить это нельзя.

Перед любым production-профилем установщик уже требует существующий lock: обычный файл, не symlink, mode `0600`, владелец — пользователь CMS из конфига. Если файла нет, установка останавливается до замены helper. Создавать этот inode этой процедурой нельзя: это отдельное изменение production, и сейчас оно не разрешено.

Окно на хосте, когда установка всё же понадобится: один оператор, автоматические источники остановлены и додренированы, существующие publication lock и operation lock удерживаются на всё время установки и проверки. Production-launcher этой правкой не меняется.

## Откат

Миграция конфига пишет `*.pre-update-*.bak` только если файл реально меняется. Откат конфига — вернуть этот байтовый снимок. Откат четырёх helper-файлов (`rehearsal_state.py`, `housekeeping_journal.py`, `rehearsal_host.py`, `/usr/local/sbin/ikpk-rehearsal`) — повторная установка предыдущего проверенного CI-артефакта, не ручная правка. Снятие семи файлов не восстанавливает inode lock; эта процедура его не создаёт и не меняет.

## Хаускипинг CMS

`cleanup-site` удаляет только завершённые каталоги внутри `releaseRoot`. Он оставляет текущий релиз, каталог из `oldPair` последней committed-операции, каждый релиз, названный в `EnvironmentFile` службы CMS, и каталог живого процесса. Если операция не завершена, цель отката уже исчезла, unit или env-файл не читается, запись в корне не каталог — уборка CMS ничего не удаляет или останавливается. База и `backupRoot` не входят в этот корень.

Чтобы таймер мог удалять эти каталоги, unit получает `releaseRoot` в `ReadWritePaths`. Это появляется только после установки helper из CI-артефакта, не из локального дерева.
