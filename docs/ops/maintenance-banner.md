# Баннер технических работ

Баннер управляется при сборке сайта переменной `MAINTENANCE_BANNER`.
Без неё, с пустым значением или `off` баннер выключен. `on` включает прежнее уведомление в обоих шаблонах, включая 404. Пробелы по краям значения игнорируются; другие значения останавливают сборку с ошибкой.

Из каталога `web`, с обычными настройками нужного окружения:

```sh
MAINTENANCE_BANNER=on npm run build
MAINTENANCE_BANNER=off npm run build
```

Это команды создания статики. Чтобы посетители увидели изменение, нужно проверить и опубликовать полученную сборку через согласованный процесс выпуска. Изменение переменной на уже работающем сервере и перезапуск nginx готовый HTML не меняют. В demo-выводе и при demo-формах баннер технических работ подавляется; существующее уведомление стенда сохраняется.

Для штатной серверной публикации установите `"maintenanceBanner": "on"` (или `"off"`) в root-owned конфигурации выбранного профиля до начала операции. Например, production-static использует `/etc/ikpk/rehearsal-production-static.json`. Если поле отсутствует, сервер явно передаёт сборщику `MAINTENANCE_BANNER=off`; другие значения поля отвергаются до запуска дочерних команд. Настройка входит в существующий хеш конфигурации операции: менять её посреди выпуска нельзя.

После установки версии host-helper с этой поддержкой запустите обычный новый выпуск по действующему процессу и проверьте баннер в кандидате и опубликованном HTML. Переменная в локальной оболочке команды публикации не заменяет поле серверной конфигурации. CMS, данные и параметры demo этим флагом не меняются.

Для восстановления использовать предыдущую проверенную статику по штатному процессу отката либо собрать и опубликовать вариант `off`. Эта поставка сама ничего не публикует.
